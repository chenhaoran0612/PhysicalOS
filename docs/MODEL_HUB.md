## 分类和指标

一个模型属于一个分类。**分类绑定指标**：这一类模型的评测只报这几项指标；其中一项是主指标，一轮改进按它判断变好还是变差。有达标线的指标全部达标，这次评测才算达标。评测集可以给指标定自己的达标线，覆盖分类的。

| 分类 | 主指标（达标线） | 其他指标 |
|---|---|---|
| 动作类强化模型 | 成功率（≥ 100%） | 平均用时、平均控制步数、平均回报 |
| 导航模型 | 到达成功率（≥ 95%） | 路径效率、碰撞率（≤ 0%）、到点误差（≤ 0.2 米） |
| 意图识别模型 | 准确率（≥ 95%） | 宏平均 F1、误触发率（≤ 1%）、响应时延 |
| 大语言模型（LLM） | 任务通过率（≥ 90%） | 工具调用正确率、首字时延、生成速度 |
| 视觉语言模型（VLM） | 问答准确率（≥ 85%） | 目标定位 IoU、幻觉率（≤ 5%）、响应时延 |
| 视觉-语言-动作模型（VLA） | 任务成功率（≥ 80%） | 子目标完成率、人工接管率（≤ 5%）、控制频率 |
| 感知模型 | mAP@0.5（≥ 80%） | 召回率、帧率、单帧时延 |
| 语音模型 | 字错率（≤ 5%） | 唤醒率（≥ 95%）、误唤醒、响应时延 |
| 其他模型 | 综合得分 | — |

定义在 `brainos/model_hub_catalog.py`（数据和纯函数）。达标线是起步值，没有哪一条来自验收标准；要改就改那张表。

## 规则

1. **小黄鸭的技能模型一直在库里。** 给它传一个自己训练的版本（不在某一轮里），这个版本就成为它的当前版本，状态按这个版本的评测算（没有评测时是「待评测」）。 它们来自 `duck_kit.SHOWS`，不是存下来的记录：那张清单换了包，模型库跟着变。随应用带来的包是它的一个版本；训练项目的两组验收成绩（固定组、独立组）是它的两条导入的评测。issue #79 起，以前随应用带来的包也是它的版本（不能运行），每个版本有自己的独立起姿组，这一版的验收评测带着每个起姿的结果，见 [DUCK_TRAINING_DATA.md](DUCK_TRAINING_DATA.md)。
2. **模型文件留在这台电脑上。** 上传是分片的（每片 8 MB，一个文件最多 4 GB，同时最多 8 个上传，一小时没有新内容的上传作废，磁盘空间不够时不开始），按内容的 SHA-256 存在工作区的 `model-hub/files/` 下，同样的内容只存一份。路径从不由用户输入拼出来：上传用随机编号，文件用记录编号。传上来一天内没有成为版本或数据集的文件，下次打开工作区时清掉。
3. **只有登记过的小黄鸭模型包在这台电脑上运行。** 模型包里有代码（见 [DUCK_SKILLS.md](DUCK_SKILLS.md) 规则 3）。所以「在仿真里评测」只对随应用带来的包开放；上传的模型文件只保存和核对，它的成绩从训练项目的评估记录里取（按这一版的训练轮次和更新次数找），或者手动导入。
4. **评测是一个版本在一个评测集上的指标。** 动作模型的评测集是一组起姿编号：同一个编号每次从同一个姿态开始。真跑时每个起姿运行一遍，由模型包自带的裁判判定；全部跑完才计算指标。被停止、被打断或小鸭进程不在了的评测不产生指标，已经跑过的回合留着。一个仿真小鸭同一时间只跑一次评测。
5. **仿真里的结果不是现场证据。** 页面上写明。
6. **一轮改进的步骤按顺序走**：基线评测 → 找短板 → 训练（应用外）→ 评测候选 → 决定。起点和候选在同一个评测集上评测才比较。候选传错了可以再传一个：新的那个成为候选，重新评测。起点和候选的评测在决定之前都可以重做，以最后一次为准。采纳后候选成为当前版本；不采纳，候选留在版本列表里。一个模型同一时间只有一轮；任何一步都可以放弃。
7. **模型训练完就是一个技能。** 小黄鸭的技能模型对应 issue #67 生成的技能（技能入口 `duck.<节目>`），自动显示。其他模型在它的页面上绑定到同一品牌型号的一个技能。
8. **用过的评测集和训练集不能删**：它们要留着才能说明那些结果。随应用带来的内容不能删。

## 记录

都在工作区的库里，没有 `project_id`（归账号，删除任务不会带走它们）：

| 种类 | 是什么 |
|---|---|
| `hub_models` | 自己添加的模型：名称、分类、品牌型号、说明 |
| `hub_versions` | 版本：标签、文件、训练出处（轮次、更新次数）、属于哪一轮 |
| `hub_files` | 文件：文件名、大小、SHA-256 |
| `hub_sets` | 评测集和训练集：分类、起姿或条数、达标线、文件 |
| `hub_evaluations` | 评测：版本、评测集、指标、方式（运行 / 导入）、每个起姿的结果 |
| `hub_rounds` | 改进轮次：起点版本、评测集、目标、短板、做法、候选、结论 |
| `hub_skill_links` | 模型绑定的技能 |

## 页面

- 三页的页头都是英文一行、中文一行和按钮，没有句子（[PAGE_TITLES.md](PAGE_TITLES.md)）。
- 模型库：看板点一个分类只看这一类。任务从平台目录选用或自己接入的模型（原来这页的内容）按用途归到分类里，卡片上标「任务选用」，原来的按钮照旧。「从平台选择更多模型」「工程助手使用的大模型」折叠在页面下方。
- 训练与改进：看板写明一轮的五步；每个模型一张卡片，显示这一轮走到哪一步、主指标从多少到多少。下面是小黄鸭的仿真舞台（issue #63 的那一块，原样）和原来的训练任务表。
- 训练与测试数据：评测库、训练库两面墙。任务登记的数据版本（原来这页的内容）在训练库里，标「任务登记」。
- 评测运行时，页面每秒问一次这次评测，只改动显示它的那几处（每个起姿一个方块、表格里的计数），不重画整页。

## 代码在哪里

| 文件 | 做什么 |
|---|---|
| `brainos/model_hub_catalog.py` | 分类、指标、达标判断、前后比较 |
| `brainos/model_hub.py` | 模型、版本、评测集、评测、轮次、技能绑定；给页面的总览 |
| `brainos/model_hub_files.py` | 分片上传、按内容保存、下载、清理 |
| `brainos/model_hub_eval.py` | 在仿真小鸭上逐个起姿运行的线程 |
| `web/model_hub.js` | 三页和两个子页的内容（纯函数） |
| `web/model_hub_pages.js` | 读取、对话框、上传、跟随正在运行的评测 |
| `web/model_hub.css` | 样式 |

接口都在 `model-hub/` 下（`brainos/server.py` 的路由表）；文件内容走 `PUT /api/model-hub/chunk` 和 `GET /api/model-hub/file`。
