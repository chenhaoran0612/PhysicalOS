# 机器人属于账号，不属于某个任务（issue #42 第二部分）

用户在 issue #42 里补充的要求：「我的机器人」的数据和当前任务没有关系，两者是独立的；不同的任务可以关联到同一台机器人进行开发。本文说明原来是怎样的、现在的规则、旧数据怎么处理，以及验证到了哪一步。

## 原来的问题

每台机器人都记在添加它时打开的那个任务名下：

- 切换到另一个任务，「我的机器人」里就看不到它了；
- 另一个任务不能用它（后端回答“所选资产不属于当前项目”）；
- 删除一个任务之前，必须先把这个任务里的机器人都删掉。

## 现在的规则

| | 原来 | 现在 |
|---|---|---|
| 「我的机器人」列出谁 | 当前任务的机器人 | 这个账号的全部机器人，打开哪个任务都一样 |
| 一个任务能用哪些机器人 | 只有自己名下的 | 账号里的每一台；几个任务可以同时用同一台 |
| 机器人的连接、调查、修复、硬件扫描、设备档案等 | 跟着任务 | 跟着机器人，在每个任务里都能看到 |
| 任务用机器人做出来的东西（应用、测试报告、发布、运行记录） | 跟着任务 | 不变，仍然跟着任务 |
| 删除任务 | 先删机器人 | 机器人留下；只删任务自己的东西 |
| 没有打开任何任务时添加机器人 | 不行 | 后端可以（页面见“已知限制”） |

任务和机器人之间没有单独的“关联”操作：任务在创建应用、让助手做工程工作、启动流程时选哪台机器人，就是在用哪台。

## 怎么实现的

`brainos/robot_scope.py`：

- 工作区里有一条固定的记录（`project-robot-home`），它是全部机器人的“家”，不是任务：页面读到的任务列表里没有它，`state.robot_home` 给出它的标识。机器人和关于机器人的记录都写着这个标识。原来各个模块“记在机器人所在的项目下”的写法没有改，只是所有机器人现在在同一个地方。
- 关于机器人的请求（`robots/…`、`sims/…`、SSH 连接、硬件、设备档案、调查、技能包安装、驱动包下发、云端技能安装等），服务端在分发时一律按“家”处理，页面当前打开的是哪个任务不影响结果。
- `Platform.same_project`：机器人，以及记在“家”里的记录，每个任务都可以用；按“家”处理的请求可以引用任务里的东西（例如调查时选用当前任务里配置的工程模型）。两个任务之间仍然不能互相引用对方的记录。
- 页面：按任务筛选的列表（`rows`、`hwList`）同时包含“家”里的记录；任务自己的助手设置（工程模型、Skills、MCP）不共享。
- 任务工作台：每张任务卡片上的“机器人”是账号的机器人；看板上的机器人数按台数算，几个任务共用的一台只算一次；删除任务的确认框不再要求先删机器人。“我的机器人”页不再出现“先创建任务”的提示。
- 直接调用平台代码并传入任务号的地方（单元测试是这样写的）仍然把机器人记在那个任务下；应用自己不再这样做，下次打开工作区时它们也会被移到“家”。

## 旧数据

打开工作区时迁移一次（`robot_scope.migrate`），之后不再做：

- 每台机器人移到“家”；
- 写着这台机器人、并且原来记在它那个任务下的记录一起移过去：SSH 连接和主机指纹记录、调查与修复会话、本体档案、调查证据、硬件扫描和修复报告、现场处理标记、设备档案、驱动包下发记录等；
- 任务做出来的东西留在任务里：应用、测试报告、发布、运行记录、训练和仿真任务、模型、技能、数据、场景、服务、协作流程。

迁移原地改写记录并一次提交：列表的顺序不变；中途被打断等于没有做，下次打开再做。迁移不联系任何设备。

回到旧版本的应用时，“家”会显示成一个名为「我的机器人」的任务，机器人都在里面，数据不丢。

## 在哪里验证过，哪里没有

验证过的（没有真机）：

- `tests/test_robot_scope.py`（25 项）：旧工作区迁移后机器人和它们的记录都在“家”里、任务做的东西留在任务里、列表顺序不变、只做一次；有过机器人的任务可以删除而机器人留下；“家”不出现在任务列表里，也删不掉，任务的东西不能建在“家”里；经 HTTP：在任务 A 里添加的机器人在任务 B 里照常使用，没有任务时也能添加，删掉任务 A 后机器人还在，仿真机器人同样属于账号。
- `tests/robot_scope_logic.cjs`（29 项）：每个任务都列出账号的机器人和关于它们的记录，任务自己的应用和助手设置不共享；任务工作台把共用的机器人只算一次，不拦删除；任务的技能从账号的机器人上读。
- `tests/robot_scope_browser.cjs`（Chromium 和 WebKit）：打开任务 A 时按地址添加一台“真机”（真实的管理层加替身本体）；切到任务 B，它在“我的机器人”里，两个任务的卡片上都有它，看板只算一台；在任务 B 里读它的技能、安装并运行一个技能；删除任务 A 不要求先删机器人，删完机器人还在；再从任务 B 删除机器人。
- 原有测试里跟着改的：`tests/cloud_skills_logic.cjs`、`tests/robot_remove_logic.cjs` 里断言“只算当前任务”的三处；`tests/test_task_workbench.py` 数任务时不算“家”；`tests/test_model_compute.py` 里默认模型的配置多了“家”的一条；`tests/test_ssh_multi_hop.py` 里迁移后连接记录的归属；`tests/test_product.py` 里另一个账号拿别人的任务号添加机器人，原来被拒绝，现在机器人建在它自己的账号里（别人的账号里什么都没有多）；浏览器脚本 `task_workbench_browser`（“有机器人的任务不能删”两步）、`body_types_browser`（设备旁边不再写任务名）、`ux05_fix2_browser`（安全横幅不再写“项目：…”，查看机器人不切换任务）。
- 桌面端完整测试 1831 项：最后一次运行有 3 项失败（`test_engineering` 1 项、`test_extensions` 2 项，都是助手会话等待超时；当时机器的负载在 100 以上），这两个文件随后单独运行 16 项全部通过；前一次完整运行里它们是通过的。跳过 9 项。
- 浏览器验收（Chromium）：运行器认识的 50 个脚本全部通过，没有重试；WebKit 上跑了改动涉及的 8 个脚本和新脚本，全部通过。`account_browser` 运行器里没有它的配置，没有跑。`tokenfans_browser` 在前两轮里“第一次读取状态早于页面加载完成”这一处检查失败过 5 次（当时机器负载很高），之后三次运行都通过，最后一轮完整运行里一次通过；没有改动的 `integration` 上只跑过一次，通过。没有找到它和这次改动的关系，也没有排除。
- 迁移在本机真实的 4 个工作区上演练过：只读打开，复制到内存里执行，不写回，只看条数。机器人、连接、调查会话、证据、硬件扫描和修复、设备档案、心跳记录都移到了“家”，再执行一次没有改动，列表顺序不变。
- 合并到当时最新的 `integration`（0.21.10）没有冲突；在合并后的代码上重跑了相关的单元测试 127 项、6 个页面逻辑脚本和 4 个浏览器脚本，通过。

没有验证的：

- 真机上的任何一步；桌面应用窗口（WKWebView）里没有点过。
- 真实数据只做了上面的演练，没有用新版本的应用打开过真实的数据目录。

## 已知限制

- 账号里一个任务都没有时，页面上的大多数按钮仍然先让人创建任务（调查机器人要用任务里配置的工程模型）；仿真机器人的第一次试用仍然会自动建一个试用任务。
- 每个任务的“工程助手”会话列表里能看到所有机器人的调查和修复会话，不只是这个任务用到的机器人。
- 直接对机器人做的操作（运行技能、安装技能包、停止、解除急停）的记录记在“家”里，在每个任务的运行记录里都能看到；机器人删除后这些记录还在。
- 调查或修复会话当时选用的工程模型、Skills 或 MCP 属于某个任务；这个任务被删除后，那次会话不能“继续”，页面会说明原因，需要重新开始一次。
- 任务和机器人之间没有单独的“关联”清单：任务卡片上列出的是账号的全部机器人，不是这个任务实际用到的那几台。
- 迁移出错时不会挡住工作区打开：什么都不移动，日志里记一条 `robot_scope.migration_failed`，下次打开再试。
