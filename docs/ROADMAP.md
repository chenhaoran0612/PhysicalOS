# 路线图

> 每轮进化结束、每个 issue 合并时更新。✅ 完成（注明验证级别）· 🟡 进行中 · ⬜ 未开始
> 验证级别：单元测试级 / 仿真级 / 替身级（协议替身，不是真设备、真服务）/ 真机级 / 真服务级。

## 阶段 1：跨本体骨架（第 01–03 轮）

- ✅ 云平台：账户/组织/API Key、邮箱验证、钱包账本、模型市场、推理网关、支付接口（第 01 轮，替身级；真实支付/上游未接）
- ✅ SDK + `nx` 命令行 + 技能模板（第 01 轮，5 分钟上手实跑通过）
- ✅ 桌面端：仿真证据隔离、解除急停（第 01 轮修复）
- ✅ 桌面端接入：能力表、技能包安装、云端登录与钱包（第 02 轮）
- ✅ 异步现场测试、网关会话流式、技能进程沙箱（第 02 轮；沙箱经实证攻击，第三方技能前仍需 uid/文件系统/网络隔离）
- ✅ Python 3.10 / 非 root 运行（Jetson 基线）、端侧模型安装、遥测持久化、工程助手云网关计费（第 03 轮）

## 阶段 2：第一台真机（第 04 轮起）
- ✅ 能力一致性测试套件（static / dry / motion）+ AI 本体适配助手 v2：SSH 调查 → 适配器初稿 → 能力对照测试（第 04 轮，仿真与 ROS 2 替身级；真机未验证）
- ✅ 桌面开箱即用：一键仿真机器人、示例技能库、授权运行并实时观看（第 04 轮 ux01）
- ✅ 用户路径审计与修复（第 05 轮）；安全拒绝说真话、错误分类（第 06 轮）
- ✅ 锁存守护：慢蠕动、反馈失效、真实传感器噪声下不误报，且所有可比场景不比 0.13.0 弱（第 05–07 轮，仿真与对照场景级；阈值未经真机标定）
- 🟡 SSH 经一台跳板机接入（两跳指纹固定）+ 粘贴 ssh 命令自动填表（含嵌套写法 `ssh 用户@跳板机 'ssh 名称'`，目标名称按跳板机上的 SSH 配置解析）+ 真机只读实时状态（issue #3，已合并到 main，0.15.1；界面流程替身级；只读状态和嵌套写法的解析经公网跳板机在一台四足机器人上只读验证）；登录被拒时提示说明这次用的是密码、私钥还是“本机 SSH Agent”，用 Agent 时直接说没有用密码、请改为“密码”（issue #39，0.21.4；那台设备上的真正原因是表单停在“本机 SSH Agent”上，粘贴 ssh 命令会自动设成它，没有发送密码，用户改为“密码”后能连上）；认证方式选“密码”时，主机拒绝 `password` 方法后，在同一条连接上用同一个密码回答一次主机自己的密码提问（`keyboard-interactive`，终端里 `ssh` 先用的就是这种），给只认这种问法的主机用（issue #39，0.21.3；替身级，并在本机容器里的真 OpenSSH 8.9 上测过三种配置；不是那台设备被拒的原因）
- 🟡 连接后初始化硬件扫描，并修复扫描出的问题（驱动、权限、网络等；当时是逐条审批，issue #13 起默认允许执行），内置 Skill `hardware-init`（issue #2，已合并到 main；只读扫描在一台 Jetson Orin NX 真机上验证，修复会话为替身级）
- 🟡 桌面端账号管理：打开即登录 / 注册页，注册与找回密码要邮箱验证码，保持登录，账户面板与侧栏账户菜单（main 212da95，其他成员提交，第 08 轮与各 issue 的改动一起合并；单元测试与浏览器验收级；真实邮件服务见下面的 issue #37）
- 🟡 登录应用时同时登录云平台（issue #36）：登录、注册、重置密码时用同一邮箱和密码登录云平台，云平台没有这个账户就自动注册（开发环境的云平台当场验证邮箱）；“保持登录”传给云平台，云会话 30 天（云平台也要更新，否则 12 小时到期后资料页提示重新登录）；旧版本留下的应用登录在启动时退出一次；应用里改密码不会改云平台的密码。工作空间没填云平台地址时自动采用默认地址（127.0.0.1:8800）并把密码发过去：本机上抢占那个端口的其他程序理论上能收到密码（只限回环地址，http）。对进程内的真实云平台应用测过；已部署的桌面应用和本机 8800 的云平台上还没验证。
- 🟡 验证码邮件真的发出（issue #37）：发信账号配在本机状态目录的 `mail.json` 里（不在代码仓库和安装包里），邮件带纯文本和 HTML 两个版本，不加载外部资源、没有链接；写错的配置在发信时报出，不再悄悄退回本机的 outbox；`python -m brainos.mailer init|check|test` 生成模板、检查登录、发测试邮件。单元测试里 SMTP 是替身；用一个真实的企业邮箱账号登录并发过测试邮件，收件人确认收到、样式可以。安装版里还没有运行检查和测试发信的入口（要用源码目录的 Python）；只支持密码方式登录 SMTP，不支持 OAuth。
- 🟡 桌面应用里的文件上传按钮会弹出文件选择面板（issue #40，0.21.4）：设备资料、资料库、Skill 导入这几处的上传按钮以前在桌面窗口里点了没反应（macOS 的网页视图不会自己弹面板，要应用来弹），浏览器里一直正常，所以浏览器验收发现不了。面板按页面的要求允许多选或选文件夹；文件类型不在面板里过滤，不支持的类型仍由后端拒绝。源码检查和 Swift 类型检查级，另用同一份代码编的临时应用点过；打包后的应用里还要人点一次。
- 🟡 自带导航程序的四足机器人：去指定地点 / 巡检 / 无图自由走三个技能（issue #38，0.21.4）。能力标准 1.1 → 1.2（`base.navigate_to_place`、`base.explore`，`neuxmind_spec` 1.2.0；运行时版本仍是 0.4.0），运行时把机器人上自带的程序接成动作（`adapters/programs.py`：不经 shell、按退出码和输出判定、整条路线先核对速度上限、停止时先 SIGTERM 再 SIGKILL、没成功时发零速度），仿真四足有三个虚构地点。仿真、替身程序和真实 ROS 2 Humble 容器（Fast DDS）里跑过；没有在真机上运行过，那台狗用的 `rmw_zenoh_cpp` 没覆盖；0.21.12 起控制台可以设置真实本体并安装 / 应用配置（issue #38 后续：卡片「更多功能」里的「本体设置」，见 [ROBOT_BODY](ROBOT_BODY.md)；巡检示例的默认顺序改成会议室、二楼）；替身机器人、真实安装脚本加替身 ROS 2、两种浏览器里验证过，没有在真机上走过。旧管理层不认识这两项能力，要用这一版的安装包。
- 🟡 「我的机器人」页面重新设计（issue #41，0.21.5）：页面跟着状态走，没有机器人时是三种添加方式，有机器人后只有卡片和页头的「添加机器人」；卡片只留名称、在线状态、类型和地址、要处理的事和两个按钮（下一步、实时状态），其余收进「更多功能」（连接 / 设备 / 管理层 / 仿真 / 其他，删除在最后），「解除急停」一直留在卡片上；说明和设置收在页面底部的折叠行里。0.21.8 起机器人的对话框共用一个框架：标题是这个对话框做什么（「真机状态」改叫「实时状态」），机器人名在下面；从卡片打开实时状态、设备档案、硬件初始化、配置连接、管理层时可以在它们之间直接切换；标题和操作按钮固定可见（控制台所有对话框都是）。对话框里的内容没改，实时状态、设备档案、硬件初始化各自的设备概览和硬件列表都还在。逻辑测试和 Chromium、WebKit 浏览器验收级。0.21.12 起（第三部分，用户说「真机接入流程说明 / 这个页面怎么用 / 助手使用的模型 / 本体类型清单 这些不需要，上面的提示尽量少，且对齐」）：页面底部的折叠行去掉，两段说明不再显示（使用指南在页面右上角），「助手模型」「本体类型清单」收进页头的「设置」；每张卡片逐行对齐。卡片之后又精简了一次，见 issue #53 一条。
- 🟡 机器人属于账号，不属于某个任务（issue #42 第二部分，0.21.11）：用户在 issue 里说「我的机器人」和任务是独立的，不同任务可以用同一台机器人。机器人和关于它的记录（SSH 连接、调研和修复、硬件扫描、设备档案、交付等）放在一个固定的「家」（`project-robot-home`，不算任务，页面上看不到）；关于机器人的请求不管当前打开哪个任务都按「家」处理；任务自己做的东西（应用、测试报告、部署、操作记录）仍属于任务，删任务时一起删，机器人留下。旧数据在打开工作区时迁移一次（一个事务，失败就不动并记审计）；退回旧版本时「家」显示成一个叫「我的机器人」的任务，数据不丢。新的关于机器人的接口要加进 `brainos/robot_scope.py` 的 `ROUTES` / `PREFIXES`。见 [ROBOT_SCOPE](ROBOT_SCOPE.md)。「我的机器人」页面的清理（用户同时提的）由 #41 的会话做。0.21.12 起（第三部分，用户说「创建任务的时候选择机器人。用哪一个具身设备来做」）：新建任务时选机器人，任务记下 `robot_id`，几个任务可以选同一台；选了的任务，卡片和任务页的技能都只算这一台，任务页标题下可以更换（`projects/robot`）；没选的任务原来照旧用全部，合并 issue #50 后显示它品牌型号的机器人，选了的任务由所选机器人决定能绑定哪些应用（见 #50 一条）；所选机器人被删后任务页提示重选。一个任务只能选一台；创建应用、让助手调查等表单的下拉框还不会默认选中任务的那一台。
- 🟡 机器人状态只在有证据且阻塞时报故障（issue #47，0.21.12）：一台能走的狗卡片上挂着「运控驱动缺 2 项」「硬件 24 项 · 10 个问题」两个红标签，其实没有一条证明有东西不能用。现在硬件扫描（规则版本 2）只有直接读到不能用、并且写得出阻塞了什么（`blocks`）的才是故障，目前只有根分区用满 99%；没驱动的设备、CAN 关着、没有默认路由等是待确认；账号权限、没接的网口、开机日志是提示。运控接口没读到从不是故障（清单可信时待确认，一个节点都没读到时是提示）。卡片上只有故障是红色。旧的扫描记录在打开工作区时按新规则重新定级一次（只降不升）。内置 Skill `hardware-init` 1.4.0：运控程序已经在运行时不再装第二个驱动。提示不再默认勾给助手；#13 的现场保护按新字段 `onsite` 判断，不跟级别走。没有在真机上重新扫描。
- 🟡 应用和技能按品牌型号归属（issue #48，0.21.12）：机器人有品牌和型号（`product`），设备在能力清单里上报，没上报时添加机器人要填写（经 SSH 添加时必填），之后设备上报的以上报为准；机器人应用、登记的技能和云端技能版本都属于一个品牌型号，同品牌同型号的机器人都能检查、现场测试和发布同一个应用，其他品牌型号的拒绝（`app_other_model`、`skill_other_model`）；现场测试证据和发布仍按台算，交付清单里可以选用哪一台。云端 `skill_releases` 多 `vendor`、`model` 两列（启动时自动补列），没有品牌型号的旧版本在「技能发布」里指定一次，部署时要重建云平台。旧数据在打开工作区时整理一次：没有品牌型号的旧机器人自成一类，为它建的应用只能用在这一台，卡片上填一次品牌型号后同型号的机器人都能用。ROS 2 适配器默认上报 `unknown`，真机要在适配器配置里填品牌型号，否则添加时由人填。见 [ROBOT_MODEL](ROBOT_MODEL.md)。单元测试、云端（SQLite）和浏览器验收级；没有在真机上运行，云端补列没有在 PostgreSQL 上跑过，没有用旧版本的数据目录做过升级检查。
- 🟡 任务绑定应用，不在任务里开发（issue #50，0.21.12）：用户说「任务工作台应该是绑定应用或者跳转到应用页面中创建应用。而不是直接开发。」应用属于账号，在「机器人应用」里创建和修改，不打开任务也能创建；任务和应用多对多绑定，删除任务只解除绑定，应用和它的测试、发布记录留下。任务页面只留已绑定的应用（版本、品牌型号、工作步骤、可用的机器人、检查 / 测试 / 发布进度），去掉「现在做这一步」、五步进度和「需要时，再使用这些能力」；没有合适的应用时「去创建应用」，再在应用卡片上「绑定到这个任务」。一个任务只用一个品牌型号的应用：选了机器人的任务由这台机器人决定，已绑定应用时不能换成另一个品牌型号的机器人（`task_robot_other_model`）；没选的由第一个绑定的应用决定，卡片和「技能与配置」显示这个品牌型号的机器人。旧数据在打开工作区时整理一次：每个应用移到账号里、绑定回原来的任务，摘要不变，已有的测试证据照旧有效。模型、数据、训练和仿真任务仍属于任务。见 [TASK_APPS](TASK_APPS.md)。单元测试、逻辑测试和 Chromium、WebKit 浏览器验收级（设备是协议替身）；没有在真机上运行，整理只在测试建的旧数据上验证过。
- 🟡 工作台精简（issue #52，0.21.12）：页面改名「工作台」（侧栏、页面标题、面包屑）；概览页和任务页面上只作说明的文字删除（“最近创建的在前”、“现在没有正在进行的工作”、三个数字下面的说明、标题下的说明段落；任务页面的页头只有任务名称）；任务卡片不再显示机器人地址，没起名字的机器人只写台数；「技能与配置」去掉「重新读取」，每个技能多一行运行信息（在这台机器人上直接运行过几次、最近一次的时间和结果）。只改页面文字和布局，数据和接口不变。见 [WORKBENCH_UI](WORKBENCH_UI.md)。逻辑测试和 Chromium、WebKit 浏览器验收级；没有在安装好的应用里看过。
