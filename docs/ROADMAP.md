- 🟡 桌面端账号管理：打开即登录 / 注册页，注册与找回密码要邮箱验证码，保持登录，账户面板与侧栏账户菜单（main 212da95，其他成员提交，第 08 轮与各 issue 的改动一起合并；单元测试与浏览器验收级，真实邮件服务未验证）
- 🟡 调研状态与对话修复：调研入口按状态打开（开始表单 / 实时进展 / 报告），报告上可重新调研（先只读硬件扫描，再做不读旧档案的完整调研，生成新档案版本）和逐条审批的对话修复（issue #6，已合并到 main；替身级，真机与真实模型未验证）
- 🟡 调查不设 Token 和时间上限，由用户停止（issue #5，已合并到 main；替身级）
- 🟡 控制台界面：自己的下拉框、同色系悬停状态、运行中不显示代码和 JSON，要批准的命令除外（issue #7，已合并到 main；Chromium 与 WebKit 浏览器验收级）
- 🟡 真机状态页列出全部硬件（驱动是否加载、能否工作及原因）和正在运行的软件（系统服务、ROS 等中间件进程、Docker 容器、占用最高的进程），每分钟读取一次（issue #8，0.18.0，已合并到 main；页面替身级，Chromium 与 WebKit；完整读取经公网跳板机在一台四足机器人上只读验证，ROS 节点识别只在容器里验证）
- 🟡 已接入的 SSH 机器人在“配置连接”里原地修改连接：打开接入时的 SSH 表单，凭据不回显，地址变了重新确认指纹，已保存的凭据只发给指纹一致的机器（issue #9，0.18.0，已合并到 main；替身级，Chromium 与 WebKit；真机未验证）
- 🟡 硬件修复不设 Token 和时间上限，由用户停止，是否逐条批准见 issue #13（issue #10，0.18.0，已合并到 main；替身级）
- 🟡 “我的机器人”里的真机可以删除：连同它的 SSH 连接和保存的登录信息、调研与修复会话及其在本机留下的目录、设备证据、本体档案、硬件扫描、修复报告和硬件问题标注一起从这台电脑上删掉，不登录机器人；调研、修复、硬件扫描或本体适配流程运行中拒绝删除；以它为目标的应用、测试、发布和流程记录保留（issue #11，0.19.0，已合并到 main；替身级，Chromium 与 WebKit；没有在真机的记录上删过）
- 🟡 “配置连接”什么状态都能打开并保存：调研、修复或硬件扫描进行中不再拒绝；正在运行的会话继续用已经打开的 SSH 连接，还是同一台机器（指纹不变）时之后重新登录用新保存的设置，换了机器（指纹变了）则不跟过去，修复命令和重新扫描被拒绝并说明原因；新保存的登录信息立即从运行中会话读到的内容和证据里隐去（issue #12，0.19.0，已合并到 main；替身级，Chromium 与 WebKit；真机和真实运行中的会话未验证）
- 🟡 硬件修复默认允许执行，软件修不了的问题只标注：开始修复和对话修复的表单默认勾选“默认允许执行”，设备命令通过产品检查后直接执行并留记录，会话中可随时切回逐条批准；产品从文字上看不清的命令（命令替换、下载、运行脚本文件、递归删除、定时任务与 sudoers、密钥位置）、连续 60 条之后的下一条、读取新目录的申请仍先问。扫描判定需要现场处理的问题，以及修复报告里需现场处理、未修好或等待重启的问题，只标注、不能勾选，人工标注“已现场处理”后才能再交给助手（issue #13，0.19.0，已合并到 main；替身级，Chromium 与 WebKit；真机和真实模型未验证）
- 🟡 SSH 经多级跳板机接入：最多 5 级，每一级一步确认指纹，失败报级数，旧的一级连接自动迁移；`-J a,b,c`、多级 ProxyJump、嵌套写法；跟随跳板机配置里的 ProxyJump（issue #15，0.20.0，已打包部署、等用户验证，还没有进 `integration`；替身级，真机和真实的多级跳板机未验证）
- 🟡 SSH 设备的后台心跳和连接状态：每分钟在保持的 SSH 会话上执行一条 `true`，3 分钟没有心跳算离线，恢复后自动回到在线；状态页的“连不上”改为按心跳显示；被拒绝的登录不反复尝试，跳板机拒绝时它后面的机器人一起算（issue #24，0.20.0，已打包部署、等用户验证，还没有进 `integration`；替身级，Chromium 与 WebKit；心跳来自 SSH 连接本身，还不是管理层的心跳；离线时禁用安装、下任务、升级还没有做）
- 🟡 设备档案：真机卡片上的“设备档案”把系统、硬件、ROS 2（发行版、域、RMW、节点、话题、动作、服务）和资源占用合成一份记录；ROS 2 用固定的只读命令读取，ROS 设置从机器人节点进程取（issue #27，0.20.0，已打包部署、等用户验证，还没有进 `integration`；替身级，Chromium 与 WebKit；ROS 2 的只读命令在一台真机上手工执行过一次，整条产品路径没有对着真机跑过）
- 🟡 向设备传文件的通道：分块、压缩、续传、设备端 SHA-256 核对，只写到登录账号主目录下允许的目录；给安装和升级用，没有界面（issue #18，0.20.0，已打包部署、等用户验证，还没有进 `integration`；替身级；弱网验收里 60% 丢包时 SSH 建连本身失败，要先决定建连怎么处理）
- 🟡 本体类型清单：添加设备时的类型来自平台清单（内置四足机器人和机械臂，可以添加和删除，每类带状态机模板标识和应有的运控接口）；在用的类型不能删除；以人选的类型为准，不再被设备自报的类型覆盖；旧的 5 类不能再选，已登记的保留并标为“旧类型”（issue #32，0.20.0，已打包部署、等用户验证，还没有进 `integration`；替身级，Chromium 与 WebKit；标准 `spec/` 不变）
- 🟡 安全限值按设备填写：最大线速度、最大角速度、运动指令超时由人在控制台里填，保存在设备上并记录填写人和时间；真机没填时管理层照常启动、状态可读、停止可用，但所有运动指令被拒绝（`safety_limits_missing`）；ROS 2 适配器不再因为配置里没有限值而拒绝启动（issue #22，0.20.0，已打包部署、等用户验证，还没有进 `integration`；仿真与 ROS 2 替身级，Chromium 与 WebKit；只做了底盘一组，机械臂限值未定；没有在真机上验证）
- 🟡 设备上的记录：安全事件、任务结果、操作记录各自保存不被淘汰；状态和运行数据只留 1 小时，可以按时间段取；磁盘占用 90% 时按操作记录、任务结果、安全事件的顺序清理并留记录；运行日志按大小轮转（issue #25，0.20.0，已打包部署、等用户验证，还没有进 `integration`；仿真级；真机上的运行时仍是 0.4.0，新安装脚本要和新运行时一起换）
- 🟡 设备向云平台上报告警：设备上的管理层每 5 分钟上报一次，没发出去的下一次再发；急停锁定和停止未生效立刻发；云平台收下、可查看、可标已处理，连续 3 次（另有 1 分钟宽限）没收到上报的设备标为离线并出一条告警；上报默认关闭，要在设备上放配置文件（云平台地址和只能上报的 key）才开启（issue #26，0.20.0，已打包部署、等用户验证，还没有进 `integration`；仿真本体与带临时证书的替身云端，云端另在 PostgreSQL 16 上跑过；收到告警后怎么通知人、每台设备单独的凭证还没有做）
- 🟡 资料库：手册、参数表、URDF 和驱动安装包上传到云平台的磁盘卷（分片上传、中断后续传、SHA-256 核对），按本体类型、厂家、型号、版本标注；按组织隔离，owner / admin / developer 可上传和删除，operator 只读；单个文档 200 MB、驱动包 2 GB、每个组织 20 GB；上传后停在“解析中”，解析见 #34（issue #33，0.20.0，已打包部署、等用户验证，还没有进 `integration`；替身级，Chromium；真实部署的云平台未验证）
- 🟡 端侧运行时装到真机并由桌面端接入：一台 Jetson Orin NX（Ubuntu 22.04，aarch64，Python 3.10.12），两个纯 Python 包离线装在普通用户目录里，不用 sudo、不改系统；以不接硬件的仿真本体启动，只监听回环地址，桌面后端经一条手工的 SSH 隧道（过公网跳板机）接入并显示“已连接”（2026-11-15，运行时 0.4.0 / 规范 1.1.0；真机级的是安装、令牌认证、清单与状态、技能在独立进程里运行、停止锁存与解除；没有接这台机器人的硬件和 ROS，机器人不会动；没有开机自启；安装脚本 `runtime/deploy/device_install.sh`，步骤见 [runtime/README §0.4](../runtime/README.md#04-装到真机用户目录离线)）
