- 🟡 “我的机器人”里的真机可以删除：连同它的 SSH 连接和保存的登录信息、调研与修复会话及其在本机留下的目录、设备证据、本体档案、硬件扫描、修复报告和硬件问题标注一起从这台电脑上删掉，不登录机器人；调研、修复、硬件扫描或本体适配流程运行中拒绝删除；以它为目标的应用、测试、发布和流程记录保留（issue #11，0.19.0，在 `integration`，尚未合并到 main；替身级，Chromium 与 WebKit；没有在真机的记录上删过）
- 🟡 “配置连接”什么状态都能打开并保存：调研、修复或硬件扫描进行中不再拒绝；正在运行的会话继续用已经打开的 SSH 连接，还是同一台机器（指纹不变）时之后重新登录用新保存的设置，换了机器（指纹变了）则不跟过去，修复命令和重新扫描被拒绝并说明原因；新保存的登录信息立即从运行中会话读到的内容和证据里隐去（issue #12，0.19.0，在 `integration`，尚未合并到 main；替身级，Chromium 与 WebKit；真机和真实运行中的会话未验证）
- 🟡 硬件修复默认允许执行，软件修不了的问题只标注：开始修复和对话修复的表单默认勾选“默认允许执行”，设备命令通过产品检查后直接执行并留记录，会话中可随时切回逐条批准；产品从文字上看不清的命令（命令替换、下载、运行脚本文件、递归删除、定时任务与 sudoers、密钥位置）、连续 60 条之后的下一条、读取新目录的申请仍先问。扫描判定需要现场处理的问题，以及修复报告里需现场处理、未修好或等待重启的问题，只标注、不能勾选，人工标注“已现场处理”后才能再交给助手（issue #13，0.19.0，在 `integration`，尚未合并到 main；替身级，Chromium 与 WebKit；真机和真实模型未验证）
- 🟡 端侧运行时装到真机并由桌面端接入：一台 Jetson Orin NX（Ubuntu 22.04，aarch64，Python 3.10.12），两个纯 Python 包离线装在普通用户目录里，不用 sudo、不改系统；以不接硬件的仿真本体启动，只监听回环地址，桌面后端经一条手工的 SSH 隧道（过公网跳板机）接入并显示“已连接”（2026-11-15，运行时 0.4.0 / 规范 1.1.0；真机级的是安装、令牌认证、清单与状态、技能在独立进程里运行、停止锁存与解除；没有接这台机器人的硬件和 ROS，机器人不会动；没有开机自启；安装脚本 `runtime/deploy/device_install.sh`，步骤见 [runtime/README §0.4](../runtime/README.md#04-装到真机用户目录离线)）
