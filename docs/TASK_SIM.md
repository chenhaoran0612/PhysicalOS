## 页面

三层：

1. **任务列表**（`#simulation`）：每个任务一张卡片，写着品牌型号、绑定的应用、有几个技能、其中几个已经有仿真环境。按钮是「选择技能」（不能仿真的任务是「查看原因」）。
2. **一个任务的技能**：任务的仿真机器人在不在运行、在哪个技能的环境里（「关闭仿真」）；下面每个技能一张卡片：技能从哪里来（任务的应用用到 / 这个品牌型号的技能 / 装在任务的仿真机器人上）、它的环境到了哪一步（还没有环境、正在构建、已保存、自带场地、品牌型号变了、上次构建没有成功），按钮是「构建环境」或「进入仿真」。仿真机器人所在的那个技能的卡片标着「仿真机器人在这里」。
3. **一个技能的仿真**：左边是舞台（环境预览或实时画面、状态行、停止、解除急停、详细状态、关闭仿真），右边是这个技能的环境（构建表单、构建进度、已保存的环境和「重新构建」「删除环境」）和「运行这个技能」（用到它的每一步、「运行」或「按第 n 步运行」、「安装」）。最下面是**这个技能**的仿真运行记录（issue #70 的列表，按技能筛过；还没有环境时不显示，见 #74）。

返回链接和面包屑跟着层次走：「仿真试运行 / 任务名 / 技能名」。选中的任务和技能记在浏览器的 sessionStorage 里，刷新后回到同一页。

## 规则

1. **一个任务一台仿真机器人，每个技能一个仿真环境。** 环境记在任务的记录上（`task_sims`，按技能分：`envs[技能编号] = {saved, build}`），`active` 记着仿真机器人现在在哪个技能的环境里。仿真机器人和其他机器人一样属于账号，出现在「我的机器人」里，名字是「任务名 仿真」，记着它是哪个任务的（`sim.task_id`）。
2. **任务的技能**，按这个顺序列出、不重复：任务绑定的应用的步骤用到的技能（按步骤顺序，带着每一步的参数）；小鸭的技能模型；这个品牌型号的其他技能——登记过的技能记录（issue #68）和随应用带的、属于这个品牌型号或通用的示例技能包（issue #69）；装在任务的仿真机器人上、上面都没有的技能。所以没有绑定应用、但有品牌型号的任务（比如只选了机器人的任务）也有技能可以仿真。
3. **仿真什么由任务的品牌型号决定**（任务选的机器人的，否则是它最早绑定的应用的，见 [TASK_APPS.md](TASK_APPS.md)）。还没有品牌型号的任务不能仿真，页面写明要先绑定应用或选择机器人。
4. **机器人模型从哪里来**，按顺序找：

   | 这个品牌型号是 | 怎么仿真 | 要不要构建环境 |
   |---|---|---|
   | 内置档案里的型号，安装包里有它的模型（issue #54） | MuJoCo，用档案的模型和站立姿态 | 要，每个技能一个 |
   | 不在档案里，或安装包里没有它的模型，但资料库里有确认「可用」的机器人模型（issue #51） | MuJoCo，用资料库的模型 | 要，每个技能一个 |
   | NeuxMind 示例的两款 | 应用原有的示例仿真，没有三维画面，页面显示俯视图或关节 | 不要，每个技能都是「自带场地」 |
   | Microduck AD-P102（issue #63） | 小鸭自己的仿真；**每个技能模型在它训练时用的场地上**（场地在它的技能模型包里） | 不要 |
   | 都不是 | 不能仿真，页面写明缺什么，并给出「去资料库」 | — |

   同一个品牌型号的不同写法算同一个（`zs / L2U` 就是「智身科技 钢镚 L2-U」，和 issue #54 一致）。
5. **构建一个技能的环境**：「让工程助手构建」要勾选同意（和其他工程会话一样），要有可用的模型算力；它是一次普通的工程会话（名字是「任务名 · 技能名」），页面上可以「查看过程」，可以「取消这次构建」。「先用空场地」不用助手。两种都要在子进程里用 MuJoCo 建一次、画出预览，通过了才保存。**每个技能同时只有一次构建**；不同技能可以同时构建。
   - **交给工程助手的只有这个技能**：`SIMULATION.json` 里有任务的名字和说明、`skill`（编号、名称、说明，示例技能包里有的还带参数的定义）、`uses`（任务的应用里用到这个技能的那几步和它们的参数），没有别的技能的步骤。说明里写明「环境只为这一个技能准备」，地点名用技能参数和任务说明里的。
   - **构建时的 Token 额度**（issue #74）：工程助手的构建原来没有设 Token 额度，引擎按默认的 3 万停，真的模型三次请求就用完了，还没写出环境就被停下（2026-11-28 这台 Mac 上那次构建：「工程助手没有写出环境描述：会话被停止了」）。现在额度是 40 万，12 分钟的时间上限不变；再用完会写「用完了这次构建的 Token 额度」。见 [MUJOCO_SIM.md](MUJOCO_SIM.md)。#75 的构建仍然走 `mujoco._ask_agent`，这个额度照样生效。
   - **还没有环境时不显示运行记录**（issue #74，#75 起按技能）：技能的页面上，这个技能还没有环境（没构建过、正在构建、第一次构建没成功、品牌型号变了）时，最下面的运行记录不显示；任务的技能页面上，有一个技能有环境（或这个型号自带场地）才显示任务的运行记录。
   - 不用构建的型号（示例机器人、小鸭）要求构建时拒绝，说明「自带场地，直接进入」。
6. **保存的环境一直用**，直到重新构建成功（旧的被替换）或「删除环境」。重新构建失败、被取消、应用中途退出：已保存的不变，页面写明这一次为什么没成。
7. **重新构建成功后**：仿真机器人正在这个技能的环境里，就换到新环境（正在运行就重启一次），装在它上面的技能保留；在别的技能的环境里，就不动，下次进入这个技能时用新的。
8. **进入一个技能的仿真**：第一次新建并启动仿真机器人（MuJoCo 要先建模型，可能一两分钟），以后用已有的那一台：
   - 它在另一个技能的 MuJoCo 环境里：换成这个技能的环境，重启一次；
   - 示例机器人：不用换，直接用；
   - 小鸭：发一条「换场地」给它（`cmd: stage`），它在后台载入这个技能模型的场地，页面状态行写「正在换到「…」的场地」，载入期间不能运行；正在表演时不换（表演完的下一次运行本来也会换到自己的场地）；
   - 被关闭的会重新启动，在「我的机器人」里被删除的会重新建一台；品牌型号或仿真方式变了的旧机器人删掉再建；小鸭是在这个技能模型进套件之前添加的（它的配置里没有这个模型），也删掉再建。
   - 换环境时先记下「不在任何技能的环境里」，再改配置、重启：重启失败时，页面不会说它还在原来那个技能的环境里，下次进入会重新写配置。
   - 然后把**这个技能**装上（这台电脑上有它的技能包时：随应用带的示例技能，或以前安装时用过、现在还在的技能文件夹）；装不上照样进入，页面写明原因。小鸭的技能模型在它启动时就都装上了（issue #67）。
9. **运行**：只有仿真机器人在这个技能的环境里时能运行。走原有的路径（勾选授权 → `robots/run-skill`），参数先填好应用那一步的值，可以改；一个技能在应用里用了几次，就有几个「按第 n 步运行」。**小鸭的技能模型也这样运行**（`duck.<模型>`，issue #67 的 `policy.run`），所以它也是一条操作、有运行记录；#63 的文件通道（「训练与改进」里的「运行」）照旧。
10. **删除一个技能的环境**：只删这个技能的环境和它的预览；任务的仿真机器人、装在它上面的技能、其他技能的环境都留着。仿真机器人正在这个环境里时，把它关掉。正在进入（启动或换环境）时，删除等进入做完再做，不会留下一台指着已删除环境的机器人。
11. **任务换了品牌型号**（解除了全部应用又绑了别的）：已保存的环境标为「品牌型号变了，需要重新构建」，不能进入；重新构建后，旧的那台仿真机器人删除，进入时按新的品牌型号新建。
12. **停止**立即发出并锁存急停（和「实时状态」里的一样）；页面写明急停已锁存，给出「解除急停」，锁存期间不能运行技能。「关闭仿真」只停掉进程，环境和技能都留着。
13. **删除任务**时，它所有技能的环境、预览图和仿真机器人一起删除。
14. **#75 之前保存的记录**（一个任务一个环境）第一次读到时改成新的样子：工程助手生成的或空场地的环境，沿用为任务这时列出的**每个技能**的环境（应用用到的和这个品牌型号的其他技能；页面注明「这是以前整个任务共用的环境」，可以「重新构建」只为这个技能布置），一次构建也不丢；「自带场地」和失败的构建不沿用（每个技能自己有），失败那次的文件夹删掉。仿真机器人留着，下次进入时换到那个技能的环境里。
15. 仿真结果只说明逻辑是否正确，**不是现场证据**，这一点没有变。

## 没有改的

- 「添加仿真机器人」（按类型、品牌、型号，issue #54）照旧，在「我的机器人」里。

## 接口

桌面端后台（`brainos/task_sim.py`；都是 POST、JSON，`project_id` 是任务，`skill_id` 是技能编号，如 `patrol`、`duck.water`）：

| 路径 | 作用 |
|---|---|
| `task-sim/list` `{}` | 每个任务：品牌型号、绑定的应用、怎么仿真（`model`）或为什么不能（`problem`）、`counts`（技能数、有环境的、正在构建的、第一次构建失败的）、预览图、仿真机器人 |
| `task-sim/view` `{project_id}` | 一个任务和它的每个技能（`skills`：来源、用到它的步骤、`environment`、`build`、装没装在仿真机器人上、参数）；`robot.skill` 是仿真机器人所在的技能 |
| `task-sim/build` `{project_id, skill_id, mode: agent \| empty, note?, data_authorized?, model_id?}` | 构建一个技能的环境；自带场地的型号拒绝 |
| `task-sim/cancel` `{project_id, skill_id}` | 放弃这个技能正在进行的构建 |
| `task-sim/remove` `{project_id, skill_id}` | 删除这个技能的环境（构建进行中拒绝）；仿真机器人在里面时关掉它 |
| `task-sim/enter` `{project_id, skill_id}` | 在这个技能的环境里启动（或换过去）仿真机器人，装上这个技能；返回 `view` 加 `installed_now` |
| `task-sim/install` `{project_id, skill_id}` | 把一个技能装到任务的仿真机器人上 |
| `sims/duck/status` | 多了 `stage`（小鸭现在站在哪个技能模型的场地上）和 `staging`（正在载入的） |

预览图：`GET /api/sim/mujoco/preview?id=<环境编号>`（和 issue #51 同一个地址；只给自己工作区里记录着的编号）。实时画面、状态、运行、停止用的是仿真机器人原有的接口。

错误码没有新增（`task_sim_no_product`、`task_sim_not_built`、`task_sim_no_package`、`sim_scene_busy`、`duck_show_missing` 都是原有的）。

## 在哪里验证过，哪里没有

见提交说明和交付记录里的测试结果；这里只写范围。

验证过（2026-11-28，这台 Mac，MuJoCo 4.0.1）：

- 单元测试里：每个技能各自构建、保存、进入；进入另一个技能时同一台机器人换到那个技能的环境（配置换了、重启）；构建另一个技能不动正在用的环境；重新构建正在用的环境后机器人换过去并保留技能；删除一个技能的环境只关掉在里面的机器人、别的环境还在；交给工程助手的只有这一个技能和用到它的步骤；#74 的 Token 额度在按技能的构建里照样生效；示例四足进入不同技能是同一台机器人、只装进入的那个技能；小鸭每个技能模型是自带场地、进入后站到那个技能模型的场地上、换技能后换场地、正在表演时不换、通过运行时运行技能模型成功；#75 之前的记录改写。
  审查（独立的审查子代理）找出、已修并补了测试的：旧记录只沿用给应用用到的技能（现在给任务列出的每个技能）；换环境重启失败后页面仍说在原环境里；进入时删除同一个环境留下指向已删环境的机器人；缺少这个模型的小鸭；层次极深的技能结果让记录页出错。
- 浏览器里（Chromium，WebKit 也跑了前两项）：`task_sim_browser` 走完示例四足和真实的宇树 Go2（MuJoCo）两条路——任务列表 → 任务的技能 → 一个技能：构建空场地、进入、运行、停止、刷新后留在这个技能、窄屏不溢出 → 另一个技能有自己的环境 / 进入后同一台机器人换过去 → 列表显示几个技能有环境 → 关闭、删除一个技能的环境后机器人还在；`task_sim_duck_browser`（编造的套件）每个技能模型是自带场地、进入后小鸭站到那个模型的场地上、运行完成并列在这个技能下、进入另一个模型后同一只小鸭换场地。全部 Chromium 脚本也在这个分支上跑过一遍。

没有验证的：

- **真的大模型为单个技能写的环境**：格式和建模的检查都在，但写得合不合用只有人看。
- 小鸭的真实套件（`.build/duck-kit`）在这个页面上换场地的实际耗时：单元测试用的是编造的套件。真实的技能模型包每个都要编译场景（38 个网格），换一次可能要几秒到几十秒，期间状态行写「正在换到…的场地」。
- 资料库里的机器人模型这条路径在这个页面上没有单独跑过浏览器（规则和 issue #51 共用，单元测试只覆盖了内置档案的模型）。
- 打包后的应用、DMG 安装后的应用；Intel Mac、Linux。
- 和真机的对比。

已知的限制：

- 任务的仿真机器人和其他仿真机器人一样，应用关闭时在运行的，下次打开会自动恢复；任务多的时候会同时起多个仿真进程。
- 一个任务只有一台仿真机器人：换技能的 MuJoCo 环境要重启它（一两分钟以内）。
- 环境保存后不能改，只能重新构建。
- 技能包只认示例技能和以前安装过的文件夹；从云端「技能加载」装过的技能，进入时不会自动装到仿真机器人上，要在页面上点「安装」。
- 随应用带的示例技能包按品牌型号归属（issue #69，[SKILL_PRODUCTS.md](SKILL_PRODUCTS.md)）：任务的应用用到别的品牌型号的示例技能（比如宇树 Go2 的任务用了「巡逻」）时，进入照样进入，这个技能显示没有装上，并写明它属于哪个品牌型号。
- 运行的是单个技能，不是按应用的步骤整条跑；整条应用的仿真测试仍在应用的交付清单里。
