# 装好技能后直接运行（issue #42）

机器人装好一个技能包之后，可以马上运行它；技能有参数时，运行前的表单里每个参数都有输入框。这在仿真机器人上一直可以，真机原来不行：真机上的技能只能先编排成“机器人应用”，做完现场测试、部署之后才能运行。本文说明这次改了什么、真机上多了哪些确认，以及在哪里验证过。

> 第二部分（机器人属于账号，不属于某个任务）见 [ROBOT_SCOPE.md](ROBOT_SCOPE.md)。
>
> 状态：代码和测试完成；**没有在任何真机上运行过**。验证用的是真实的管理层加一个替身本体（仿真四足，但清单里不说自己是仿真），见[最后一节](#在哪里验证过哪里没有)。

## 用起来是什么样

1. 在“我的机器人”里点开一台已连接的机器人的“能力与技能”，点“安装技能包”，选一个技能，确认安装。
2. 安装成功后直接进入“运行技能”表单（原来真机会回到机器人详情）。
3. 表单按技能自己声明的参数生成输入框：下拉选项、数字（带单位和范围）、文字、开关、坐标点。必填的不填、超出范围的值，在发出之前就在对应的输入框旁边指出来。技能没有参数时，表单说明“这个技能没有需要填写的参数”。
4. 勾选确认，点“授权并运行”。之后看到的是这次运行的状态：进度、技能输出的最近几条消息、“停止”按钮。
5. 以后再运行：机器人详情“已安装技能包”里每个技能旁边都有“运行”；“技能运行状态”可以回到运行状态的画面。

参数表单不是这次新做的：仿真机器人和“机器人应用”的步骤一直在用它（`web/ux02.js` 的 `skillParamsForm`）。这次是让真机也走到这张表单。

## 真机和仿真的区别

| | 仿真机器人 | 真机 |
|---|---|---|
| 运行前的确认 | 一项：授权它执行这个技能 | 两项：现场有人看着、周围没有人和障碍物、急停按钮够得着；授权它执行这个技能 |
| 没填安全限值 | 不需要填 | 表单里先说明“填写之前设备会拒绝运动”，并给出“填写安全限值”的入口；只读取状态的技能仍可以运行 |
| 运行状态里的提示 | 停不下来时重启仿真 | 软件停止不能替代硬件急停 |

哪些算真机：凡不是控制台自己启动的仿真机器人，都按真机处理。设备在清单里说自己是仿真（`simulated: true`）不算数：一台接错了适配程序的真机不能靠这一项免掉现场确认。

第二项确认由后端把关（`brainos/skill_run.py`）：真机的运行请求里没有 `onsite_confirmed: true` 时，什么都不会发给设备，返回 `onsite_confirmation_required`，页面用平常的话解释。这样一个只为仿真写的页面或脚本不会误启动真机。

每次运行留下一条操作记录和一条审计记录（`skill.run`），其中写明是不是仿真、现场确认有没有给。

## 没有变的保护

这些都在设备上的管理层里，这次没有动，真机直接运行技能时照样生效：

- 急停锁存时拒绝运动；控制台在发送前也会拒绝，并提示先解除急停。
- 真机没有填写安全限值时拒绝运动（技能会启动，在第一个运动指令处失败，运行状态里显示原因）。
- 参数不符合技能声明（类型、范围、选项）时拒绝运行，并指出是哪个参数。
- 速度上限、时长和范围上限由安全监督器执行。
- “停止”立即发送、不需要确认，停止后锁存急停；解除急停要现场确认。
- 同一个请求标识不会发送两次；结果不明时不自动重试。

## 什么时候仍然用“机器人应用”

直接运行适合装好之后试一下、临时让机器人做一件事。要反复执行、要组合多个技能、要留下现场测试证据并部署的工作，仍然编排成“机器人应用”：现场测试 → 部署 → 启动。直接运行的结果不算现场测试证据。

## 改了哪些地方

- `brainos/skill_run.py`（新）：哪些机器人算仿真，真机需要的第二项确认，写进记录的事实。
- `brainos/sim_robots.py`：`run_skill` 不再拒绝真机，改为调用上面的检查（发送前一次，按连接检查刚读到的清单再一次）。
- `web/skill_run.js`（新）：运行按钮、表单底部的说明和确认、没填安全限值的提示、随请求发送的确认。
- `web/sim.js`、`web/robot_detail.js`：原来写着“只有仿真”的几处改为调用 `web/skill_run.js`；安装成功后真机也进入运行表单；真机读不到状态时不再显示“仿真进程”。
- `web/ux04_errors.js`：`onsite_confirmation_required` 的说明。

## 在哪里验证过，哪里没有

验证过的（没有真机）：

- `tests/test_skill_run.py`（13 项）：控制台后端对真实的管理层（进程内，经它的 HTTP 接口），本体是不说自己是仿真的替身。少一项确认时什么都没发出（现场确认只认 `true`，设备自称仿真也免不掉）；两项都有时技能按表单的参数运行到结束，记录里有现场确认；同一请求不重发；选项之外的值被设备拒绝并指出参数；“停止”结束运行并锁存，锁存时不能再运行；没填安全限值时机器人不动并显示原因；仿真机器人仍然只要一项确认。
- `tests/skill_run_logic.cjs`（26 项）：页面的判断，包括哪些机器人有运行按钮、表单要哪些确认、没填限值的提示、发送的内容、拒绝的解释。
- `tests/skill_run_browser.cjs`（Chromium 和 WebKit）：按地址添加一台“真机”（管理层在独立进程里），安装技能后直接进入运行表单，参数有输入框；在提示里填写安全限值；少一项确认时发不出去，后端的拒绝在表单里有解释；运行、看到状态、结束；第二个技能改数字参数后运行，“停止”后急停锁存。375、768、1440 三种宽度下没有横向溢出。
- 原来断言“真机不能直接运行”的两处测试（`tests/test_ux01_sim.py`、`tests/test_ux04.py`）改为断言新的规则；`tests/desktop02_browser.cjs` 里“安装后回到机器人详情”的一步改为“安装后进入运行表单”。
- 桌面端完整测试 1668 项通过（跳过 8 项）；经过技能安装和运行的 13 个原有浏览器验收脚本在 Chromium 上通过。

没有验证的：

- **真机上的任何一步。** 管理层在真机上经 SSH 转发连接时的运行、停止，没有试过。
- 桌面应用窗口（WKWebView）里没有点过；WebKit 上的浏览器验收通过。
- 真机运行状态的画面沿用仿真的那一个：有位置时画俯视图，本体不提供位置或关节状态时只显示“没有提供位置或关节状态”和技能的进度、消息。

## 已知限制

- 真机的卡片上没有单独的“运行技能”按钮，入口在“能力与技能”里。
- 运行表单里的“填写安全限值”会离开表单；填完后要回到“能力与技能”再点“运行”。
- 运行状态的画面里，有技能在运行时“运行技能”不可用；机器人详情里的“运行”这时仍能点，设备是否接受第二个技能由管理层决定，这一点没有测。
- 错误说明表里 `simulated_only` 一条还在（旧版后端会返回它），新后端不再产生。
