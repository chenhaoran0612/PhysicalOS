# Robot OS 平台框架 v0.2

## 产品边界

用户拿到机器人后，在平台完成接入、能力开发、模型选用 / 训练、仿真、测试、部署和运维。平台运营方提供模型、算力、闭源 API 调用与计费；自有资源接入是可选路径。系统不承诺未知本体无需驱动、校准或验收即可工作。

Mac 桌面应用是用户入口，内置本地工作空间和设备连接能力。共享商业平台属于独立服务端；桌面菜单可连接其 HTTPS 工作台。真实平台域名、模型资产、运营资源和支付渠道均由运营方配置。

## 分层

1. 产品客户端：项目、模型库、技能编排、Agent、训练、仿真、测试、部署、用量。
2. 控制平面：用户与权限、资产与版本、任务、执行预算、证据、发布。
3. 平台供给：模型目录、端侧部署包、闭源网关、训练与仿真资源、额度与计量。
4. 工程执行：训练器、模型后端、仿真引擎、Agent Harness、工具沙箱。分别实施预算和隔离。
5. 端侧运行：Edge Agent、模型运行时、技能执行器、能力适配器和厂商控制系统。

现阶段实现第 1–3 层框架及第 4–5 层协议 / 网关。平台不在 API 进程内执行用户代码或大模型训练，不混入现有 Continuum 展示服务。

## 统一对象与证据

- Workspace → Project → Robot / Model / Dataset / Scene / Skill / Application。
- Application 固定技能与模型摘要、目标机器人、参数、超时和停止条件。
- Job 为训练、仿真、Agent 或测试声明资源、配置、预算和输出。
- Evaluation 区分静态、外部执行结果和现场报告。只有匹配的现场报告可作为设备应用发布门槛。
- ModelPackage 固定模型来源、许可、版本、下载引用、SHA256、兼容形态和运行时。
- ResourceOffer 固定运营方服务、类型、计量单位与价格；用户看不到供应商密钥。
- Reservation / Usage / Ledger 把预算、实际用量、证据和余额关联起来。

## Agent 与 Harness

Agent Studio 的协作流程由独立 Workflows 服务管理。不可变定义保存角色、模型、固定扩展版本、交付文件与预算；运行实例记录阶段和尝试。每阶段创建独立工程会话，完成后校验 HANDOFF.json 与真实命令记录，再生成带摘要的快照。用户验收通过后才创建下一个会话；上游文件复制到新会话的 UPSTREAM 目录。启动、验收、停止、重试统一串行化处理，应用重启不自动重放模型调用。现阶段支持串行流程，不包含并行 DAG 调度或实机部署自动批准。

内置工程运行时负责持续会话、计划、文件修改、命令与测试、子 Agent 协作和工具审批。本体调查通过受控 SSH 工具采集证据，生成按机器人保存的软硬件档案。工程任务读取档案，在专属目录生成适配器与 Harness。用户选择平台付费模型或自有 API，计量与预算经统一账本处理。原有确定性项目检查和远程 JobExecutor 均保留。

实际实现、权限边界、模型网关协议、上游来源和尚未产品化的功能见 [ENGINEERING_ENGINE.md](ENGINEERING_ENGINE.md)。提交任务、生成代码、调查完成与实机验收分别记录，不互相替代。

## 模型与机器人部署

自研 / 开源模型可以加入项目并安装到兼容端侧；闭源模型通过平台网关调用。端侧模型包安装不启动动作。机器人应用发布则需要能力匹配和现场证据；开始工作需要明确操作授权。重复请求由设备端幂等记录约束；网络结果不确定时不自动重放。

设备端保留实时运控、控制权仲裁、硬件限制和停止行为。Web 或桌面停止按钮是受认证的停止请求，不代替硬件急停。模型推理、工程 Agent、录制、云端服务故障不能直接阻塞硬件停止路径。

## 后续里程碑

1. 平台供给上线：一个真实模型网关、一个训练执行器、一个仿真服务、一个自研端侧模型包。
2. 端侧落地：选定真实本体，实现驱动 / 能力 / 模型安装 / 技能执行与现场测试；不能用协议替身替代实机证据。
3. 开发体验：场景编辑器、3D 仿真视图、技能图编辑器、代码工作区、遥测与回放。
4. 商业上线：托管身份、团队权限、云存储、持久任务队列、实时计量、真实支付与对账、密钥服务和发布治理。
5. 分发：Developer ID 签名、公证、自动更新、Intel Mac；Windows 在用户后续授权范围内单独处理。
