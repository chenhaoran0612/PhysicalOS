# 向设备传文件（issue #18）

桌面端把一个本地文件送到设备上的指定位置：分块、压缩、可续传，传完在设备上核对 SHA-256，一致才放到目标位置。它是产品自己调用的通道，给「在控制台里安装管理层」（issue #19）和「把驱动安装包送到设备」（issue #31）用；目前没有界面，也没有 HTTP 接口。

它和助手敲的命令无关。修复规则里 `scp`、`rsync` 要人批准（`brainos/repair_policy.py` 的 `ASK_FIRST`），管的是助手提出的命令，那条规则没有变；这条通道不经过助手，本地文件由产品代码指定，目标位置在这里检查。

代码：`brainos/device_transfer.py`（传输过程和对外接口）、`brainos/device_transfer_target.py`（允许写到哪里、设备上执行的三段脚本）、`brainos/device_transfer_record.py`（本机的续传记录）。连接仍由 `device_access.SSHDevice` 建立（包括跳板机），脚本经 `hardware_init.run_command` 执行；这两个文件都没有改动。

## 怎么调用

```python
from brainos import device_transfer

result = device_transfer.send_to_robot(platform, connection_id, local_path, '~/neuxmind-pkg/runtime/pkg.whl',
                                       on_progress=show, stop=stop_event)
```

- `connection_id` 是已保存的 SSH 连接。每次重连都重新读取保存的登录信息。
- 目标路径只有一种写法：`~/目录/文件名`，相对登录账号的主目录，必须在允许的目录内。默认只允许 `~/neuxmind-pkg`；调用方可以用 `roots=('~/另一个目录',)` 换成别的。
- `mode` 是文件权限，默认 `0o644`，最多 `0o755`。目标位置已经是这个文件时不重传，但仍会把权限改成 `mode`。
- `on_progress(event)` 收到 `stage`（`checking`、`sending`、`retrying`、`verifying`、`done`）、`sent`、`total`（设备已确认的字节数和文件大小）、`attempt`；`retrying` 还带 `error` 和 `wait`。它抛出的异常会包成 `ProgressHandlerError` 原样抛给调用方，不会被当成网络问题重试；如果文件其实已经传完并核对通过，结果在异常的 `result` 里。
- `stop` 是 `threading.Event`，置位后传输结束，正在等设备答复时也一样。
- 返回 `path`（设备上的实际路径）、`bytes`、`sha256`、`verified`（恒为真；核对不了或不一致都会抛出异常）、`already_present`（目标位置已经是这个文件，没有重传）、`resumed_from`（这次调用从第几个字节接着传）、`sent_bytes`（这次调用实际发出的字节数，压缩后）、`encoding`、`attempts`、`seconds`。
- 失败抛出 `device_transfer.TransferError`（见下文「失败时」）。
- `robot_transfer_status(platform, connection_id, 目标路径)`：这个目标未完成的传输停在哪，没有则为 `None`。
- `robot_unfinished_transfers(platform, connection_id)`：这台机器人所有未完成的传输，每一项都在设备上留有临时文件。
- `discard_robot_transfer(platform, connection_id, 目标路径)`：放弃一次未完成的传输，删除设备上的临时文件和本机记录，不动目标位置已有的文件。设备连不上时记录保留，可以稍后再清理。
- `forget_robot_transfers(platform, connection_id)`：只删本机记录、不联系设备。删除机器人时（`robot_remove.py`）对它的每条 SSH 连接调用一次；设备上如果还留着未完成传输的临时文件，不会因此被清掉（要清就在删除机器人之前先放弃那次传输）。

不经过 `platform` 时用 `upload(connect, local_path, remote_path, record_dir, device_key=...)`，`connect()` 每次调用返回一个新的 `SSHDevice`；对应的还有 `transfer_status`、`unfinished`、`discard`。

调用方要自己保证 `local_path` 是产品选定的文件（随控制台发布的安装包、资料库里的安装包），不能来自模型或页面输入：这条通道不判断哪个本地文件可以离开这台电脑。通道自己只做两件事：本地路径本身（最后一级）是符号链接就不接受，上级目录是链接、或文件是硬链接则不管；每发一块之前确认它还是算过校验值的那个文件（同一个 inode、大小和修改时间），被改写或被换掉就立刻停止，不再发出任何内容。

因此本地文件要放在 inode 号稳定的文件系统上。已知不稳定的一种：Docker Desktop 把 Mac 的目录挂进 Linux 容器时，同一个文件的 inode 号每隔一两分钟变一次（大小和修改时间不变），从那里传几分钟的文件会以 `source_changed` 停下。在容器里用这条通道（比如做弱网测试）时，先把文件复制到容器自己的文件系统。桌面应用自带的安装包在本机磁盘上，不受影响。

## 文件怎么传过去

1. 先算出本地文件的 SHA-256。
2. 连接设备，执行一次检查脚本：设备上有没有可用的校验工具和 gzip；目标位置是不是已经是这个文件（是就直接结束）；同一个目标留下的别的版本的临时文件一并删除。
3. 文件切成块（默认 256 KB）。设备有 gzip 而且内容压得动时（开头 64 KB 能压到九成以下），每块单独压缩成一个 gzip 成员；否则原样发送。安装包大多已经压缩过，会原样发送。连接断过之后块的大小见下文「断点续传」。
4. 每块经 SFTP 写到目标旁边的临时文件 `.<文件名>.nxpart-<校验值前 16 位>` 的固定位置（权限 600），设备确认收到这一块的每个字节后才算数，然后把位置写进本机的续传记录。
5. 全部传完，执行一次核对脚本：先测试压缩流是否完好，再解压到只有本账号可读的临时文件，在设备上算 SHA-256，和本地的一致才 `chmod` 并一次 `mv` 到目标位置（目标位置不会出现写了一半的文件），然后删除临时文件。

「已核对」的意思是设备自己算出了这个校验值：它防的是传输途中和设备磁盘上的损坏，防不了一台对自己说谎的设备。

### 断点续传

连接断开、设备长时间不答复（默认 120 秒没有任何一块被确认，就主动断开）或者用户停止，最多损失正在传的那一块。下一次连接（同一次调用里自动重连，或者以后再调用）先问设备临时文件现在有多大，再从双方都认可的位置接着传：不压缩时是已到达的任意字节数，压缩时是最近一个完整的块。

- 自动重连：连续没有进展的失败之间依次等 1、2、5、10、20、30 秒；只要这次连接有新的块被确认，计数就重新开始。连续 7 次没有进展就停下来报告。
- 断过之后的块大小：每次重连后先用 16 KB 的小块，再断一次时在路上的内容就少。之后大小跟着链路走：设备在 3 秒内确认了一块，下一块加倍；超过 3 秒才确认，下一块减半；最小 16 KB，最大是调用方给的大小（默认 256 KB；调用方给的比 16 KB 还小时就一直用那个大小）。链路只是闪断一下时，默认大小下四块之后就回到原来的大小（每块都要等设备答复一次，往返时延大的链路上一直用小块会慢很多）；链路变差时块又缩回去。再断一次损失的是正在路上的那一块，大约是几秒钟发出的内容，块长回去之后最多是一整块；然后又从 16 KB 开始。没有断过的传输始终用调用方给的大小，以后再调用（不是同一次调用里的重连）也从这个大小开始。
- 续传记录放在工作区的 `transfers/` 目录，每台设备一个子目录，每个目标路径一个 JSON 文件，内容是文件的校验值和大小、设备上临时文件的名字、已确认的位置，没有登录信息，目录 700、文件 600。记录一直保留到这次传输完成、被拒绝或被放弃，所以设备上留下的临时文件随时查得到。记录从磁盘读回来时按外部数据检查，对不上就当作没有，传输从头开始。
- 压缩传输只记最近 64 个块的位置；设备上的临时文件如果比这更短（设备掉电丢了数据），从头开始。
- 本地文件换了内容（校验值不同），不会接着旧的传。旧版本的记录保留到设备上的旧临时文件被清掉（新传输连上设备后的第一步）为止。
- 核对脚本执行完但答复丢了：重连后的检查会发现目标位置已经是这个文件，不再重传。
- 同一个目标同一时间只允许一次传输，这个限制只在本进程内有效。

## 允许写到哪里

- 只能写进调用方允许的目录之内，而且这些目录只能在登录账号的主目录下。主目录之外的位置，要么不用 `sudo` 写不进去，要么别的账号也能写（例如 `/tmp`，别人可以在核对之后、安装之前换掉文件），所以一律不允许，绝对路径也不接受。
- 路径每一段只能用字母、数字和 `. _ + -`，不能以 `.` 开头（没有隐藏文件和隐藏目录），最多 200 个字符；不能是存放凭据的位置（沿用 `device_access.SENSITIVE`：`.ssh`、`.env`、`id_rsa`、`credentials`、`secrets` 等）；文件名里不能有 `.nxpart-`、`.nxtmp-`（留给临时文件）。这些只看文字就能判断，在连接设备之前就拒绝。设备报告的主目录路径也必须由这些字符组成（另外允许 `@`，例如 `/home/账号@域`），否则不传。
- 主目录以下经过的每一级都不能是符号链接；目标位置如果已经是目录或符号链接，不覆盖。缺少的目录在往下走的路上创建（权限 755）。
- 这些是开始时经 SFTP 检查的。之后每段脚本在动手之前还会在设备上再确认一次：目标目录仍然是它自己（`pwd -P`），临时文件不是链接，目标位置没有变成目录或链接。如果设备的 SFTP 报告的主目录本身要经过符号链接才能到达（OpenSSH 的 SFTP 会先解析链接，不会这样），这一步会拒绝，传不了。
- 清理只删除这条通道自己起的名字：`.<文件名>.nxpart-<16 位十六进制>` 和 `.<文件名>.nxtmp-<16 位十六进制>.<数字>`，旁边名字相近的别的文件不动。
- 全程不用 `sudo`。设备上只执行 `device_transfer_target.SCRIPTS` 里的三段固定脚本（检查、核对、清理）：脚本文本经标准输入交给 `sh -s`，命令行上只有 `sh -s --` 和上面那种字符组成的参数，所以登录 shell 是 sh、bash、zsh、csh 还是 fish 读到的都一样，名字里也没有任何字符会被当成 shell 语法。
- 设备返回的文字（错误说明等）显示和保存之前会去掉控制字符和方向控制字符，并隐藏已保存的登录信息。

## 失败时

`TransferError` 带 `stage`、`reason`、`sent` / `total`（设备已确认的字节数和文件大小）、`remote_temp`（设备上留下的临时文件，没有则为 `None`）、`resumable`（设备上留有这次传输的临时文件，再调用一次会从 `sent` 接着传）、`attempts`，文字说明里写了停在哪、设备上留下了什么。

`resumable` 为假不等于不值得再试：还没开始传就失败（例如一直连不上设备）时设备上没有临时文件，它也是假，这时再调用一次会从头传。要不要再试按 `reason` 判断（调用方已经在这样用，所以下表里的名字改动时要连调用方一起改）。

| stage | reason | 含义 | 设备上留下什么 |
| --- | --- | --- | --- |
| `request` | `path`、`sensitive`、`outside`、`occupied`、`roots`、`mode`、`source`、`options`、`device`、`records` | 请求本身不成立：路径无效或越界、经过符号链接、目标位置被目录或链接占着、本地文件读不到、是符号链接或超过 4 GB 等 | 没有写任何东西 |
| `request` | `busy` | 同一个目标正在传 | 不受影响 |
| `connect` | `auth`、`key`、`fingerprint`、`forbidden` | 登录被拒、私钥解不开、主机指纹变了、跳板机不让转发。不重试 | 之前传到的部分还在，可续传 |
| `connect` | `no_sftp` | 连接正常，但设备的 SSH 服务没有接受 SFTP 请求，或者它的 SFTP 不报告文件类型。不重试 | 同上 |
| `connect` / `send` / `verify` | `interrupted` | 连续 7 次连接都没有新的进展 | 临时文件保留，可续传；还没开始传时没有临时文件，再调用是从头传 |
| 任意 | `cancelled` | 按停止请求结束 | 临时文件保留，可续传 |
| `send` | `refused` | 连接正常但设备拒绝写入：磁盘已满、没有写权限、配额不足。不重试 | 已确认的部分保留，腾出空间后可续传 |
| `send` | `occupied` | 临时文件的位置被目录或链接占着 | 没有动它 |
| `send` | `source` | 传到一半本地文件读不到了 | 临时文件保留；同一个文件回来后可续传 |
| `send` | `source_changed` | 传输过程中本地文件被修改或被换掉 | 已清理 |
| `send` | `records` | 本机的续传记录写不进磁盘 | 临时文件保留，但没有记录可续 |
| `send` / `verify` | `outside` | 设备上的目标目录要经过符号链接才能到达，或在检查之后被移走 | 临时文件可能还在原处，记录保留 |
| `verify` | `no_checksum_tool` | 设备上没有 `sha256sum`、`shasum`、`openssl` 中的任何一个，无法核对，所以不传；或者传完后校验工具不可用了 | 前者没有写文件内容；后者临时文件保留 |
| `verify` | `checksum` | 设备上算出的 SHA-256 和本地不一致。不重试 | 已清理，目标位置原有的文件没有动 |
| `verify` | `damaged` | 传到设备上的压缩流已损坏 | 已清理，目标位置原有的文件没有动 |
| `verify` | `no_space` | 压缩流完好，但设备上放不下解压后的文件 | 临时文件保留，腾出空间后再调用一次即可，不用重传 |
| `verify` | `unplaced` | 校验一致，但 `chmod` 或 `mv` 到目标位置失败，或目标位置变成了目录或链接 | 临时文件保留（权限恢复为 600） |

检查和核对脚本的时限随文件大小放宽（按设备每秒读 2 MB 估算），所以目标位置有一个同样大小的大文件、需要先算它的校验值时不会超时。连接阶段的超时仍是 `device_access` 里的值（建立 TCP 10 秒、握手 20 秒、认证 20 秒）。

## 设备需要什么

SFTP、`sh`、`wc`、`cut`、`rm`、`mv`、`chmod`，以及 `sha256sum`、`shasum`、`openssl` 三者之一。有 `gzip` 时才压缩；压缩传输在核对时需要同时放得下临时文件和解压后的文件。

## 在真机上验证过什么

2026-11-22 在一台 Jetson 真机上跑过一遍：经一级跳板机，直接调用 `upload()`，每一步之后用系统自带的 `ssh` 另行读取设备上的文件（名字、类型、权限、大小、SHA-256）来核对。越界路径和符号链接的拒绝、压缩与不压缩的正常传输、停止后再调用续传、连接被掐断后在同一次调用里续传、设备上的内容被改坏后拒绝收下（原有文件不动）、放弃传输、替换旧文件，结果都和测试替身上的一致；测试建的目录结束时删除。

那条链路上建立连接约 4 秒，一次 SFTP 请求往返约 240 ms，一次调用的固定开销约 8 秒：连传几个小文件时，时间主要花在这里。

没有在真机上测的：丢包（只在容器里用 `tc netem` 模拟过）、设备长时间不答复、磁盘满、没有 gzip 或校验工具的设备、经已保存的连接调用（`send_to_robot`）。「断过之后的块大小」那条规则是这次验证之后加的（真机上掐断后剩余部分明显变慢，由此发现），只在容器里按相近的往返时延比较过，没有回到真机上重测。

## 测试

```sh
PYTHONPATH=.:tests python -m unittest test_device_transfer test_device_transfer_limits
```

设备是测试替身 `tests/upload_fixture.py`：本机的 SSH 服务端，文件放在私有的临时目录里，登录口令每个实例随机生成。它只在这些条件都成立时才执行命令：命令行是 `sh -s --` 加参数，标准输入里的脚本和上面三段之一逐字节相同，每个参数符合那段脚本的要求，路径参数跟随链接之后仍在临时目录之内；执行时路径改到临时目录下，PATH 里只有测试允许的工具。可以注入的故障：收到若干字节后断开连接、不再接受连接、不答复写入、每次写入都答复得慢、拒绝写入（磁盘满）、存错一个字节、脚本执行完但不答复、不提供 SFTP、SFTP 不报告文件类型、登录脚本先打印一段文字、放不下解压后的文件。替身断开连接时先发出流结束再关闭：只关闭的话，客户端还有数据在路上时连接是被重置的，在 macOS 上偶尔客户端收不到这个重置，会一直等到自己的时限。对端无声消失的情况由「不答复写入」来模拟。`FlakyLink` 是一个每条连接传够若干字节就切断的中继。设置 `NX_UPLOAD_FIXTURE_BUSYBOX=/path/to/busybox` 时，替身的 shell 和全部工具换成 busybox。

覆盖：正常传完并核对；压缩与不压缩；中途断开后在同一次调用里续传、在以后的调用里续传；断开之后块从小到大恢复（压缩传输也一样）、设备答复得慢时保持小块、长回去之后变慢又缩小、每次新的断开重新从小块开始、没有断过时不调整；核对答复丢失后不重传；设备上的临时文件变短或消失；本地文件换了版本；设备不答复；连续断线的弱链路；停止、列出与放弃；校验不一致、压缩流损坏、放不下解压后的文件、磁盘满（包括一块中间的某一片被拒绝）、本地文件中途被改或被换掉；三种校验工具、没有 gzip、没有校验工具、没有 SFTP；越界路径、绝对路径、带 shell 特殊字符的名字、符号链接、敏感名称、不允许的目录和权限；检查之后目录、目标位置、临时文件被换成链接或目录；设备返回文字的清理；续传记录被改坏、不含登录信息；本机这一侧的读写失败；命令行在本机能找到的各种 shell 下读到的内容一致；替身拒绝执行别的命令和临时目录之外的路径；经已保存的连接调用。
