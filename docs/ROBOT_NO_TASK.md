# 添加机器人不需要任务，也不会顺带建任务（issue #56）

用户的要求：创建机器人，不需要创建关联任务；在创建任务的时候，绑定给机器人。

机器人属于账号（issue #42，见 [ROBOT_SCOPE](ROBOT_SCOPE.md)），任务在创建时选择用哪台机器人来做（同一文档的“创建任务时选择机器人”）。这次改的是剩下的两处：账号里还没有任务时，页面在添加机器人之前先弹出「你希望机器人完成什么工作？」；添加第一台仿真机器人时，后端自己建了一个“试用仿真机器人”任务。

## 现在的规则

| | 原来 | 现在 |
|---|---|---|
| 没有任务时点“通过 SSH 调查真机”“连接已在运行的机器人” | 先弹出新建任务的表单 | 直接打开各自的表单 |
| 没有任务时添加仿真机器人 | 后端自动建一个“试用仿真机器人”任务，页面跳进去 | 不建任务，页面留在「我的机器人」 |
| 没有任务时机器人卡片上的操作（实时状态、配置连接、硬件初始化、安装管理层、开机自启、本体配置、安全限位、删除、从云端安装技能等） | 先弹出新建任务的表单，或者点了没有反应 | 和有任务时一样 |
| 没有任务时「设置 → 助手模型」 | 先弹出新建任务的表单 | 可以打开和配置；这时配置的模型和机器人放在一起 |
| 任务从哪里来 | 人创建，或者添加仿真机器人时自动建 | 只由人创建；创建时在“用哪台机器人来做”里选机器人（可以选“之后再选”） |
| 仍然需要任务的事 | — | 任务自己的工作：工程任务（“提出工程需求”）、协作流程、助手工具、训练和仿真任务、模型、数据、场景等 |

新建任务表单标题下面的说明改成了“先描述目标，再选用哪台机器人来做。模型、测试与部署结果会保存在这个任务里；机器人属于账号，不随任务增减。”（原来写的是设备也保存在任务里）。

## 没有改的

- 创建任务时“用哪台机器人来做”仍然可以选“之后再选”，没有改成必选。账号里还没有机器人时也能先建任务。
- 已经存在的“试用仿真机器人”任务不动，卡片上仍然有“试用任务”标记；可以照常删除，机器人会留下。
- 有任务时的行为不变：打开某个任务时，助手模型仍然是这个任务自己的，调查机器人时用它。没有任务时配置的模型留在机器人那边，建了第一个任务以后，任务里要用模型需要在任务里再选一次（TokenFans 的默认模型每个任务都会自动带上，不受影响）。
- 直接调用平台代码、不经过服务端添加仿真机器人（单元测试是这样写的）仍然会建试用任务；应用自己不走这条路。

## 怎么实现的

后端：

- `brainos/sim_robots.py` 的 `add`、`brainos/sim_profiles.py` 的 `_task`：经服务端来的请求（机器人记在“家”里）在账号没有任务时不再建任务，回答里的 `project_id` 为空。
- `brainos/robot_scope.py`：`NO_TASK_ROUTES`（`engineering/models`、`engineering/models/use`、`engineering/models/cloud`）在请求没有带任务时按“家”处理；带了任务就是那个任务的，和原来一样。页面仍然不能直接点名“家”。

页面：

- `web/robot_no_task.js`：`robotNoTaskNeeded(type)` 判断一个操作是不是对机器人做的、不需要任务；`robotNoTaskNext` 决定添加仿真机器人之后页面留在哪个任务（服务端没有给出任务时留在原处）。
- 原来在没有任务时打开新建任务表单的四处改为先问它：`engineAction`（`web/engineering.js`）、`hardwareAction`（`web/hardware.js`）、`journeyAction`（`web/journey.js`）、`action`（`web/app.js`）。
- 给机器人卡片加功能的几个模块原来在没有任务时把操作让给下一层（结果是弹出新建任务表单）：`safety_limits.js`、`robot_remove.js`、`runtime_install.js`、`runtime_autostart.js`、`robot_body.js`、`ssh_edit.js`、`cloud_skills.js`，去掉了这个条件。
- `web/app.js` 的 `robotShared`：没有打开任务时，页面的各个列表就是“家”里的记录，包括助手模型。
- `web/sim.js`、`web/sim_profiles.js`：添加之后不再把服务端回答里的空任务号当成当前任务。

## 在哪里验证过，哪里没有

验证过的（没有真机）：

- `tests/test_robot_no_task.py`（13 项）：没有任务时经 HTTP 添加仿真机器人，机器人已连接、任务列表为空，再加一台也不建任务；没有任务的机器人可以读状态、停止、删除；之后创建任务时绑定这台机器人；没有任务时添加的助手模型记在“家”里，有任务时仍是任务的；任务自己的东西（训练任务）没有任务仍被拒绝；内置型号的仿真机器人同样不建任务。
- `tests/robot_no_task_logic.cjs`（82 项）：哪些操作不需要任务、哪些仍然需要；没有任务时页面各列表取“家”里的记录，有任务时和原来一样；四个处理函数先问再弹表单；除了任务自己的页面，没有哪个页面脚本再问“有没有打开任务”。
- `tests/robot_no_task_browser.cjs`（Chromium 和 WebKit）：新账号没有任务，三种添加方式各自打开自己的表单；按地址添加一台“真机”（真实的管理层加替身本体）并连接；添加并启动一台仿真机器人；全程任务列表为空，页面留在「我的机器人」；设置里的助手模型、机器人详情、「更多功能」里的删除都能用，删掉一台；最后在工作台创建任务并选剩下的那台，任务页显示这台机器人。同一个脚本在改动前的代码上第一步就失败（弹出的是新建任务表单）。
- 桌面端完整单元测试 2076 项全部通过，跳过 12 项；40 个页面逻辑脚本全部通过。
- 浏览器验收（Chromium）：运行器认识的 57 个脚本全部通过。其中四个原来依赖“加仿真机器人会自动建任务”，改成了自己建任务（`tests/robot_no_task_helper.cjs` 的 `openTask`）：`ux02_browser`、`ux03_browser`、`ux05_fix2_browser`、`cloud_skills_browser`。`account_browser` 运行器里没有它的配置，没有跑。
- 一次独立的代码审查：指出设备档案、运控驱动、接入管理层、调查四个模块仍在等任务（没有任务时按钮点了没有反应），已改并加进逻辑测试。

没有验证的：

- 真机上的任何一步；桌面应用窗口（WKWebView）里没有点过。
- 改了四个模块（设备档案、运控驱动、接入管理层、调查）的等待条件之后，没有在“没有任务”的状态下逐个点过它们的对话框；它们各自的浏览器脚本（有任务的情形）都通过。
- 旧版本留下的数据目录没有用新版本打开过；这次没有数据迁移。

## 已知限制

- 没有任务时配置的助手模型留在机器人那边，创建第一个任务之后在任务里看不到它（见“没有改的”）。
- 「提出工程需求」等任务自己的工作在没有任务时仍然先让人创建任务。
