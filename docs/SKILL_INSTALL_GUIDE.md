# 机器人没有连上时，怎么安装技能（issue #62）

更新：2026-11-27。对应 GitHub issue #62「机器人应用页面无法安装技能」：

> 机器人应用页面安装技能栏无法点击选择安装

> 状态：代码和测试完成；**没有在任何真机上运行过**，也还没有合并。验证范围见[最后一节](#在哪里验证过哪里没有)。

## 问题是什么

复现的情况（和报告时账号里的数据一致）：账号里没有任务，只有一台通过 SSH 接入的机器人，机器人上的管理层还没有接入（机器人的状态是“未连接”，心跳显示在线）。

1. 「机器人应用」是空的，页面让人点「使用机器人上已安装的技能」。
2. 对话框写“机器人上还没有安装技能”，给一个「安装技能」按钮。其实没有问过任何机器人：没有一台是连上的。
3. 点「安装技能」，对话框里每个技能的「安装到这台机器人」都是灰的，点不了。唯一的说明是每张卡片右上角的小字“无法判断（机器人未连接）”，没有下一步。

技能是装到机器人上的管理层里的，机器人没有连上就装不了，这条规则没有错。错的是页面把人带进了死路。

## 现在的页面

| | 原来 | 现在 |
|---|---|---|
| 「使用机器人上已安装的技能」，有机器人但一台都没连上 | “机器人上还没有安装技能” + 「安装技能」 | “没有已连接的机器人”，每台机器人一行：缺什么、点哪个按钮 |
| 「安装技能包」对话框，这台机器人没连上 | 一排灰按钮 | 技能上面一块说明：为什么装不了，带下一步的按钮；下面的技能照旧显示（仍然是灰的） |
| 「使用机器人上已安装的技能」里的「安装技能」打开哪台机器人 | 列表里的第一台，不管连没连上 | 已连接的那台；都没连上时才是最早添加的那台 |

说明里给哪个按钮，按机器人的情况：

| 机器人的情况 | 说明 | 按钮 |
|---|---|---|
| 只通过 SSH 接入，没有管理层的地址 | 这台机器人还没有接入管理层 | 「安装管理层」（issue #19 的安装）、「接入已有的管理层」（issue #17 的接入） |
| 有管理层的地址，但现在没连上 | 这台机器人现在没有连上 | 「重新连接」；通过 SSH 接入的还有「管理层设置」 |
| 仿真机器人没有在运行 | 这台仿真机器人现在没有在运行 | 「打开「我的机器人」」 |
| 没有任何接入方式 | 这台机器人还没有接入 | 「打开「我的机器人」」 |

- 「安装管理层」「接入已有的管理层」「管理层设置」打开的就是「我的机器人」卡片上同名功能的对话框，没有另写一套。装好并接入后机器人变成已连接，再打开安装技能的对话框，说明没有了，按钮可以点。
- 「重新连接」在对话框里原地做：成功后对话框接着往下走（安装技能的对话框重新读一遍，或者回到已安装技能的列表）；失败时把原因写在对话框里（对话框开着的时候，页面底部的提示会被挡住）。连接期间人已经去做别的事（换了对话框），成功后只提示一句，不会把别的对话框顶掉。
- 机器人已连接时，两个对话框和原来完全一样。

## 怎么实现的

- 新增 `web/skill_install_guide.js`、`web/skill_install_guide.css`，最后加载。
- 它包了一层 `simGalleryOpen`（`web/sim.js`，安装技能包的对话框）：对话框一打开，机器人没连上就在最上面插入说明（技能还在读取时就有，读取失败也留着）。从「我的机器人」里打开这个对话框也一样。
- 它包了一层 `action`：`ux-adopt`（`web/ux02.js`）在“有机器人、没有一台连上”时显示自己的内容，其余情况交回原来的；另外两个动作 `skillpkg-guide-connect`、`skillpkg-guide-robots`（`skillpkg-` 开头的动作不需要先有任务）。
- 改到共用文件的地方只有两处插入：`brainos/server.py`（静态文件）、`web/index.html`（一行）。服务端的规则和接口没有改动。

## 测试

- `node tests/skill_install_guide_logic.cjs`：不碰页面的函数（每种机器人的下一步、说明、没有机器人连上时的列表、「安装技能」打开哪台）。
- `python -m unittest tests.test_skill_install_guide`：两个文件能取到、页面只加载一次且在它包的脚本之后；上面的逻辑检查；被包的函数和写法还在。
- `node tests/skill_install_guide_browser.cjs <fixture-config.json> [截图目录]`，fixture 用 `tests/runtime_install_browser_fixture.py`（本机的 SSH 替身，不碰任何真机）。`BRAIN_BROWSER=webkit` 在 WebKit 上跑同样的检查。检查：没有任务的账号、两台只通过 SSH 接入的机器人；两个对话框的内容；320–1440 不横向滚动；键盘能到按钮；从说明里「安装管理层」装完后说明消失；「接入已有的管理层」打开接入表单；连不上的地址「重新连接」后原因写在对话框里；「打开「我的机器人」」。

## 在哪里验证过，哪里没有

见分支交付说明里的测试结果。没有验证的：

- 真机。这次没有改动任何发给设备的请求；真机上「安装管理层」「接入管理层」本身是 issue #19、#17 的功能。
- 打包后的桌面 app（WKWebView）：只在 Playwright 的 WebKit 上跑过。
- 「重新连接」成功的那条路只有代码，没有浏览器检查（测试替身里没有“有地址、先连不上、后来又能连上”的机器人）；失败的那条路检查过。

## 这一版没有做的

- 已连接、但读不出能力清单的机器人，技能卡片上仍然写“无法判断（机器人未连接）”，按钮仍然是灰的（这句话在这种情况下不准确；这次没有动）。
- 「我的机器人」卡片上的「安装技能」入口本身没有改：没连上的机器人点进去，看到的是同一块说明。
- 装好管理层之后不会自动回到安装技能的对话框，要再点一次。
