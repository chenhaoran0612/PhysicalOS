# 架构决策记录（ADR）

只追加。推翻旧决策时新增条目并引用被推翻的编号。

## ADR-001 · 2026-11-05 · 从"桌面端中心"转向"三层 + 契约"
- 背景：0.7.1 的全部能力集中在 Mac 桌面端；机器人端只有转发网关；注册与计费在本机 SQLite。
- 决策：拆为 `spec/`（契约）、`runtime/`（端侧 OS）、`cloud/`（商业平台）、`sdk/`（开发工具），桌面端成为控制台之一。
- 后果：桌面端通过 v1 兼容层继续工作；新层可独立部署和测试。

## ADR-002 · 2026-11-05 · 标准能力接口是跨本体的唯一机制
- 决策：技能/模型只依赖 `spec/` 定义的能力 ID 与字段；本体通过适配器实现能力子集；兼容性由单一函数 `check_compatibility` 判定。
- 备选：直接以 ROS 2 话题/动作作为标准 —— 否决：大量本体（厂商 SDK、单片机）不跑 ROS 2，且 ROS 接口无单位/限位语义；ROS 2 作为适配器之一桥接。
- 后果：需要持续维护能力表；厂商私有功能走 `x.` 命名空间。

## ADR-003 · 2026-11-05 · spec 与 runtime 仅用 Python 标准库
- 原因：端侧设备（Jetson、工控机）环境差异大，零依赖便于安装；云端可使用 FastAPI/SQLAlchemy。

## ADR-004 · 2026-11-05 · 计费沿用"预留 → 服务端计量结算"
- 决策：继承 `brainos/commerce.py` 的账本设计迁至云端：整数点数、余额只来自账本、调用前预留、凭服务端计量证据结算、结果不明保留待核对、绝不伪造支付成功。

## ADR-005 · 2026-11-05 · 多 Agent 按目录所有权并行开发
- 决策：总指挥写契约，各 Agent 只写自己的目录，交付必须含测试、模块 README 与进化记录；独立审查 Agent 不写产品代码。见 `docs/AGENT_COLLABORATION.md`。

## ADR-006 · 2026-11-05 · 两种付款路径：法币买点数，点数买模型
- 决策：token 套餐（点数）通过 PaymentProvider 用法币支付；模型授权直接从钱包扣点数；所有模型（含免费、按量计费模型的 0 点授权）调用或下载前必须先有授权（Entitlement）。
- 原因：支付渠道只需对接一种商品（点数），模型定价和促销在平台内部完成；授权记录统一了"谁能用哪个模型"的判断。

## ADR-007 · 2026-11-05 · 预留按最坏情况上界，超额转人工核对
- 决策：网关预留 = max_tokens + 输入字节数 + 每条消息 64；上游报告用量超出预留时不自动扣费，标记待核对。
- 原因：保证"预留先于调用"的上限真实有效，避免用户被意外超额扣费。

## ADR-008 · 2026-11-05 · 平台运营员与组织操作员分离
- 决策：组织角色 `operator` 是现场操作员；平台运营员仅能由服务端环境变量或管理命令授予，用户不能自升权限。

## ADR-009 · 2026-11-05 · 急停锁存，需显式授权解除
- 决策：任何停止请求都会锁存急停；之后所有运动类调用被拒绝，直到带现场授权调用 `/v2/reset`。
- 原因：防止停止后被排队中的旧指令或自动重试重新带动机器人。

## ADR-010 · 2026-11-05 · 技能运行在运行时进程内，本轮不做沙箱
- 决策：技能是机器人所有者自己安装的可信代码；不响应停止的技能 2 秒后被收回能力调用权限。
- 后果：第三方技能市场上线前必须引入进程级隔离（列入路线图）。

## ADR-011 · 2026-11-05 · 现场证据"失败即关闭"
- 决策：设备的现场测试结果只有明确声明 `evidence_kind: "device_run"`、且本体与结果都未标注仿真、证据引用不以 `simulation://` 开头时，才算现场证据；缺少 `evidence_kind` 一律按仿真处理。
- 代价：旧的自定义适配器必须补上该字段才能发布。目前没有已部署的真机，代价可接受。
- 来源：审查 R-08；桌面修复 Agent 提出、总指挥确认。

## ADR-012 · 2026-11-05 · 超额用量按预留上限扣费（部分推翻 ADR-007）
- 背景：审查 C-02 证明"超额不自动扣费"可被利用——通过透传参数让上游产出远超预算的用量，实测预算 1000 token 用掉 45070、扣费 0。
- 决策：预留仍为最坏情况上界；上游报告用量超过某次调用的预留时，按预留上限扣费、不返回输出、超出部分记为待处理超额；会话因此锁定，只能关闭。超出预留的部分只能由运营员人工处理（免除或扣费，扣费不超过记录的超额与可用余额）。平台永远不在没有人工步骤的情况下扣超过预留的费用。
- 配套：会话参数白名单、`n=1`、服务端强制输出上限，使超额在正常情况下不会发生。

## ADR-013 · 2026-11-05 · 消费与运营资格以邮箱验证为前提
- 背景：审查 C-01，白名单邮箱可被抢注成为平台运营员。
- 决策：未验证邮箱可注册、浏览，不能购买或调用网关；平台运营员须"已验证邮箱 + 命令授予（生产）"。

## ADR-014 · 2026-11-05 · 账户所有权以"本人会话 + 邮箱令牌"共同证明
- 背景：复审 N-01，攻击者预注册他人邮箱后，主人点无需登录的验证链接，验证的却是攻击者账户。
- 决策：验证必须在账户本人的登录会话中完成；被未验证账户占用的邮箱可由收件人通过认领令牌夺回，占用账户随之停用；平台运营员在生产环境只由服务器命令 `create-operator` 创建。

## ADR-015 · 2026-11-05 · 停车通道与普通指令解耦、限值启动即冻结
- 背景：复审 N-02/N-03/N-04。
- 决策：停止代数在请求到达时捕获、reset 也推进代数；看门狗与停止不等待普通指令持有的锁；安全监督器的限值在启动时深拷贝冻结，运行中清单变化即停车并拒绝运动直到重启。

## ADR-016 · 2026-11-08 · 网关会话串行化（N-05）
- 决策：同一会话同一时刻至多一个在途调用（含流式，结算完成才算结束）；并发调用返回 409 `session_busy`。
- 理由：超额锁定只拦"之后"的调用；串行化保证每个会话最多一次调用可能超出其 hold，与客户端并发度无关；"每调用单独预留"只能保总预算，仍允许 N 次并发各超一次。工程助手调用天然串行；需要并行可开多个会话。
- 关于"结果不明"：非流式保留整笔预留待核对，流式中断把本次 hold 计入会话用量待核对——两者都在核对前占用预算、都不向用户追加扣费，语义一致，保持现状。

## ADR-017 · 2026-11-08 · 技能默认进程隔离（取代 ADR-010）
- 决策：技能默认在独立子进程运行（最小环境、降权用户、NO_NEW_PRIVS、rlimit + cgroup pids、只读包副本、父进程退出即终止），所有能力调用经管道代理回主进程的能力总线与安全监督；违反协议即杀进程且适配器零调用。`inprocess` 仅调试用、显式开启且状态可见。
- 剩余信任边界：网络未隔离、无 seccomp——对可经网络/DDS/串口直接驱动的本体，恶意技能仍可绕过运行时。第三方技能市场上线前必须补上网络隔离（列入第 05 轮）。
- 生产部署：运行时以 root 启动让技能降权到独立用户，或配置专用 `--sandbox-user`。

## ADR-018 · 2026-11-08 · 第三方技能上线闸门扩大为"网络 + 文件系统 + uid 隔离"
- 背景：第 02 轮复审以真实恶意技能实证：运行时、安全监督、停止路径与机密均未被突破；但并发技能共用降权用户时可互相读写工作区（Q2R-01，P2）。
- 决策：0.9.0 只面向第一方/可信技能发布。第三方技能市场上线前必须同时具备：每次运行独立 uid、mount/文件系统隔离（私有 /tmp）、网络命名空间或防火墙。列入第 05 轮。

## ADR-019 · 2026-11-09 · 一致性测试的安全规则：测试本身绝不能成为危险源
- 背景：第 04 轮审查证明一致性套件会清除操作员急停后继续运动（Q4-01，P0）、dry 级会让机械臂移动 0.9 rad（Q4-02，P0）、并在多种"会撒谎的适配器"面前判通过。
- 决策：
  1. 套件只解除自己发出且来源完全匹配的锁存；任何外部停止立即中止全部后续用例并保持锁存，绝不复位。
  2. dry 级向适配器发出的任何运动类调用必须可证明零位移（按名称匹配，不一致即 blocked 不发送）。
  3. 任何用例异常、超时或状态不确定 → 立即停车、保持锁存、中止。
  4. 倍速仅对运行时内置的受信任仿真适配器生效；所有 motion 目标受绝对上限约束（与适配器自报值无关）。
  5. motion 验证方向与幅度，取消/停止后持续观察静止；测试结束必须验证静止。
  6. 一致性报告由适配器同进程产生，属自报，可被恶意适配器篡改：只用于"可用性提示"，永不作为发布或现场证据（ADR-011 不变）。
