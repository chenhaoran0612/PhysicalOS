### 2.2 预防性停止的其他问题（无退化）

| 问题 | 结论（数字） |
|---|---|
| `stop()` 幂等：仿真四足 | `stop()` 只把指令清零、终止当前目标，重复调用无副作用 |
| 仿真机械臂 | 同上（关节速度清零、终止目标）；关节通道没有游走容许，预防性停止**不作用于关节**（`sit*` 场景预防 0 次，`attack_sit` 的 `stop()` 调用次数与 v0.13.0 逐项相同） |
| ROS 2 适配器 | `stop_adapter()`：发零速 Twist + 取消已知目标 + 异步 Nav2 cancel-all，每步都执行、可重复；游走 1 mm/√s 的静止本体上约 0.19 次/s（8 h 4982–5657 次），即每约 5 s 一条零速 Twist 与一次 CancelGoal 异步调用。v0.13.0 同情形 5006–5656 次再停，频度相当 |
| 脚手架生成的适配器 | 与 ROS 2 相同的写法（零速 + 取消），重复调用安全 |
| 受控坐下 | 预防性停止在刹停宽限（`settle_s`/`stop_settle_s`）内不触发；关节不受影响；见上 |
| 复位起立 | 复位执行期间（`reset_in_flight`）不触发预防性停止。代码阅读：守护在检查“复位进行中”与调用 `latched_restop()` 之间存在毫秒级窗口，落在窗口内会让该次复位失败并给出 `latch_guard_reset_grace` 文案——与 v0.13.0 的计数再停同一窗口，频度相当，未复现，不单列 |
| 被说谎驱动利用 | 见 §2.1（能多走）。另一方向：驱动无法区分预防性停止与计数再停（同一 `stop()` 调用），所以不能“只对预防性停止不服从” |

### 2.6 `reset_expected_s` / `expire_s`（`pexp.py`、`expire.py`、端到端 §4）

| 检查 | 结论 |
|---|---|
| spec 校验 | 0、-1、30.0001、31、NaN、inf、`True`、`"5"`、`null`、`[5]` → 拒绝（清单无效）；1e-9、0.5、7、25、30 接受 |
| 运行时（建议性读取） | 非法值忽略并给注释，>30 夹到 30（spec 已先拒绝，正常不会到这里） |
| 桌面 `expire_s` | 未声明/非法/bool/字符串/NaN → 8；1、3 → 8；7 → 12；20 → 25；25–31 → 30；HTTP 超时恒为 `expire_s + 4`（12/16/29/34），**始终 ≥ expire_s** |
| `capabilities.reset_expire` | 仅 `=== true` 时承诺作废；缺失、`"true"` 字符串、状态非对象 → 不承诺 |
| 运行时 `expire_s` | 0.001 夹到 1 s（1.5 s 返回 → 409 `reset_expired`，锁存且落盘）；省略 → 默认 30 s |
| 余量 | `reset_expected_s` 26–30 时 `expire_s` 被夹到 30，余量 4–0 s → Q7c-07（P3）：建议 spec 上限 25，或运行时/桌面对 >25 给出警告 |

### 2.7 float/int 数值相等（`pnum.py`，25 例全部符合预期）

- 接受：float 选项 `[0.5, 1.0]` 传 `1`（技能收到 `1.0`）；`[0.5, 1]` 传 `1.0`；vector `[[1.0,2.0]]` 传 `[1,2]`；pose 选项含整数四元数；float 默认值 `1` 配选项 `[1.0]`。
- 仍拒绝：float 传 `True`、`"1"`、`1.0000001`、`10**400`；float 选项 `[True, 1.0]` 传 `True`；int 选项 `[1,2]` 传 `1.0`/`True`；int `min/max` 传 `1.0`；enum `[1.0, 2.5]` 传 `1`、`[1,2]` 传 `1.0`/`True`、`["1"]` 传 `1`；bool 传 `1`/`1.0`；str `["1"]` 传 `1`；vector 元素 `True`；object `{"a":1.0}` 传 `{"a":1}`；int 默认 `1.0` 安装即拒。
- 结论：只放宽了声明为实数的类型，bool/str/int/enum/object 的严格性没有被绕过。
