# 界面样式：下拉框、悬停与可读的展示内容（issue #7）

更新：2026-11-13。对应 GitHub issue #7「样式优化」。

三条要求和做法：

| 要求 | 做法 | 文件 |
| --- | --- | --- |
| 下拉框和整体风格一致 | 每个 `<select>` 自动换成控制台自己的下拉框 | `web/dropdown.js`、`web/dropdown.css` |
| 悬停颜色不突兀 | 每种按钮有自己同色系的悬停、按下和禁用状态，变化渐入 | `web/hover.css` |
| 运行中不展示代码和 JSON | 数据显示成“名称—值”的行；命令、原始输出、文件内容折叠在“展开查看…”里 | `web/readable.js`、`web/readable_dom.js`、`web/readable.css` |

这些文件都是新增的，在 `web/index.html` 末尾加载（晚于 `style.css`），`brainos/server.py` 只多了一行静态文件表。各页面的渲染代码没有改动：下拉框和可读展示都是在页面渲染完成后接手的，所以其他分支对页面的修改不会和这里冲突，新写的页面也自动生效。

## 下拉框

- 原生 `<select>` 仍在表单里，只是视觉上隐藏：表单提交、`required` 校验、页面已有的 `change` 监听、测试脚本的 `selectOption` 都照常工作。页面用代码设置 `select.value` 时，下拉框同步显示。
- 下拉框是一个按钮（`role="combobox"`），展开的列表固定定位，在对话框里也不会被裁切，空间不够时向上展开。
- 键盘：↑/↓ 打开并移动，Enter/空格 选择，Home/End，输入首字母跳转，Esc 只关闭列表（不关闭对话框），Tab 离开。
- 多选（`multiple`）的列表选择后不关闭，按钮上显示“甲、乙”。
- 必填项为空时显示“请选择一项”，并把焦点放到这个下拉框上。
- 个别地方要保留原生控件时，在 `<select>` 上加 `data-native`。

## 悬停

`style.css` 原来只有一条 `.button:hover`（深绿），其他按钮没有自己的悬停：

- 链接样式的按钮（如“查看完整流程”）悬停时变成深绿色块，文字几乎看不见；
- 禁用的按钮悬停时也会变色；
- 危险、描边、首页大卡片、急停横幅里的按钮悬停时完全没有反馈。

`hover.css` 给每种按钮一个同色系、变化幅度小的悬停和按下颜色，禁用按钮保持静止色；图标按钮、标签页、对话框关闭、可展开标题等原来没有反馈的地方也补上了柔和的悬停。颜色变化 0.16 秒渐入；系统开启“减少动态效果”时没有过渡。

## 不展示代码和 JSON

规则：**界面默认不出现代码**。机器数据要转换成人能读的样子；必须保留原文的内容（实际执行的命令、设备原始输出、生成的文件），放进“展开查看…”里，摘要写明里面是什么、有几行，用户一点就能看到完整原文。

转换方式（`web/readable.js`，纯函数，不依赖页面）：

- JSON（含被截断的 JSON、Python 风格的字典）→ “名称—值”的行。字段名换成中文（`exit_code` → 退出码，未收录的字段名转成可读的词），`true/false` → 是/否，空值 → —，时间 → 本地时间，短列表 → 标签，长列表只显示前几项并注明“还有 N 项”，嵌套超过三层只写“N 个字段”。
- 带类型的记录（如工程助手的 `commandExecution`、`fileChange`）→ 标题行“执行命令 · 已完成”，其中的命令、改动内容、输出折叠。
- 字段名本身是代码的值（`command`、`stdout`、`diff`、`content`……）一律折叠。
- Python 报错堆栈 → 只显示最后的错误信息，堆栈折叠。
- 文字里的 Markdown（标题、列表、表格、粗体）→ 排好版的文字；其中的 ``` 代码块折叠。

应用范围（`web/readable_dom.js`，页面渲染后自动处理）：

- 页面上所有 `<pre>`（包括各页面 `json()` 生成的 `.json-view`、命令、原始输出、文件预览）；
- 整段文字就是 JSON / 报错堆栈 / 带代码块的元素；
- 工程助手会话记录和任务日志（`.log-item > p`）：标为“命令”“命令输出”“文件修改”的条目一律折叠，助手回复里的 Markdown 排版；
- `<dt>` 里直接打印的字段名（如适配报告的 `evidence_kind`）换成中文名称；
- `<code>` 和 `.mono` 改用正文字体，看起来是普通词语而不是代码。

用户展开过的折叠，在页面轮询刷新后保持展开（按折叠所在的位置记忆，不按内容；实时输出每次刷新内容都在变）。确实需要原样显示代码的元素，加 `data-keep-code`。

**审批是例外。** 要用户批准的内容（修改设备的命令、调查时的 SSH 命令）必须不用点击就能看全：审批表单（`form[data-form="engine-approval"]`）里的折叠默认展开，仍然可以收起，数据照样显示成“名称—值”的行；对话修复里的审批卡片用 `data-keep-code` 保持原样。这与 [HARDWARE_INIT.md](HARDWARE_INIT.md) 的“审批框完整展开命令”一致，由 `tests/style_browser.cjs` 的 `approvalsShowTheCommand` 检查。

没有改动的地方：

- 输入框里的 JSON（任务的“高级配置”、参数的“直接编辑 JSON”等）是用户自己填写的内容，保持原样。
- 启动失败页（`boot.js`）的错误原文，用来截图发给开发人员，保持原样。
- 复位说明里需要用户自己执行的一条命令（`ux04.js`，`sudo systemctl restart neuxmind-runtime`）仍然显示，只是不再用代码字体。
- 后端拼进句子里的 JSON 片段（例如能力参数说明中的 `[0.1, 0.5]`）：整段不是 JSON，不做转换。

## 测试

- `node tests/readable_logic.cjs`：转换规则（截断 JSON、Python 字典、分类、标签、转义、折叠、Markdown、报错堆栈）。
- `node tests/style_browser.cjs <fixture-config.json> [截图目录]`，fixture 用 `tests/ux01_browser_fixture.py`（服务需要 `NEUXMIND_MAIL_DEV_ECHO=1`）。加 `STYLE_BROWSER=webkit` 在 WebKit（桌面应用 WKWebView 的内核）上跑同样的检查；需要与所用 Playwright 版本匹配的 WebKit。覆盖：下拉框（鼠标、键盘、Esc 不关对话框、点击后焦点不在按钮上时——Safari 的行为——键盘仍然有效、代码赋值同步、必填校验、多选）；9 种按钮在悬停时文字对比度 ≥ 3、颜色变化不过大、有可见反馈、禁用不变化；用页面自己的 `json()`、`hwCommand()` 和会话记录渲染时屏幕上没有代码，折叠能展开出原文、刷新后保持展开，实时输出变长时也保持展开；15 个页面没有可见的代码。
- 已有的浏览器脚本中读取 `#dialog pre` 原文的 6 处改为先展开折叠再读（adaptation、cloud03、discovery、engineering、workflows），planner 的状态文字只匹配可见的那一个（折叠的技术记录里也会出现同样的状态）。
