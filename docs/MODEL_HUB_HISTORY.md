# 候选版本从历史中选（issue #76）

issue：「训练的模型文件不是必须上传。模型文件可以通过点击选择历史中的模型文件。」

一轮改进（[MODEL_HUB.md](MODEL_HUB.md) 规则 6）走到「训练」这一步，原来只能「上传新模型文件」。现在旁边多了「从历史中选择」：点开是一个对话框，点一行，它就成为这一轮的候选版本，不用上传。

## 用户定的事（2026-11-28，本 issue 的会话里）

| 问题 | 决定 |
|---|---|
| 「历史中的模型文件」是哪里的文件 | 两样都列：这个模型在应用里的历史版本；小黄鸭的模型再列训练项目留下、有评估成绩的模型文件 |

## 对话框里有什么

**这个模型的版本**：这个模型的全部版本，这一轮的起点除外——以前上传过的、上一轮没采纳的候选、随应用带来的模型包。每一行写明它从哪里来（当前版本、第几轮的候选、随应用带来）、训练出处、文件。它在这一轮的评测集上已经有评测的，评测的指标跟着显示，点它就直接用这次评测：这一轮直接到「决定」。

**训练项目里的模型文件**（只有小黄鸭的技能模型有）：训练看板（这台电脑上的 `127.0.0.1:8767`，`NEUXMIND_DUCK_DASHBOARD` 可改）评估过的每一次更新：第几轮第几次更新、训练步数、CPU/GPU、评估时间、固定起姿组上通过几个。从新到旧，先列 20 个，「再显示」每次多 20 个；「只看全部通过的」只留 10/10 的。和这一轮起点同一轮次、同一次更新的那个不能选；已经是这个模型一个版本的，点它就是那个版本。

底部仍然可以「上传新模型文件」。「评测候选」和「决定」两步里的「换一个候选版本」也打开这个对话框。

## 规则

1. **选一个已有的版本不复制任何东西。** 这一轮记下这个版本是候选；它在这一轮的评测集上最近一次完成的评测就是候选的评测（和开始一轮时找基线的做法一样）。没有，就到「评测候选」这一步。
2. **训练项目的文件按看板记下的 SHA-256 取。** 看板的数据里每次评估都带着它的模型文件地址和校验值（`checkpoint_url`）。选中时从看板取这个文件，校验值对上才保存（和上传的文件一样按内容存在工作区的 `model-hub/files/` 下），成为这个模型的一个新版本：版本名「第 R 轮 · 第 U 次更新」，训练出处是轮次、更新次数、步数和设备，说明「从训练项目的历史里选的模型文件」。对不上就不保存，对话框里说明。
3. **成绩跟着文件来。** 看板对这次更新的评估（固定起姿组上通过几个）记在这个版本上。这一版的「取训练项目的评估」先在训练进度里找，找不到就用这份记下的成绩，所以随应用带来的训练进度副本里没有的新轮次也能比较。不是在固定起姿组上评估的，不记成绩。
4. **只问这台电脑上的看板。** 地址只能是 `127.0.0.1` 或 `localhost` 的 http，不走代理，不跟随跳转。文件最多 256 MB。
5. **看板的数据很大，读得省。** 2026-11-28 它的 `/api/evolution` 有 151 MB（gzip 34 MB）。这里要 gzip，解析时只留用到的字段，一次只读一份，读到的列表记一分钟（没读到的只记 5 秒）。读一次约 3.5 秒，峰值内存约 540 MB。对话框先显示版本，看板的列表读到了再补上。
6. 看板没开时，这一部分写明原因，版本和上传照常可用。
7. **一次只选一个。** 选择进行中所有行都不能点，对话框因为看板的列表晚到而重画也一样；取来的文件没有成为版本（这一轮在此期间被放弃、或同时有人选了同一个文件）就立刻删掉，不等一天后的清理。

## 接口

| 路由 | 做什么 |
|---|---|
| `model-hub/rounds/history` | `round_id` → 这一轮可以选的版本 |
| `model-hub/rounds/history/training` | `round_id` → 训练项目里的模型文件（小黄鸭的模型） |
| `model-hub/rounds/candidate` | `round_id` 加 `version_id` 或 `training_key`（`轮次-更新次数`）→ 成为候选，返回这一轮 |

一轮要在「训练」「评测候选」「决定」三步之一才能选候选（`hub_round_state`）。新的错误码：`hub_candidate_start`（选了起点）、`hub_history_unknown`（看板里没有这个文件，或者不是小黄鸭的模型）、`hub_history_unavailable`（看板没回答，或文件太大）、`hub_history_mismatch`（取到的内容和校验值不一致）。

## 代码在哪里

| 文件 | 做什么 |
|---|---|

| `brainos/model_hub_files.py` | `adopt`：不是上传来的文件也按内容保存 |
| `brainos/model_hub.py` | `self.history`；`import_training` 找不到训练进度时用版本上记下的成绩 |
| `web/model_hub_history.js` / `.css` | 对话框（纯函数在前，接线在后；包住 `hubAction`） |
| `web/model_hub.js` | 「训练」一步的两个按钮，「换一个候选版本」打开对话框 |

## 测试

```sh
python -m unittest tests.test_model_hub_history      # 20 项：两种历史、校验、看板不在、只读一次、白取的文件不留
node tests/model_hub_history_logic.cjs                 # 对话框和步骤的页面逻辑，26 项
python tests/model_hub_history_fixture.py INFO.json &  node tests/model_hub_history_browser.cjs INFO.json SHOTS
```

单元测试和浏览器验收都用一个编出来的看板（本机端口，gzip，一个文件故意给错内容，两个文件晚 1.5 秒给）。浏览器验收：「训练」一步的两个按钮、对话框分页和筛选、错的文件被拒绝且提示在视线内、好的文件成为候选并取到看板的成绩、取文件期间对话框重画也不丢正在进行的选择和提示、换候选时两边都标出当前候选、下一轮选上一轮没采纳的候选直接到「决定」、375/768 宽不溢出。

## 没有做的

- 上传的或从训练项目取来的模型文件在这台电脑的仿真里评测（[MODEL_HUB.md](MODEL_HUB.md) 规则 3 不变：只有随应用带来的模型包运行）。
- 模型页上「把一个历史版本设为当前版本」：issue 说的是这一轮的候选，没有做。
- 训练看板以外的历史（其他分类的训练项目）：现在只有小黄鸭有训练项目。
