# 技能包按品牌型号归属：「安装技能包」只列出这台机器人能装的（issue #69）

「安装技能包」原来把随应用带的技能包全部列出来，再逐个标「适用」或「这台机器人不能用」。一台 Microduck AD-P102 打开它，六个里有五个是不能用的。现在每个技能包写明自己属于哪些品牌型号，或者是通用的；对话框只列出这台机器人的品牌型号的技能包，加上通用的。

> 状态：代码和测试完成；**没有在任何真机上运行过**。验证范围见[最后一节](#在哪里验证过哪里没有)。

用户在 issue 里写的三条，和在 issue 会话里选的一条（2026-11-27）：

1. 只展示本产品可以安装的技能包。
2. 状态类的技能包是通用的，所有机器人都可以安装。
3. 技能包只绑定品牌型号，不区分仿真和真机。
4. 归属怎么定：**包上写明品牌型号**（没有选“按能力自动判断”）。

## 规则

- 随应用带的每个技能包，在归属表里要么是**通用**（`generic`），要么列出一个或几个**品牌型号**。两样都写或都没写的条目无效。
- 一台机器人的列表 = 属于它品牌型号的技能包 + 通用技能包。品牌型号怎样算相同，沿用 issue #48 的规则（`robot_model.key`：不分大小写，已知品牌和型号的别的写法算同一个）。
- **只看品牌和型号**：同品牌同型号的仿真机器人和真机，列表完全一样。
- 没有填写品牌型号的机器人只看到通用技能包，对话框里写明原因。
- 归属表里没有的技能包不给任何机器人（有测试保证随应用带的每个包都在表里）。归属表缺失或读不了时，一个都不列。
- 不只是不显示：对一台别的品牌型号的机器人预检或安装这样的包会被拒绝（`skill_other_model`；机器人没有品牌型号时是 `robot_model_missing`），在读取机器人、发送任何东西之前。
- 列出来的技能包照旧做能力检查：机器人没连上、或者缺某项能力时，卡片照旧说明原因，按钮是灰的。
- 对话框的小标题一行里写着「另有 N 个技能包属于别的品牌型号，没有列出」。

## 现在的归属

| 技能包 | 属于 |
|---|---|
| 状态报告 `status_report` | 通用 |
| 巡逻 `patrol` | NeuxMind 示例 通用四足 |
| 挥手 `wave` | NeuxMind 示例 通用六轴机械臂 |
| 去指定地点 `goto_place`、巡检 `patrol_places`、无图自由走 `free_walk` | 智身科技 钢镚 L2-U；NeuxMind 示例 通用四足 |

两点说明：

- 内置的两台示例仿真机器人，设备自己上报的写法是 `neuxmind-sim` / `sim-quadruped`、`sim-arm-6dof`，表里两种写法都列了。
- 去指定地点、巡检、无图自由走是为钢镚 L2-U 写的（issue #38）。内置的仿真四足当时特意声明了这两项能力，用来不接真机就能试这三个技能，[PLACE_SKILLS.md](PLACE_SKILLS.md) 的“仿真（现在就能试）”和一批测试都靠它，所以表里也列了它。不想让示例四足看到这三个包，删掉表里对应的两行即可。

按这张表，Microduck AD-P102、宇树 Go2 等其他品牌型号现在只看到「状态报告」。给某个品牌型号加技能包：把包放进 `runtime/examples/skills/`，在归属表里加一条。

## 没有改的地方

- **从文件夹安装（高级）**：用户自己选的文件夹没有归属，照旧只做能力检查。
- **云端技能**（技能发布 / 技能加载）：一个版本属于一个品牌型号，是 issue #48 做的，没有动。把示例技能发布到云端时照旧由用户选品牌型号，不读这张表。
- 技能包的内容和摘要：归属表放在技能包**旁边**，不在包里，所以每个包的摘要不变，已经发布到云端的同内容版本不受影响。
- 已经装在机器人上的技能：不会因为这次改动被卸载或禁用。

## 代码在哪里

| 位置 | 内容 |
|---|---|
| `runtime/examples/skills/products.json` | 归属表（`skill.products.v1`） |
| `brainos/skill_products.py` | 读表、判断（`table`、`offered`、`scope`、`view`、`check`） |
| `brainos/sim_robots.py` `gallery` | 带 `robot_id` 时只列这台机器人能装的；返回多了 `left_out`（没列出的个数）、`product`（机器人的品牌型号）、每项的 `scope` |
| `brainos/skill_packages.py` | 预检、安装带 `example` 时先核对归属 |
| `web/sim.js` | 对话框标题写品牌型号，卡片上的「通用」「适用：…」标签，没列出的个数 |

接口 `POST /api/skills/examples` 不带 `robot_id` 时照旧列出全部（`left_out` 为 0）。

## 在哪里验证过，哪里没有

- 单元测试 `tests/test_skill_products.py`：归属表完整、通用包给所有机器人、别的写法算同一品牌型号、没有品牌型号只给通用包、表损坏时不列；用真的仿真运行时（内置四足和机械臂）验证列表、拒绝和安装。
- 浏览器 `tests/ux01_browser.cjs`：四足的列表里没有「挥手」，「状态报告」标着通用，有「另有 1 个…」一行；机械臂的列表里没有「巡逻」。
- **没有验证**：真机；钢镚 L2-U、Microduck 的仿真机器人（它们的模型不在公开仓库里，只在打好的安装包里有），这两种的列表是按表和规则推出来的，由 `test_skill_products.py` 里不启动机器人的用例覆盖。
