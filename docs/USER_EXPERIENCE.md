# 用户目的与使用路径

更新：2026-10-15，0.5.1。产品设计以用户的机器人工作目标为起点，不以底层技术模块为起点。

## 用户为什么使用这个系统

用户拿到机器人，希望它完成一项具体工作。平台帮助用户了解设备、补齐能力、验证效果、部署并持续运行。模型、训练、仿真、Agent、算力与工具都服务于这个目标，不应成为使用前必须逐个理解和配置的清单。

主路径：描述工作 → 连接机器人 → 准备能力 → 验证效果 → 部署使用。

- 描述工作：在哪里做什么，怎样算完成。保存为任务项目。
- 连接机器人：用户提供可用连接信息，助手调查设备并保存档案。已有兼容接入程序可直接连接。
- 准备能力：优先使用已有模型、技能和设备能力；需要时让助手开发接入程序与测试。训练解决现有模型效果不足的问题。
- 验证效果：按需仿真，检查应用配置，进行有真实记录的现场测试。
- 部署使用：发布匹配版本的应用，用户发起工作或停止请求，查看设备反馈并改进。

## 已落地的交互规则

1. 首页优先展示下一步，不以空统计卡片占据主要位置。首次使用先写工作目标；注册后回到该步骤。每个功能页面说明用途、需要准备的内容和产出。
2. 任务目标沿用到助手准备计划，常见四阶段流程不要求用户先搭建角色编排；查看计划和授权调用后才执行。自定义角色、模型、扩展仍可从协作流程进入。
3. 左侧导航按主路径、模型与数据、工具与账户组织。工程术语放在对应的详细设置和开发接口，主入口使用用户能理解的工作名称。
4. 训练、选模型和仿真是按任务需要组合的能力，不作为所有机器人都必须经历的步骤。点击训练或仿真平台资源入口时保留对应分类，模型来源分类可实际筛选。
5. 进度来自当前机器人和应用版本的记录；不以另一个应用、旧本体版本、旧测试报告、仅生成代码或仿真通过代替当前现场验证。最近一次失败记录覆盖之前成功记录的进度提示。
6. 发布与运行分开说明。应用已发布不表示已开始工作，启动请求被接收不表示任务已完成。
7. 缺少真实服务时说明用户目前可做什么。平台目录为空、支付未开通、USB/串口连接插件尚缺等都直接说明，不展示伪造可用资源。
8. 左侧头尾与右侧顶栏保持固定，仅各自内容区滚动。

## 仍需继续完成的体验

这轮是使用路径与入口收敛，不代表所有深层表单已经达到最终产品体验。训练/仿真执行器的专用配置仍依赖服务契约，部分工程表单仍需技术人员；后续应结合真实执行器能力生成结构化表单与可复用配方。工程产物到设备端安装、技能注册和发布仍需要完整接入链路，不能将助手完成的工程流程标成机器人已经上岗。

## 0.6.0：训练与仿真任务的具体操作

训练、仿真、外部测试与远程工程任务统一为三步：选择执行服务/方案 → 填写服务支持的参数 → 确认任务与预算。项目目标可自动带入；数据、模型、机器人应用和场景从当前项目选择。服务提供默认参数，用户只在需要时展开高级设置。

确认页列出实际参数、最长运行时间和平台预留点数；查看确认页不执行、不占用额度。返回修改保留所填内容。用户确认后创建任务并发送执行请求；结果页优先展示状态解释、返回产物、基础指标、日志及实际结算，完整技术记录折叠保留。

空服务目录、未检查的服务、缺少必需资产、服务尚未声明简化方案分别给出原因与可用入口。不把通用 JSON 隐藏后假称已经支持任意训练器。配方规范见 JOB_RECIPES.md；训练和仿真仍需真实执行服务提供能力。

## 0.6.1：训练完成后，如何真正使用结果

成功训练的结果页提供“保存到模型库”。用户只需填写名称和用途；平台保留检查点地址、来源任务、执行时的数据等资产快照、参数摘要和保存时指标。同一任务、同一检查点重复保存返回已有资产。保存后状态明确为“训练产物 · 待配置”，不是已经可以调用或安装的模型。

模型详情解释下一步：如需调用，先让推理服务加载产物，选择已连接服务并填写它实际识别的模型引用与输入输出要求；生成独立的调用配置，保留原训练记录。随后可直接进行调用测试，再用于应用。平台登记配置不会替服务加载权重，也不会自动证明模型效果。端侧安装仍需明确的兼容模型包，训练检查点不自动转成部署包。

仿真或外部测试完成后提供“检查应用与现场测试”和“继续改进方案”入口，不将远程任务成功当成现场验收通过。保存后的强制刷新会等待正在进行的读取完成，再读取最新记录，避免后台轮询导致新资产暂不显示。

## 0.6.2：围绕一个应用完成验证和交付

机器人应用保存后进入“应用交付清单”。顶部固定说明目标机器人、应用版本、当前阶段和下一步；下方按工作步骤展示完成条件、停止条件及超时，技术参数折叠。缺少机器人或技能时先给准备入口，不打开无法完成的创建表单。

清单通过 applications/readiness 读取当前配置、匹配的最新现场报告、发布记录和设备请求；打开清单不检查网络、不新增报告、不执行设备。用户点击配置检查才保存静态报告，现场测试和启动仍需勾选现场授权。发布前展示设备、应用版本和现场报告，发布完成后单独启动。

现场失败优先提示查看失败报告和修复问题，不能以“请求已完成”掩盖“测试未通过”。较新的现场测试失败或结果未知会使旧通过报告失去发布/启动资格；后端同样校验，不能仅靠前端隐藏按钮。停止请求不受此条件阻断。首页、应用、验证和部署入口都可回到同一应用清单。

当前清单依据平台已有记录，不替代现场实时遥测。状态未知的请求需到设备端核对，本轮没有新增通用远程对账接口。技能仍需要真实设备实现，步骤参数仍由技能契约定义；没有自动生成通用机器人动作。

## 0.6.3：修改应用并重新验证

交付清单提供“修改为新版本”。编辑器沿用原应用的目标机器人、技能、参数和执行时限；支持添加、移除及调整步骤顺序。用户填写新版本号，先查看新旧差异，再保存；返回修改保留配置。变更预览明确标出新增/移除步骤、技能、参数与执行时限变化。

保存创建独立版本，记录父版本及原始应用关系，原版本、报告与发布记录不变。同一应用版本号不可被另一份配置占用，完全相同的重复提交返回同一个版本。原技能记录如与已固定摘要不同，不能悄悄用新定义替换旧技能。

新版本不复制旧的检查、现场测试或发布资格，保存后进入新版本交付清单，首页立即指向新版本的下一步。版本记录可回看原应用及它的现场结果；查看历史不执行部署或回退。修改配置不会自动生成技能代码或向设备发送请求，复杂技能参数仍遵循执行器的 JSON 契约。

接口：POST /api/applications/revision-preview 接收 project_id、source_application_id、name、version、robot_id、steps，返回规范化 manifest、changes 与 preview_digest，不写入记录。POST /api/applications/revise 另需同一 preview_digest，重新校验源应用与依赖后保存。版本关系字段为 parent_application_id、parent_application_digest、root_application_id；revision_digest 用于重试去重。旧应用无需迁移。


## 0.7.0：连接后持续调查本体

用户先输入 SSH 信息并确认主机指纹；若尚未配置工程模型，添加平台模型或自有 API 后自动返回刚连接的本体。初始读取目录收在高级设置，不要求用户预先了解全部配置位置。

调查窗口显示原生计划、消息、工具结果、基础调查覆盖数和原始证据。额外 SSH 命令显示目标、用途、完整命令和时限；新目录显示路径及用途。用户批准或拒绝后仍回到同一调查会话。可停止、继续追问、查看本地分析产物和本体档案。

档案区分已有依据、尚无依据的类别和具体未知项。基础信息通过一次体检收集，厂商工程、服务、协议与标定由 Agent 按发现继续追查。没有发现某设备不能推断不存在，读取配置也不能推断该配置已在实机生效。


## 0.7.1：把调查结果变成可使用的本体档案

入口为“我的机器人 → 本体档案”。档案顶部显示当前/历史版本、发现数、引用证据数和待确认项；用户可以按系统、计算硬件、传感器、执行器、接口、软件、中间件、服务、模型与配置筛选，或搜索条目名称及描述。没有证据的类别单独列为待确认，不显示为“没有该硬件”。

版本下拉切换已保存报告，历史正文、证据引用、未知项和建议保持原值；选择历史版本不覆盖当前报告。与上一版的比较区分新增记录、描述变化、依据更新和本版未记录。基于类别+名称进行记录分组，保留同名多项；改名不会被推测为同一个物理部件。不同调查对同一组件重新取证时只显示依据更新。未再出现的未知项不能自动判定已解决。

条目的“依据”展示采集时间、目标连接、探针/命令/路径、标准输出、错误及读取限制；完整记录可以展开，返回保留所选版本和筛选。页面读取存储证据，不重新访问机器人。来源调查入口与该版本绑定，历史会话打开其当时保存的档案。

“补齐未知项 / 继续调查”从当前档案预填调查请求，进入确认表单，仍需明确授权调用模型；有调查运行时打开该会话。没有自动调用或收费重试。证据、比较和导出都使用已有契约，无数据迁移；这次更新不扩大设备权限或改变部署资格。


## 第 01 轮修复：仿真标注与解除急停

**仿真标注。** 本体能力清单声明 `simulated=true` 的机器人，在“我的机器人”卡片、交付清单的机器人信息、验证报告列表和设备请求记录中都带“仿真”标记，卡片下方写明“仿真本体的测试结果不能作为现场证据；请在真实本体上进行现场测试”。用户仍可对仿真本体发起“现场测试”来试运行应用：结果原样保存（通过/未通过不改写），但记为“仿真测试（不能作为现场证据）”，交付清单显示仿真结论和查看入口，不出现“发布”“启动”。报告详情列出判定依据（本体声明仿真、设备返回 `simulated=true`、证据类型不是 `device_run`、证据引用为 `simulation://`）。直接调用发布或启动接口会被拒绝，并给出同一句中文说明。真实本体（非仿真）的现场测试照常进入“发布 → 启动”流程。

兼容说明：设备端现场测试结果必须声明 `evidence_kind: "device_run"` 才算现场证据。旧适配器若没有返回该字段，结果会被记为仿真测试并注明“设备未声明 evidence_kind=device_run”，需要在适配器中补上该字段后重新测试。旧设备清单没有 `simulated` 字段时仍可连接，摘要不变。

**解除急停。** 设备在“请求停止”后会锁存急停，之后的现场测试和启动都会被拒绝。出现以下任一情况时，交付清单顶部显示“急停已锁存”和原因，“我的机器人”卡片显示“急停已锁存”标记，两处都有“解除急停”按钮：设备状态或执行前检查报告急停已锁存；这台机器人最近一次操作是停止。点击后进入确认页，需要勾选“我在现场，已确认急停原因已排除……授权解除急停锁存”才能提交，没有勾选时不会向设备发送请求。设备确认后提示“设备已确认解除急停”，设备请求记录出现“解除急停 · 已受理”，之后可以再次“准备启动工作”。若请求结果不明，记录为“待人工核对”，不会自动重试；同一次确认重复提交不会重复发送。急停锁存期间，“请求停止”始终可用；启动会直接提示先解除急停，不会发往设备。

## 第 02 轮：看懂机器人能做什么，装上技能，接入云平台

**机器人能做什么。** “我的机器人”卡片上，连接检查通过的机器人有“能力与技能”入口。详情先列出机器人身份、形态、连接状态、厂商与型号；仿真本体带“仿真”标记并重复说明仿真结果不能作为现场证据。下面是“标准能力”：每项能力显示中文名、标准 ID、类型（状态读取 / 传感数据 / 即时指令 / 持续动作）、安全级（不产生运动 / 会产生运动 · 需现场授权 / 修改设备软件）和设备声明的参数（带单位，例如 max_vx 1.0 m/s；没声明的写“未声明”）。名称、类型与安全级都来自 NeuxMind 能力标准，与运行时、SDK、云平台一致。设备提供 `/v2/manifest` 时按标准清单显示；旧设备只有 v1 能力名称列表时照样显示，并说明“没有参数与限值信息”；不在标准中的名称如实标为“未在能力标准中”，厂商扩展 `x.*` 标为运动类。打开详情只读取设备，不会让机器人动作。

**装上技能。** 在详情的“已安装技能包”处点“安装技能包”，两步完成：
1. 填写本地技能文件夹的完整路径（文件夹里要有 skill.json；在“访达”中选中文件夹按 ⌥⌘C 可复制路径）。平台只读取文本文件，不跟随符号链接，跳过 tests/ 与隐藏文件，并限制文件数与大小；隐藏目录中的文件夹不读取。点“检查兼容性”只做检查，不安装。
2. 结果页先给结论：“兼容：可以安装”或“不兼容：不能安装”，不兼容时用人话列出原因，例如“缺少能力「机械臂关节位置」（arm.joint_position）：这台机器人没有声明它”“「底盘速度」（base.velocity）的参数 max_vx：技能需要至少 2.0 m/s，这台机器人声明为 1.0 m/s”。不兼容时没有安装按钮，技能包不会发送到机器人。兼容时列出需要的能力、运行参数和将要安装的文件，确认后安装；安装只写入技能文件，不启动技能、不让机器人动作。

如果确认前文件夹内容变了，平台要求重新检查，避免装上没看过的内容。同一次确认重复提交不会重复安装；设备拒绝（例如同一版本号内容不同）会直接说明；结果不明时记为“待核对”，不自动重试。安装后详情页自动滚到“已安装技能包”。

**云平台账户。** 左侧“工具与账户”新增“云平台账户”。先设置云平台地址：只接受 https，本机开发服务（127.0.0.1、localhost）可以用 http 并有提示。然后登录或注册。注册后显示邮箱验证状态；未验证可以浏览和查看钱包，但购买、调用云端模型需要先验证。云平台运行在开发/测试环境、没有发送真实邮件时，注册结果里会显示带“仅开发环境”标记的开发令牌和“用开发令牌完成验证”按钮；正式环境令牌只出现在邮件里。登录后显示钱包的可用、已预留和账户余额（点数），以及“适合这台机器人的模型”：选择项目中已连接的机器人，云平台按它的能力清单、形态和端侧推理运行时筛选。登录会话保存在本机工作空间的凭据文件（只有本人可读），不出现在页面数据、记录或日志中；密码只发送给云平台。更换云平台地址会退出账户；会话过期时页面提示重新登录。（第 02 轮时工程助手尚不走云平台网关；第 03 轮起见下一节。）

**现场测试进行中。** 发起现场测试后，交付清单立刻显示“现场测试进行中”：开始时间、最近一次查询时间（读不到设备状态时说明原因，测试仍视为进行中），以及始终可用的“请求停止”和“立即刷新状态”。结果返回后清单自动更新，不需要刷新页面。停止后本次测试记为未通过，并显示“急停已锁存”。测试结束前不能发布或启动。设备报告结果未知（例如运行时重启）时记为“待人工核对”，不会重试。旧设备不支持异步测试时自动按原方式等待结果。仿真本体的结果仍记为仿真测试，不能作为现场证据。

**急停锁存时不能启动。** 应用已发布但急停锁存时，交付清单写明“急停已锁存，暂时不能启动”，“准备启动工作”按钮不可点并注明“需先解除急停”；“部署与运行”页的“启动工作”同样不可点，卡片下方说明原因。解除急停后恢复可用。“请求停止”始终可用。

**第 02 轮审查修复补充。** 技能文件夹的路径上任何一级是符号链接都不读取，并指出是哪一级；在 macOS 上 `/tmp`、`/var` 本身是链接，请填写 `/private/tmp/...` 这样的实际路径（在“访达”中复制的路径通常已经是实际路径）。文件夹里的硬链接文件、管道和设备文件也不读取，提示复制成普通文件后再选。云平台地址中的 `localhost` 会保存为 `127.0.0.1`；指向内网或链路本地地址的云平台默认不允许连接（页面说明原因），确需连接内网部署的云平台时，由本机管理员设置 `NEUXMIND_CLOUD_ALLOW_PRIVATE=1` 后重启桌面端；云主机元数据地址始终不允许。设备返回无法识别的现场测试状态时，记录显示为“待人工核对”，并写明收到的状态。

## 第 03 轮：工程助手使用云平台模型

**选择云平台模型。** 登录云平台账户后，“工程助手 → 配置 / 选择模型”里多出“使用云平台模型”，并说明调用经云网关会话、计量与扣费只在云平台进行；未登录时只提示“登录云平台账户后可以选用云平台模型”，并给出前往“云平台账户”的按钮，原有的“平台付费模型”和“自有模型”不变。列表只显示云平台目录里可经网关调用的大语言模型，每项带计价（例如“10 点 / 千 token”）；尚未获得授权的模型列在下方“尚未授权”，不能选；账户邮箱未验证时提示先验证。选中后模型卡片标为“云平台计费 · 云网关会话 · 云平台计量与扣费”。

**预算。** 新建工程任务或设备调查时选中云平台模型，Token 预算自动提到 200000，并显示说明：预算就是云端会话的硬上限，开启时按预算在云平台钱包预留点数，结束后按云端计量结算；预算至少 80000（网关按每次请求的大小保守预留，工程引擎每次请求约 5 万 Token）。低于 80000、未登录、云地址已更换或邮箱未验证时，任务在开始前就被拒绝并说明原因。

**运行与结算。** 每次运行（新建或“继续会话”）开启一个云端会话，结束时——无论完成、用户停止、达到时间或 Token 限额，还是出错——都会关闭它。会话详情里的“云端计量”块显示：云端会话编号、本次预算与云平台预留点数、云端计量用量、云平台扣除点数、计量依据，以及多次运行的累计扣除；如果某次调用超出预留，还显示“超出预留的调用”（只按预留上限计费，超出部分待平台核对）。说明一行写明“费用只由云平台按服务端计量结算，本机账本不记账；‘已报告’Token 是工程引擎自报的观察值”。本机的点数账本在这条路径上完全不变。

**出错时看到什么。** 钱包不够预留本次预算：“云平台钱包可用点数不足以预留本次预算……（需要 10000 点，可用 4968 点）”；未授权、模型下架、会话忙（同一会话同一时刻只允许一个调用）、剩余预算不足以容纳下一次请求、会话已锁定或过期、网关拒绝某个请求参数等都有对应的中文说明，原始返回内容保留在“服务返回详情”里。云端的超额结论优先于工程引擎自己的报错。应用崩溃或网络故障导致云端会话没有关闭时，会话记录标为“云端会话待关闭 / 未能关闭”，并提供“关闭云端会话并获取计量”按钮；直接“继续会话”时也会先尝试关闭上一次留下的会话，关闭不了的会话仍保留在记录中，不会因为开启新会话而丢失；云平台也会在会话到期后自动关闭并结算。

**第 03 轮审查修复补充。** 很长的工程任务可能因为会话历史超过云端单次请求的体积上限而停下，这时会话记录写明“云端会话历史过长……请新建工程任务（新会话）继续，并在目标中简要说明已完成的进度”，本次请求不计费，产物与记录保留。协作流程中，某一阶段的云端会话没有关闭成功（“云端会话未能关闭 / 待关闭”）时，阶段不会进入验收，而是显示“费用待确认”，在该阶段的会话记录中点“关闭云端会话并获取计量”后再重试。工程引擎不再在会话目录里保存 shell 环境快照（其中曾包含模型密钥），也不再从网络下载插件市场；每个会话目录从约 86 MB 降到约 2 MB。


## 第 04 轮：从本体档案到适配报告（本体适配）

**入口。** “我的机器人”里打开某台本体的“本体档案”，当前版本底部有主按钮“本体适配：生成适配器并测试”（查看历史版本时不显示——适配总是基于最新档案）。表单写明使用的是哪一版档案（编号与时间）、四个阶段各做什么，让你选择阶段 1、2 使用的工程模型、每阶段 Token 观察限额与时长，并提示：motion 级需要你在现场确认并显式授权、只对真机执行，本轮不会自动执行；一致性测试会在本机独立进程中运行生成的适配器代码（替身后端，不连接机器人）。勾选授权后启动第一阶段。同一本体已有进行中的适配流程时，按钮直接打开那个流程。

**阶段 1 · 能力映射。** 工程助手读档案与能力标准，为每一项标准能力写一行：实现方式（ROS 2 话题、ROS 2 动作/服务、厂商 SDK、串口协议、其他接口、不支持、需确认）、具体接口、引用的档案证据和说明。产品逐行检查：缺项、非标准能力、重复、引用了档案中不存在的证据都会让阶段停下并写明原因；**没有引用证据的行一律显示为“需确认”**，并注明“Agent 原写：厂商 SDK”之类；写了实现方式但缺少能力标准要求的参数（如底盘最大速度、相机坐标系——这些限值只取自档案，不猜测）的行同样改为“需确认”并写明缺哪些参数；参数值不合规范则阶段停下。表格上方提示有几项被这样处理。映射表在阶段卡片里直接显示，验收通过后才进入下一阶段。

**阶段 2 · 生成适配器。** 平台先用运行时脚手架生成适配器包（只包含映射为可实现的能力，以及必备的停止与系统健康），工程助手再在其中实现。阶段卡片列出适配器包的文件数、入口（`<模块>.adapter:<类>`）、脚手架已实现的能力（ROS 2 模板）与待实现（不声明）的能力；停止或系统健康还未实现时用粗体提示“实现前运行时拒绝加载，一致性测试会失败”。映射里缺少限值时脚手架会拒绝生成，阶段停下并显示运行时给出的原因（例如“base.velocity 缺少必填参数 max_wz”）。交付快照可逐个查看 `adapter/<模块>/adapter.py`、`adapter.json`、`adapter/README.md`、`adapter/IMPLEMENTATION.md`。本阶段要求至少一条真实成功的命令记录。

**阶段 3 · 一致性测试（不调用模型）。** 平台用运行时的一致性测试套件对已验收的适配器副本运行 static 与 dry 两级测试（ROS 2 部分连到运行时自带的测试替身与假机器人，不连接真实机器人），阶段卡片显示“最新一致性报告”：三个级别（static / dry / motion，motion 固定为“未运行”），每级写明通过、失败、跳过、无法测试的用例数和无法测试的原因；黄色提示“一致性报告不等于现场验收证据”并附运行时自己的声明（ADR-011）；下面列出报告的关键字段——evidence_kind（仿真/替身证据）、simulated、field_acceptance（false，不是现场验收）、报告编号、运行时与能力标准版本，以及报告带有时的 manifest_digest；每项已声明能力的 static/dry/motion 结论与原因，dry 跳过时注明“无可测内容”或“无法测试”。适配器无法被运行时加载（例如停止能力还没实现）时，阶段停下并显示原因，不会生成看似通过的报告。原始 `conformance.report.v1` 报告可在交付快照中查看。测试失败也会进入验收，由你决定退回或继续；你可以随时“停止推进”，测试进程会被立即终止且不保存报告，之后可“修正要求并重试”（不调用模型）。

**审查修复后的安全提示（第 04 轮）。** 阶段 2 卡片用粗体写明"验收后平台会在本机以你的用户身份运行这些代码做一致性测试（断网）；请先审查代码"。如果适配器代码试图接触一致性测试套件或运行时内部（例如导入 `neuxmind_runtime.conformance`、动态导入、`exec`），阶段 2 直接停下并列出文件与行号。一致性报告卡片写明是否已断网运行，并提示"报告由适配器所在进程产生，可被适配器代码影响"。测试被中止时（例如操作员按下急停、本体未按时停下），级别显示红色"测试中止"，卡片顶部写出中止原因和"结束时急停仍锁存"，不会显示为通过；测试前已锁存时提示该级别无法测试。

**阶段 4 · 适配报告（不调用模型）。** 卡片显示四个数字：可用（仅替身/仿真验证）、未实现、需现场验证、风险；`ADAPTATION_REPORT.md` 按这四节列出每项能力和依据。运动能力即使在替身上通过，也会列在“需现场验证”里。

**在本体详情里看结论。** 有档案的本体卡片上都有“能力与技能”。本体详情左边是标准能力表，右边是最新一致性报告摘要（是否已验收、三个级别及用例数、报告关键字段、每项能力状态），并重复“不等于现场验收证据”和 motion 说明；本体档案页底部也显示适配流程的进度和最新报告的三项结论。

**浏览器验收（本轮）。** 从档案进入 → 启动表单 → 映射表（含“需确认”降级）→ 适配器阶段 → 一致性摘要 → 原始报告 → 适配报告 → 流程完成，截图 1440×930 与 900×640 已逐张查看。第一版时本体详情“与能力表并列”的一步待复验；第 04 轮第二版（接真实运行时）的浏览器验收一次通过全部步骤（含本体详情并列、900 px 不横向溢出、档案页结论），并检查了报告字段（field_acceptance false、evidence_kind simulation、dry 失败 0、ADR-011 声明、报告编号）与原始报告中的 `"field_acceptance": false`，13 张截图已逐张查看，0 个 JS 异常。

## 第 04 轮：停止有上界

工程会话（调查、工程任务、协作流程的阶段）点击“停止”后，最迟约 10 秒内一定结束：正在等待工程引擎答复的调用会立即放弃；引擎没有响应中断请求或 10 秒后仍未结束时，平台强制终止引擎进程，会话标记为“已停止”，并写明“停止请求在 10 秒内未生效，已强制终止工程运行时进程；已保存的证据、产物与记录保留……可继续会话”。重复点击停止不会产生额外动作。

## 第 05–07 轮：站在新用户的路径上（摘要）

逐条细节与修改前后截图见 `docs/evolution/iterations/2026-11-09-iter05.md`、`2026-11-09-iter06.md`、`2026-11-10-iter07.md` 和 `docs/evolution/reviews/2026-11-09-ux-audit.md`，这里只记约定：

- **先说能做什么，再让用户动手。** 仿真机器人在部署前就说明能做什么、不能做什么、真部署需要什么，不要等到最后一步才出现技术性拒绝。"运行技能"变灰时写明原因。
- **参数用表单，不用 JSON。** 按 `skill.json` 生成表单（中文名、说明、单位、范围），单位只取自 `skill.json`；越界在发送前标到对应字段，设备返回的字段级拒绝也映射回字段；"高级 JSON" 保留。下拉选项显示名称，不显示内部编号。
- **报错说白话，并且说真话。** 中文说明在前，技术细节收起。错误先按错误码分类，再看 HTTP 状态，最后才看文字；安全拒绝永远不能说成"服务出错，稍后重试"或"网络超时"。
- **每个空状态都有下一步。** 只用仿真机器人也能走完主流程；没配模型时说明用途、获取方式和费用，并提示"不配置也能先用仿真机器人"。
- **术语收进"高级"。** 第一屏不出现接口地址和能力 ID，用机器人名代替内部编号。
- **复位和急停如实告知。** 复位卡住时说明"完成后急停可能自动解除、本体可能动作，请保持远离"，并提供"停止（取消那次复位）"；驱动不服从停止时显示全局横幅"请立即使用硬件急停"（真机也显示、跨项目）；仿真机器人不提"硬件急停"。
- **首次使用引导**三步，完成一步自动打勾一步；实时状态全部用中文。

## 第 08 轮：接入真机的第一分钟（issue #2、#3、#4）

细节见 `docs/evolution/iterations/2026-11-12-iter08.md`、[ENGINEERING_ENGINE.md](ENGINEERING_ENGINE.md) 和 [HARDWARE_INIT.md](HARDWARE_INIT.md)，这里只记约定：

- **怎么连就怎么填。** SSH 接入可以直连或经一台跳板机，也可以直接粘贴平时在终端里用的 ssh 命令（包括“先登录跳板机、再在上面 ssh 到目标机”的嵌套写法），表单自动填好；命令只解析、不执行，采用不了的部分（密钥文件、本机别名、末尾的远程命令）要在页面上说明。
- **先确认指纹，再发凭据。** 经跳板机时两台的指纹依次确认；失败时说清是哪一跳、什么原因（不通、不是 SSH 服务、认证被拒、指纹变了、应答超时）。
- **替用户解析出来的去向要摆出来。** 目标机只给了一个名称、由跳板机上的 SSH 配置解析时，确认指纹那一步显示“名称 → 用户@地址:端口”，用户确认的是实际要连的地方；为此在跳板机上只执行一条固定的只读命令，页面和文档都写明是哪一条。
- **连上之后先看硬件。** 连接成功的下一步是只读的硬件扫描（几秒，不调用模型，不修改设备），用表格列出硬件和需要处理的问题；原来的“让 Agent 深入调查本体”是扫描结果页上的下一步。
- **会改设备的事逐条问。** 硬件修复的每条命令单独审批，完整展开，写明目的、风险和回滚方式；产品会拒绝常见的危险命令，但这只是第二道防线，不能替代用户的审批。
- **真机状态只读，并且写明。** 实时状态页标“真机 · 只读”，由一条固定命令产生，不经过模型。
- **模型只有一个来源。** 工程助手的大模型只对接 TokenFans，在“云平台账户”页配置；需要模型而还没配置时，对话框只给这一条路，并说明费用从哪里扣。第 03 轮描述的“选用云平台模型”等入口在界面上不再提供（后端路径保留给历史会话）。
- **Key 不回显。** 页面只显示 Key 的前后几位；密码只用于一次登录，不保存。
- **先登录，再进工作空间。**（并入 main 的账号管理之后）应用打开是整页的登录 / 注册页，不再先闪出空的工作台；注册和找回密码用邮件里的 6 位验证码，没配邮件服务时页面要写明验证码存在本机哪个文件里。账户相关的入口集中在侧栏底部的账户菜单；侧栏不再显示版本号，版本在“关于”窗口里看。
- **调查不设 Token 和时间上限。**（issue #5）“让 Agent 调查本体”对话框不再填写 Token 观察限额和最长运行时间，也不显示限额说明；调查一直运行到 Agent 完成，或用户在会话里停止。新建工程任务、硬件修复、本体适配和协作流程的限额不变。
- **调研入口看状态。**（issue #6）每台 SSH 机器人有一个调研状态，入口按状态打开：未调研是开始表单，调研中是实时进展（连接或硬件扫描 → 基础体检 → 深入调查 → 生成档案，以及等待批准），调研完成是报告。调研进行中不会再给出第二张开始表单。
- **重新调研走完整流程。** 报告上的“重新调研”先做一次只读硬件扫描，再做一次不读旧档案的完整调研，生成新的档案版本；旧版本保留，可以对比。
- **修复用对话，改设备逐条批准。** 报告里的“问题与修复”按类别列出最近一次扫描的问题，可以勾选问题或直接描述，开始对话修复；每条修改设备的命令以卡片显示完整命令、回退方法和风险，由用户逐条批准。
- **界面默认不出现代码和 JSON。**（issue #7）机器数据显示成“名称—值”的行；命令、原始输出、文件内容折叠在“展开查看…”里，摘要写明是什么、有几行。例外是审批：要用户批准的命令不用点击就能看全。规则见 [UI_STYLE.md](UI_STYLE.md)。
- **下拉框和悬停状态是控制台自己的。** 所有下拉框用同一个控件（键盘可用）；按钮和链接的悬停、按下、禁用颜色留在各自的色系里。
