issue 的四条要求和做法：

| 要求 | 做法 |
| --- | --- |
| 入口是一个 Dashboard，展示任务名称和数量 | `#overview` 改成概览页：最上面一块是任务数量、任务名称，以及所有任务合计的机器人、应用、已部署数 |
| 下面是瀑布流的任务列表，绑定给用户账号 | 概览下面是「全部任务」，每个任务一张卡片（issue #46 起所有卡片大小一致）；任务保存在当前登录账号自己的工作空间里 |

这里的“任务”就是控制台一直叫“任务项目”的那个东西（记录类型 `projects`）：一项要机器人完成的工作，机器人、应用、测试和部署记录都挂在它下面。没有新增数据类型。

## 页面

| 地址 | 内容 |
| --- | --- |
| `#overview` | 概览页（入口）。没有任务时显示“创建你的第一个任务”，首次使用引导在它上面；有任务后任务列表紧跟在概览下面，引导排在列表后面。首次使用引导只在账号第一次进来时出现 |
| `#task` | 一个任务的页面：“现在做这一步”、五步进度、**技能与配置**、按需使用的能力。左上角「← 全部任务」回到概览页；页头没有按钮 |

- 新建任务后直接进入这个任务（`#task`）。
- 进入任务：卡片上的「进入任务」，或概览里的任务名称。上次打开的任务在卡片上有标记。
- 任务的页面在侧边栏里仍然算「任务工作台」，面包屑显示“任务工作台 / 任务名”。
- 没有任务时打开 `#task`（例如最后一个任务刚被删除）会回到概览页。

卡片上有：创建时间、名称（一行）、目标（两行）、五步进度（明确任务 → 连接机器人 → 准备能力 → 验证效果 → 部署使用，写明有几步已有记录、下一步是什么）、机器人、机器人应用、已准备（模型/技能/数据数量）各一行。放不下的文字截断并以“…”结尾，名称的全文在鼠标悬停时显示；没有内容的一行写“还没有”。卡片上的五步进度是按任务的全部记录粗算的，任务页面里的进度按当前机器人和应用细算，两者在有多个应用时可能不同。

## 任务属于账号

每个账号有自己的工作空间（`<状态目录>/workspaces/<账号 id>/`），任务和它下面的所有记录都在里面，接口只读写当前登录账号的工作空间。所以概览页上是这个账号自己的任务，别的账号看不到，也删不掉（`projects/remove` 对别人的任务 id 回答“这个任务已经不在了”）。页面上原来有一句话说明这一点，issue #46 要求删除；规则本身没有变。

任务保存在这台电脑上，不随账号同步到别的电脑。

## 删除任务

接口 `POST /api/projects/remove`，参数 `project_id`；实现在 `brainos/task_remove.py`。

会删除（都只是这台电脑上保存的内容，不联系任何机器人或服务）：

- 任务本身；
- 所有带这个任务 id 的记录，不分类型：模型、数据、技能、应用、任务记录、测试报告、发布和运行记录、助手会话、协作流程、助手工具等。以后新增的记录类型只要带 `project_id` 就会一起删除，不用在这里登记；
- 挂在这些记录 id 下面的内容：助手自有模型和工具服务保存的密钥、硬件扫描的原始输出；
- 这个任务的助手会话在这台电脑上生成的文件。

不删除：审计日志（`events`）原有的记录保留，并新增一条 `project.removed`，写明任务名称和各类记录删了多少条。

以下情况拒绝删除，任务和它的内容原样保留：

| 情况 | 提示 | 怎么办 |
| --- | --- | --- |
| 任务里还有机器人（真机或仿真） | 这个任务里还有 N 台机器人（名字）… | 先到“我的机器人”里删除它们。对话框里有「去我的机器人」，会切到这个任务。0.21.11 起机器人属于账号（issue #42 第二部分，[ROBOT_SCOPE](ROBOT_SCOPE.md)），迁移后任务里不再有机器人，这一条在应用里不再出现 |
| 有助手会话正在运行 | 这个任务有助手会话正在运行… | 等它结束或先停止 |
| 协作流程正在运行 | 这个任务的协作流程正在运行… | 等这一阶段结束或先停止 |
| 提交给执行服务的任务还在执行，或提交后没有得到明确答复 | …还在执行，或提交结果还没有确认（任务名）… | 等它结束、同步状态或先取消 |
| 有任务的预留额度还没有结算 | …有预留额度还没有结算（任务名）… | 在任务记录里同步或取消：只有这条任务记录能结算它 |
| 有助手会话的云端会话没能关闭（费用待确认） | …云端会话还没有关闭… | 在这次会话里“关闭云端会话”：只有这条会话记录能关闭它 |

**为什么有机器人就不能删（0.21.10 及以前）。** 0.21.11 起机器人不属于任务，删任务不动机器人，下面这段只说明当时的考虑。 机器人带着保存的登录信息、调研记录，仿真机器人还有正在运行的进程；删除机器人已经有自己的规则（issue #11 的 `brainos/robot_remove.py`、仿真机器人的 `SimRobots.remove`），知道哪些情况不能打断。这一版让用户先在“我的机器人”里逐台删除，而不是删任务时连带删掉。如果希望删任务时把机器人一起删掉，需要另外决定（改 `TaskRemoval._refuse_while_in_use` 并逐台调用上面两个删除）。

被拒绝时什么都不动。先删文件，有一个文件夹删不掉就什么都不删；记录逐条删除，任务自己的记录最后删，所以中途被打断（例如应用被关掉）时任务还在列表里，再删一次即可。

没有覆盖的情况：删除任务的同一瞬间正好有机器人或其他记录加进这个任务（那边“检查任务存在”和“写入”是两步），这条记录可能留下来而任务已经没有了。

页面在打开删除对话框时先按自己已有的数据说明会删什么、或者为什么现在不能删；最后以服务端的判断为准。对话框打开之后情况变了（例如别处刚给这个任务加了机器人），点「删除任务」会被服务端拒绝，对话框重新画成不能删除的说明。

## 做法

- 新增 `web/task_workbench.js`、`web/task_workbench.css`、`brainos/task_remove.py`。页面在所有脚本加载完之后（`DOMContentLoaded`）接管 `views.overview`、新增 `views.task`，并包装 `action`（`task-` 开头的动作）和 `render`（任务页面的侧边栏高亮和面包屑），所以 `index.html` 里这一行放在哪里都可以。

- `twFacts / twTotals / twPlan / twCard / twBoard / twDashboardMarkup / twTaskMarkup` 是只处理数据和字符串的纯函数，在 `tests/task_workbench_logic.cjs` 里检查。

## 对已有浏览器验收脚本的影响

入口页不再是某一个任务的步骤页：

- 需要看“现在做这一步”（`.journey-next`）或五步进度（`.journey-step`）的脚本，改为打开 `#task`（`ux03_browser`、`ux04_browser`）。
- `ux05_browser` 里“关闭引导后工作台其余内容照常”的检查，改为检查概览（`.tw-board`）还在。

## issue #46 的改动

### 全部任务

| 要求 | 做法 |
| --- | --- |
| 所有方格大小一致，考虑不同屏幕和不同文字数量 | 卡片排在等宽等高的网格里（`.tw-wall`，每列至少 300 像素，按窗口宽度自动决定列数，手机上一列）。每张卡片的组成固定：每一部分占固定的行数，文字多了截断，没有内容的一行也保留。所以高度和任务叫什么、有多少内容无关 |
| 首次使用引导第二次进来的时候删除 | 账号第一次打开任务工作台时显示，并记下“这个账号看过了”；下次再打开应用（页面重新加载）就不再显示。同一次打开期间引导一直在，跟着做三步时不会中途消失 |
| 删除“任务属于当前登录的账号…其他账号看不到” | 已删除 |
| 右上角使用指南删除 | 页头的「使用指南」按钮和它的对话框已删除 |

“第二次进来”按“下一次打开应用”理解（`twGuideOnce`，浏览器存储里每个账号一个标记 `nx-first-run-guide-seen:<账号 id>`）。同一台电脑上换一个账号，那个账号有自己的第一次。浏览器存储不可用时记不住，引导照常显示。引导自己的「关闭」按钮照旧。

窗口最上面一条里的「使用指南 ↗」是所有页面共用的，没有动。

### 任务详情

| 要求 | 做法 |
| --- | --- |
| 去掉“任务工作台里的 N 个任务之一” | 已删除，返回链接那一行只剩「← 全部任务」 |
| 创建应用项目和使用指南都去掉 | 页头的「新建任务项目」「使用指南」两个按钮已去掉。“现在做这一步”里的「查看完整流程」还在 |
| 展示用了哪些技能、安装了哪些技能、怎么配置的 | 新增「技能与配置」一节，在五步进度下面 |

「技能与配置」按任务里的机器人分块（`web/task_skills.js`），每台机器人：

- **认识的地点**：机器人在能力清单里声明的地点名（`base.navigate_to_place` 的 `places`）。
- **已安装的技能**：机器人已连接时从设备上读（和“能力与技能”里是同一个只读请求 `robots/detail`，每台机器人读一次，可以点「重新读取」）；没连接或读不到时，按控制台自己的安装记录显示，并写明原因。
- **每个技能在这个任务里怎么用、配成什么**：
  - 机器人应用里用到它的每一步：哪个应用的第几步、时间上限、这一步保存的每个参数；
  - 最近一次直接运行：时间、结果、当时的参数，以及一共直接运行过几次；
  - 任务还没用到的技能：标明“这个任务还没有用到”，列出运行时的默认值。
- 参数按技能自己声明的名称和单位显示。值是这台机器人认识的地点名时，按保存的顺序排成带编号的一串（巡检顺序）；值是一组坐标点时，带编号列出每个点的坐标（航点）。没有填的参数写“未填写”，用的是默认值的写“默认值”。
- 应用的步骤里写了、但设备上没有的技能，标“设备上没有这个技能”；读不到设备时标“不知道是否已安装”。

**没有的内容：地点的坐标和地图。** 机器人按能力标准只报告地点的名称，坐标和地图在机器人自己的导航程序里，控制台没有这些数据，页面上如实写了“没有报告”。用坐标的技能（“巡逻”的航点）坐标是技能参数，所以能显示。要显示地点坐标和地图，需要先在能力标准里加上这两项声明，并让本体（仿真本体、ROS 2 适配器的配置）报告它们；这一步没有做。

这一节不新增数据类型，也不向机器人发任何指令。它是单独更新的：读到设备的回答后只重画这一节，不重画整页。
