# 任务工作台（issue #44）

更新：2026-11-24。对应 GitHub issue #44「任务工作台」。

issue 的四条要求和做法：

| 要求 | 做法 |
| --- | --- |
| 入口是一个 Dashboard，展示任务名称和数量 | `#overview` 改成概览页：最上面一块是任务数量、任务名称，以及所有任务合计的机器人、应用、已部署数 |
| 下面是瀑布流的任务列表，绑定给用户账号 | 概览下面是「全部任务」，每个任务一张卡片，按内容高低排成多列；任务保存在当前登录账号自己的工作空间里 |
| 任务可以删除或创建 | 页头「新建任务」；卡片上的「删除」。删除是新增的后端功能 |
| 右上角使用指南 | 页头右上角「使用指南」，说明任务是什么，怎样新建、进入、删除 |

这里的“任务”就是控制台一直叫“任务项目”的那个东西（记录类型 `projects`）：一项要机器人完成的工作，机器人、应用、测试和部署记录都挂在它下面。没有新增数据类型。

## 页面

| 地址 | 内容 |
| --- | --- |
| `#overview` | 概览页（入口）。没有任务时显示“创建你的第一个任务”，首次使用引导在它上面；有任务后任务列表紧跟在概览下面，引导排在列表后面 |
| `#task` | 一个任务的页面：原来入口页上的“现在做这一步”、五步进度和按需使用的能力。左上角「← 全部任务」回到概览页；原来页面底部的“我的任务项目”列表去掉了 |

- 新建任务后直接进入这个任务（`#task`）。
- 进入任务：卡片上的「进入任务」，或概览里的任务名称。上次打开的任务在卡片上有标记。
- 任务的页面在侧边栏里仍然算「任务工作台」，面包屑显示“任务工作台 / 任务名”。
- 没有任务时打开 `#task`（例如最后一个任务刚被删除）会回到概览页。

卡片上有：创建时间、名称、目标（最多 8 行）、五步进度（明确任务 → 连接机器人 → 准备能力 → 验证效果 → 部署使用，写明有几步已有记录、下一步是什么）、机器人和应用的数量与名称、已准备的模型/技能/数据数量。卡片上的五步进度是按任务的全部记录粗算的，任务页面里的进度按当前机器人和应用细算，两者在有多个应用时可能不同。

## 任务属于账号

每个账号有自己的工作空间（`<状态目录>/workspaces/<账号 id>/`），任务和它下面的所有记录都在里面，接口只读写当前登录账号的工作空间。所以概览页上是这个账号自己的任务，别的账号看不到，也删不掉（`projects/remove` 对别人的任务 id 回答“这个任务已经不在了”）。页面上写明了当前账号的邮箱。

任务保存在这台电脑上，不随账号同步到别的电脑。

## 删除任务

接口 `POST /api/projects/remove`，参数 `project_id`；实现在 `brainos/task_remove.py`。

会删除（都只是这台电脑上保存的内容，不联系任何机器人或服务）：

- 任务本身；
- 所有带这个任务 id 的记录，不分类型：模型、数据、技能、应用、任务记录、测试报告、发布和运行记录、助手会话、协作流程、助手工具等。以后新增的记录类型只要带 `project_id` 就会一起删除，不用在这里登记；
- 挂在这些记录 id 下面的内容：助手自有模型和工具服务保存的密钥、硬件扫描的原始输出；
- 这个任务的助手会话在这台电脑上生成的文件。

不删除：审计日志（`events`）原有的记录保留，并新增一条 `project.removed`，写明任务名称和各类记录删了多少条。

以下情况拒绝删除，任务和它的内容原样保留：

| 情况 | 提示 | 怎么办 |
| --- | --- | --- |
| 任务里还有机器人（真机或仿真） | 这个任务里还有 N 台机器人（名字）… | 先到“我的机器人”里删除它们。对话框里有「去我的机器人」，会切到这个任务 |
| 有助手会话正在运行 | 这个任务有助手会话正在运行… | 等它结束或先停止 |
| 协作流程正在运行 | 这个任务的协作流程正在运行… | 等这一阶段结束或先停止 |
| 提交给执行服务的任务还在执行，或提交后没有得到明确答复 | …还在执行，或提交结果还没有确认（任务名）… | 等它结束、同步状态或先取消 |
| 有任务的预留额度还没有结算 | …有预留额度还没有结算（任务名）… | 在任务记录里同步或取消：只有这条任务记录能结算它 |
| 有助手会话的云端会话没能关闭（费用待确认） | …云端会话还没有关闭… | 在这次会话里“关闭云端会话”：只有这条会话记录能关闭它 |

**为什么有机器人就不能删。** 机器人带着保存的登录信息、调研记录，仿真机器人还有正在运行的进程；删除机器人已经有自己的规则（issue #11 的 `brainos/robot_remove.py`、仿真机器人的 `SimRobots.remove`），知道哪些情况不能打断。这一版让用户先在“我的机器人”里逐台删除，而不是删任务时连带删掉。如果希望删任务时把机器人一起删掉，需要另外决定（改 `TaskRemoval._refuse_while_in_use` 并逐台调用上面两个删除）。

被拒绝时什么都不动。先删文件，有一个文件夹删不掉就什么都不删；记录逐条删除，任务自己的记录最后删，所以中途被打断（例如应用被关掉）时任务还在列表里，再删一次即可。

没有覆盖的情况：删除任务的同一瞬间正好有机器人或其他记录加进这个任务（那边“检查任务存在”和“写入”是两步），这条记录可能留下来而任务已经没有了。

页面在打开删除对话框时先按自己已有的数据说明会删什么、或者为什么现在不能删；最后以服务端的判断为准。对话框打开之后情况变了（例如别处刚给这个任务加了机器人），点「删除任务」会被服务端拒绝，对话框重新画成不能删除的说明。

## 做法

- 新增 `web/task_workbench.js`、`web/task_workbench.css`、`brainos/task_remove.py`。页面在所有脚本加载完之后（`DOMContentLoaded`）接管 `views.overview`、新增 `views.task`，并包装 `action`（`task-` 开头的动作）和 `render`（任务页面的侧边栏高亮和面包屑），所以 `index.html` 里这一行放在哪里都可以。
- 任务页面的内容仍然由 `web/journey.js` 的 `journeyOverview()` 画，这里只在前面加返回链接、去掉末尾的旧任务列表。
- 改动到共用文件的地方都只是插入：`web/app.js` 一行（新建任务成功后调用 `taskCreated`）、`web/index.html` 一行、`brainos/server.py` 两处（静态文件表、路由）、`brainos/service.py` 两行、`brainos/store.py` 新增 `Store.kinds()`。
- `twFacts / twTotals / twPlan / twCard / twBoard / twDashboardMarkup / twTaskMarkup` 是只处理数据和字符串的纯函数，在 `tests/task_workbench_logic.cjs` 里检查。

## 对已有浏览器验收脚本的影响

入口页不再是某一个任务的步骤页：

- 需要看“现在做这一步”（`.journey-next`）或五步进度（`.journey-step`）的脚本，改为打开 `#task`（`ux03_browser`、`ux04_browser`）。
- `ux05_browser` 里“关闭引导后工作台其余内容照常”的检查，改为检查概览（`.tw-board`）还在。
- 点 `[data-action="journey-start"]` 新建任务的脚本不用改：概览页的「新建任务」还是这个动作；新建后停在 `#task`。

## 测试

- `python -m unittest tests.test_task_workbench`：删除任务（带走什么、保留什么、什么情况拒绝、文件删不掉时什么都不删）、两个账号各自只看得到也只删得掉自己的任务、页面文件被正确加载。
- `node tests/task_workbench_logic.cjs`：概览的数量和名称、卡片、删除对话框的说明、输入内容的转义。
- `node tests/task_workbench_browser.cjs <fixture-config.json> [截图目录]`，fixture 用 `tests/ux01_browser_fixture.py`。覆盖：空的概览页、使用指南的位置和内容、新建后进入任务、返回、数量和名称随任务变化、瀑布流（1440 宽度下多列、卡片高度不同，手机宽度下一列）、用任务名称和键盘进入任务、删除（取消、确认）、有机器人时不能删除并能去到它的机器人、对话框打开后服务端拒绝、320 到 1920 宽度下不出现横向滚动、换一个账号看不到这些任务。`BRAIN_BROWSER=webkit` 在 WebKit 上跑同样的检查。

## 这一版没有做的

- 删除任务时连带删除机器人（见上）。
- 修改任务的名称和目标。
- 任务列表的搜索和排序（现在按创建时间，新的在前）。
