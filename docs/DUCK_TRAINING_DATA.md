# 小黄鸭的新模型、训练过程与结果数据（issue #79）

issue：「现在小黄鸭的模型文件和结果应该有新的了，接入进来。并且把对应模型训练的过程与结果数据接入进来。」

训练项目 `duck-rl` 在 2026-11-27 交付了一批新的模型（`reports/training/models/` 下的两个包）。这一版把它们接进应用：六个新模型随安装包带上，在仿真小鸭上跑得和验收时一模一样；每个模型怎么训练出来的、每一个验收回合的结果和录像，都能在「训练与改进」和「模型库」里看到。

## 用户定的事（2026-11-28，本 issue 的会话里）

| 问题 | 决定 |
|---|---|
| 120 场逐场原速录像（77 MB）要不要随安装包带上 | 带上：模型库和「训练与验收」里每个验收起姿都能点开看那一场的录像 |

## 在应用里跑得和验收时一模一样

应用不带 PyTorch，策略用 numpy 算（issue #63 定的）。这一批第一次放进来时，在应用自己的物理子进程里把 120 个验收回合全跑了一遍，和训练项目的记录（`120场验收.csv`）逐场比控制步数：

| | 第一次 | 现在 |
|---|---|---|
| 地板舞定格 | 读不出权重（两个策略网络） | 20/20 通过，20 场步数一致 |
| 没电了，又满了 | 动作差 0.009（少了两个父策略） | 20/20 通过，20 场步数一致 |
| 醉鸭不倒（绕场两圈） | 16/20 通过，0 场步数一致 | 20/20 通过，20 场步数一致 |
| 鞠躬鞠过头 | 20/20 通过，8 场步数一致 | 20/20，20 场一致 |
| 单脚探水、假动作点球 | 20/20，20 场一致 | 20/20，20 场一致 |

改了三处（`brainos/duck_policy.py`、`brainos/duck_tanh.py`）：

1. **两种新的策略结构**，按训练项目自己的回放代码选：地板舞的权重是两个策略网络（`architecture.floor_phase_actor`），按节目进度在第 180–189 拍之间从前一个交给后一个；没电了的权重是一个修正量，加在包里两个冻结的父策略（`duck_show/entrance-actor.npz`、`exit-actor.npz`）上，父策略在编舞时钟 16.06 秒处交接，修正只在开场 0.22–2.40 秒起作用。父策略只按数字读（`allow_pickle=False`），读到别的东西就不运行。
2. **和 PyTorch 一样的 `tanh`。** 矩阵乘法在 numpy 和 PyTorch 里本来就逐位一致（两者在这台 Mac 上都用 Accelerate），差在 `tanh`：PyTorch 用 SLEEF 的 `tanhf`，numpy 的单精度 `tanh` 有一部分输入差最后一位。绕场两圈这样的长节目会把这一点差别放大成另一个回合（16/20）。`duck_tanh.py` 把 SLEEF 的算法逐步写成 numpy（融合乘加按一次舍入算），在 1200 万个输入上和 PyTorch 2.5.1 逐位比过，没有一个不同。地板舞在交接的那 9 拍里用到的 `atanh` 也照样移植（800 万个输入，没有不同）。SLEEF 是 Boost 许可，许可原文在那个文件开头。
3. 没电了的交接用 PyTorch 向量化 `lerp` 的算法（从近的一端做一次融合乘加）。

`tests.test_duck_kit.RealKit` 在构建过套件的电脑上让每个模型跑它独立组的第一个回合，步数要和包里的记录一样。

## 训练过程与结果数据

三个来源，都先核对再用：

| 来源 | 有什么 | 在哪里 |
|---|---|---|
| 模型包里的 `evidence/` | 这一版怎么训练的（更新次数、累计步数、为什么停、设备、PyTorch/MuJoCo 版本、PPO 的设置）；固定组、独立组每个回合的结果、步数、回报和在 15–30 秒时钟上的用时；对照：同样的独立组起姿只按编舞、不加训练出的修正，通过几个 | 安装包里，按包内的 `SHA256SUMS` 逐个文件核对后直接从 zip 读，不解包（`brainos/duck_evidence.py`） |
| 录像包 `recordings.zip` | 120 个验收回合每场一段原速录像（正面、侧面两个视角）和索引 | 安装包里，整包按登记的 SHA-256 核对；只给权重和这一版相同的录像；每段读出时再按包内清单核对 |
| 本机的训练看板 `/api/evolution` | 历次评估、每一轮训练（轮次、结果、更新次数、步数、设备）、交付的版本和以前交付的版本 | 看板开着时读它（gzip，只留用到的字段，最多两分钟读一次），否则用安装包里构建时的那份 |

看板的数据现在有 151 MB（gzip 34 MB）。原来超过 64 MB 就当没有应答，所以页面一直显示安装包里的旧记录；现在按 gzip 读，上限 512 MB，读一次约 2 秒，峰值内存约 0.7 GB，只在有人看「训练与改进」时最多两分钟一次。看板同步出错时的错误原文（里面有服务器地址）不进页面。

### 页面上

**训练与改进 → 仿真舞台（小鸭的那一块）**

- 每个模型写明每段多长；有「训练与验收」按钮。已归档的没有「运行」。
- 「训练与验收」在模型列表下面打开一块：
  - 训练过程：这一版的训练事实和 PPO 设置；这个节目一共训练了几轮、累计多少步、评估多少次，最近 8 轮的结果。
  - 验收结果：验收要求；固定组、独立组每个起姿一行（结果、控制步数、用时、播放）；对照一行（例如绕场两圈只按编舞 7/10，训练出的修正把它提高到 10/10）。
  - 历次交付的版本：这一版和以前随应用带来的版本，各自的两组成绩和独立组起姿。
- 「播放」把那一场的录像放在舞台上，舞台下写明是哪个节目、哪组、哪个起姿；「回到实时画面」回到仿真小鸭。
- 训练进展的表多了两列：交付的版本（两组成绩、用时、设备）、训练（轮数、累计步数）。

**模型库 → 小鸭的模型页**

- 版本：这一版和以前随应用带来的版本。旧版本说明「按当时的验收要求（不看用时）验收……不随这个安装带来」，不能「在仿真里评测」，也不会成为当前版本。
- 每个版本有自己的独立起姿组（训练项目给每一版预先登记的那十个），所以「训练与测试数据」的评测库里多了这些评测集。原来只有一个「独立起姿组」（1991724000 起），那其实只是鞠躬第 40 轮的；它的编号 `hubs-duck-independent` 留给鞠躬第 40 轮，已经引用它的评测和改进轮次照样找得到。
- 这一版的两条验收评测带着每个起姿的结果（起姿、结果、步数、用时），指标是成功率、平均用时、平均控制步数、平均回报。issue #79 之前就有的版本，评测编号保持原样（`hube-duck-<节目>-fixed` 等）。
- 已归档的旧版短醉鸭状态是「已归档」。

## 已经添加的仿真小鸭

仿真小鸭启动前，它的配置换成这个安装带来的模型包（`DuckKit.refresh`，`sim_robots.start` 调用），所以它演的、技能通道跑的、模型库评测的都是新版本，不用重新添加。这个安装里没有能用的包时，它保留原来的配置。启动时它的技能按新版本装上（技能版本是 `轮次.更新次数.模板`，例如 `duck.water` 的 `132.1.<模板>`）。

## 下次训练项目交付新包时

1. 在训练项目的 `reports/training/models/` 找到新的交付包和录像包，记下 SHA-256。
2. 改 `brainos/duck_kit.py`：`BUNDLE`、`RECORDINGS` 的文件名和 SHA-256；把被取代的那一版原样挪进该节目的 `history`（不加 `legacy`：它的评测编号按包的 SHA-256 生成）；写新的包名、SHA-256、出处、两组成绩、`independent_from`、`seconds`。
3. `python scripts/duck_kit.py collect --from ~/code/duck-rl`，再 `build`（`build_macos.py` 会自动调用）。
4. 在构建过套件的电脑上跑 `python -m unittest tests.test_duck_kit tests.test_duck_training_data`：`RealKit` 会让每个模型在应用的物理子进程里跑一个回合，和包里的记录比步数。新包要是用了第三种策略结构，加载时会说权重缺什么，照训练项目包里的 `duck_show/policy.py` 在 `duck_policy.py` 里补上。

## 测试

```sh
python -m unittest tests.test_duck_training_data      # 21 项：tanh、atanh 和 PyTorch 逐位一致、融合乘加、两种新策略、记录和录像的核对、看板、刷新旧小鸭、模型库
python -m unittest tests.test_duck_kit                # 有真实套件时：每个模型在物理子进程里跑一个回合，步数和记录一样
node tests/duck_logic.cjs                             # 页面逻辑
python tests/duck_training_data_fixture.py INFO.json &   node tests/duck_training_data_browser.cjs INFO.json SHOTS
NX_DUCK_REAL_KIT=1 python tests/duck_training_data_fixture.py INFO.json &    # 用真实套件（真录像）
```

`TORCH_TANH`、`TORCH_ATANH` 里的对照值是在这台 Mac 上用 PyTorch 2.5.1 算的；测试本身不需要 PyTorch。录像包的校验值不对时只核对一次，文件变了才再核对；看板的回答解开后最多 512 MB，安装包里那份裁剪过的进展最多 64 MB。

## 在哪里验证过，哪里没有

- 2026-11-28，这台 Mac：120 个验收回合在应用的物理子进程里逐场比过步数（全部一致）；页面在 Chromium 和 WebKit 上用真实套件和编出来的套件各跑过一遍，375、768 宽不溢出；看板接口用正在运行的训练看板读过。
- 没有验证：真机（没有小鸭真机）；Linux 上的套件和 `tanh`（SLEEF 在 x86 上的路径和 Apple 芯片不同，那里 PyTorch 的结果可能本来就不一样）；训练项目以后的交付格式。
- 已知的限制：安装包比 0.21.17 大约 100 MB（六个包 53 MB、录像 77 MB，减去旧的五个包 29 MB）；以前的仿真小鸭解开过的旧包留在工作区的 `duck-kit/<指纹>/`，不会自动清理；旧版本 `duck.drunk` 等技能在已经装过它的仿真小鸭上和技能列表里还在，运行时仿真小鸭不再认这个节目。
