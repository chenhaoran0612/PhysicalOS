# 真实本体：让管理层接到机器人自己的 ROS 2（issue #38）

在这之前，控制台的「安装管理层」（[RUNTIME_INSTALL.md](RUNTIME_INSTALL.md)，issue #19）只会装仿真本体：它不接真实硬件，技能运行“成功”，机器人一步也不动，本体认识的地点也是仿真的。issue #38 的三个技能（去指定地点、巡检、无图自由走，见 [PLACE_SKILLS.md](PLACE_SKILLS.md)）要按**机器人自己保存的地点**去，所以管理层必须接到机器人自己的 ROS 2 上，并且知道这台机器人认识哪些地点、去那里要运行它的哪些程序。这一页说的是在控制台里做这件事的功能。

> 状态：代码和测试完成。在替身机器人、真实安装脚本加替身 ROS 2、两种浏览器里验证过。**这个功能本身没有在真机上走过**：那台四足机器狗上的真实本体是 2026-11-25 手工装的（同一个安装脚本、同一份配置格式），不是从这个界面装的。见[最后一节](#还没有做的没有验证的)。

代码：`brainos/robot_body.py`（本体设置、检查、从机器人读取）、`brainos/runtime_install.py` 和 `runtime_install_plan.py`（按本体安装、换本体只能重装、“应用到机器人”这个任务）、`brainos/runtime_install_device.py`（设备上执行的脚本：多了 `restart` 这一步和只读的 `rosprobe`）；`web/robot_body.js`、`web/robot_body.css`。

## 怎么用

通过 SSH 接入的真实机器人，卡片「更多功能」里多了**本体设置**（在「安装管理层」后面）：

1. 选**真实本体（这台机器人自己的 ROS 2）**。
2. 点**从机器人读取**（只读）：控制台去机器人上看 `/opt/ros` 下的环境文件、正在运行的 ROS 2 程序用的设置；机器人上已经有真实本体的管理层时，把它的设置和本体配置读回来填进表单。
3. 核对 **ROS 2 环境**：环境文件（ROS 2 Humble 的 `setup.bash`，或叠在它上面的工作区的）、`ROS_DOMAIN_ID`、只在本机通信、通信中间件（RMW）和它的配置文件。机器人自己的程序常常运行在登录 shell 里没有设置的域上，所以这些要填对，否则管理层和机器人的程序互相看不见。
4. 填**本体配置**（JSON，可以「导入文件」）：话题名、限值；机器人自带导航程序时，还有它认识的地点和去每个地点要运行的程序（格式见 [PLACE_SKILLS.md](PLACE_SKILLS.md) 和 `runtime/README.md` §3.4）。「检查并预览」用管理层自己的解析器检查它，并列出装好后机器人会认识的地点和每个地点的步骤。**地点的坐标和地图留在机器人自己的程序里**，这里只有名称和要运行的程序。
5. **保存**。保存不会动机器人，窗口会说下一步是什么：
   - 还没装过：点**安装管理层**。安装窗口里“本体”一行写明是真实本体、装好后技能会让机器人真的动起来。
   - 只改了本体配置（比如加了一个地点）：点**应用到机器人**（机器人上要有和控制台同一版本的真实本体管理层，不管是谁装的）。控制台把新配置传过去，把管理层停掉再启动，重新接入；装在里面的技能和运行记录都还在，正在运行的技能会被停掉。
   - 换了本体的种类，或改了 ROS 2 环境：只有重新安装才生效。点「安装管理层」，窗口会说机器人上那份是为另一种本体装的，只能选“删除后重新安装”（连同装在里面的技能和运行记录）。

卡片上真实本体多一行状态：还没有装到机器人上 / 机器人上用的就是这份 / 配置改过了还没有放上去 / 改动要重新安装才生效 / 机器人上已有真实本体、它用的配置不是从这里放上去的（控制台只是接入了一份别人装的；点「应用到机器人」之后就一致了）。

装好并接入后，这台机器人的「能力与技能」和任务页的「技能与配置」里就是它自己声明的能力和地点；`去指定地点`、`巡检` 这些技能的地点参数按这份清单检查。

## 在设备上做什么

和安装一样，只经这台机器人的 SSH 连接、只运行产品自带的固定脚本、不用 sudo、只动 `~/neuxmind-pkg/console/<安装包>/` 和 `~/neuxmind`。

- **多传两个文件**（和安装包走同一条上传通道，权限 600）：`body.env`（安装要用的 ROS 2 设置，一行一个 `名称=值`，以及是否带本体配置）和 `ros2-config.json`（本体配置）。
- **安装**：真实本体时，设备上的任务脚本先清掉登录环境里可能带着的 ROS 设置，只用 `body.env` 里的，再运行 `device_install.sh install`（`NX_ADAPTER=ros2`）。安装脚本自己再检查一遍：环境文件必须是 ROS 2 Humble，各项设置必须是它认识的写法，`rclpy` 必须能导入，否则什么都不留下。
- **启动 / 重新启动**：把传过去的 `ros2-config.json` 放进 `~/neuxmind/`（先写临时文件再改名），再启动。「应用到机器人」用的是新的 `restart` 一步：`device_install.sh stop` 然后 `start`，一个任务，SSH 断了也会在设备上做完。
  - **新配置起不来就退回去。** 换文件之前先留下原来那份；`restart` 里的启动失败时，放回原来的配置（原来没有就删掉新的）再启动一次，所以一份坏配置不会让机器人没有管理层。这一步仍然算失败，窗口里的设备输出会写明退回了。
  - **清空了本体配置也会生效。** 控制台放过去的配置带一个记号（`~/neuxmind/.console-body-config`）；本体设置里把配置清空后再应用，这份会被拿走。别人手工放在那里的配置（没有记号）只会被替换，不会被删除。
  - **ROS 2 环境以机器人上记录的为准。** 接入一份已有的真实本体、或应用之前，控制台读设备上 `ros2.env` 里记录的环境和设置，和这里保存的比较：不一样就不动机器人，告诉你要么「从机器人读取」沿用它的，要么重新安装。
- **从机器人读取**（`rosprobe`，只读）：列 `/opt/ros/*/setup.bash`；读本登录账号下带 `ROS_DISTRO` 的进程的环境（`/proc/<pid>/environ`）里的那几项 ROS 设置，取设置最多的一组；`~/neuxmind` 是装好的管理层时，读它记录的本体、`ros2.env` 和本体配置（24 KB 以内，十六进制传回）。别的账号运行的程序读不到，那种情况下窗口会说没有读到，要自己填。

## 定下来的规则

- **默认仍然是仿真本体。** 不设置本体的机器人，安装和以前完全一样。没设置过本体的机器人，设备上已有的安装记录的是什么本体，启动时就用什么（issue #21 的规则不变，手工装的真实本体照样能接入）；只有人在「本体设置」里选过本体，才拿它和设备上的比较。
- **换本体只能重装，而且要人确认。** 机器人上为仿真本体装的管理层不会被当成真实本体接入或启动，反过来也一样：安装检查读设备上记录的本体，不一致时只给“删除后重新安装”这一个选择。
- **保存不碰机器人**；从机器人读取只读；放到机器人上只有「安装管理层」和「应用到机器人」两条路，都是看得见步骤、可以停止的任务。
- **本体配置里不能写 `simulated: true` 或 `use_sim_time: true`**：设备上的安装脚本会拒绝启动（仿真本体绕过安全限值），所以保存时就拒绝。
- **所有填的东西先在控制台检查**：路径只能是绝对路径、只含字母数字和 `. _ / + -`；域编号 0–232；RMW 形如 `rmw_xxx`；本体配置用适配器自己的解析器和清单生成器检查（不需要 ROS 2）。从机器人读回来的值过同样的检查，不合格的不填进表单。设备上的安装脚本再各检查一遍。
- **真实本体没有内置限速**：本体配置里没写 `limits` 时，机器人不声明速度上限，管理层拒绝一切运动，直到在控制台里给这台机器人填了安全限值。这是有意的。

## 接口

- `POST /api/robots/body/save` `{project_id, robot_id, kind: 'sim'|'ros2', setup?, settings?, config_text?}` → `{robot_id, body, declares}`。`body.state` 是 `sim` / `unset` / `unknown` / `current` / `config_changed` / `reinstall`。
- `POST /api/robots/body/check` `{project_id, robot_id, config_text}` → `{empty, declares}`：只检查，不保存。
- `POST /api/robots/body/detect` `{project_id, robot_id}` → `{setups, running: {count, settings}, installed}`：只读。
- `POST /api/robots/runtime-install/apply-body` `{project_id, robot_id}`：立刻返回任务视图（`mode: 'body'`，步骤 检查设备 / 上传安装包 / 重新启动 / 接入并检查），进度和安装一样经 `runtime-install/status` 读。
- `/api/state` 里机器人多一个 `body`（设置过才有）。安装结果的 `adapter` 可以是 `ros2`；`choice.found` 多 `adapter`、`other_body`。
- 新的错误码：`body_settings_invalid`、`body_config_invalid`、`body_detect_failed`、`body_apply_not_real`、`body_apply_reinstall`、`body_apply_no_install`、`install_body_missing`。

## 还没有做的、没有验证的

- **没有在真机上用这个界面装过。** 那台四足机器狗上的真实本体是手工装的；控制台对它是“接入了一份已有的”，要点一次「应用到机器人」（会重启管理层）才算从这里放上去过。
- **没有接过真实的 ROS 2 做这条界面流程**：浏览器和 Linux 测试用的是替身 ROS 2。适配器对真实 Humble 的检查在 `runtime/tests/ros2_humble`（Fast DDS）；`rmw_zenoh_cpp` 只在那台机器狗上读过里程计和电量。
- **本体配置是 JSON 文本**，没有逐项的表单编辑器；预览只读。
- **开机自启**（issue #20）沿用原来的做法；真实本体的服务文件没有单独测过。
- **限值不在这里填**：安全限值还是在机器人的安全设置里填（issue #22）。
