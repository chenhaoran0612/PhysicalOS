# Microduck AD-P102：模型、技能模型和训练（issue #63）

小鸭的资料在训练项目 `duck-rl` 里（不在本仓库）。这一版把三样东西接进了应用：

- **外观模型**：AD-P102 第二版的仿真模型，作为「其他 → Microduck → AD-P102」的一个档案，可以在「添加仿真机器人」里添加（issue #65 起归在「其他」类型，原来在「双足机器人」下；已经添加的仿真小鸭在应用启动时自动改成「其他」）；
- **技能模型**：训练项目交付的节目模型包，随安装包带上，在仿真小鸭身上按原策略真跑并显示画面；
- **训练**：各节目历次评估的成绩，在「训练与改进」页里看，完整看板一键打开。

## 用户定的事（2026-11-27，本 issue 的会话里）

| 问题 | 决定 |
|---|---|
| 品牌和型号 | 品牌 `Microduck`，型号 `AD-P102`（训练项目的文档里没有写明品牌名） |
| 技能模型做到哪一步 | 在应用自带的仿真里真跑，不依赖 PyTorch |
| 训练做到哪一步 | 应用里看训练进展；发起和续训仍在训练项目里做 |
| 文件放哪里 | 不进公开仓库，放在 `~/code/PhysicalOS-private/duck`，由打包脚本装进安装包 |

## 规则

1. **一个模型包只在它验收时的物理引擎版本上运行。** 交付的包在 MuJoCo 3.10.0 上验收（固定十个起姿 10/10）。同一份权重放到应用里其他仿真用的 MuJoCo 4.0.1 上实测：探水 10/10，旧版醉鸭 6/10，鞠躬 6/10，点球 2/10。所以套件里自带 3.10.0，小鸭的物理在自己的子进程里只加载它；权重文件写明的版本和引擎不一致时不运行，并说明两个版本号。
2. **不用 PyTorch。** 策略是三层全连接网络。`brainos/duck_policy.py` 把 `.pt` 当成它本来的格式（一个 zip，里面一份目录和若干数据块）读出数字，只认张量和有序字典两种内容，别的一律拒绝，所以一份权重文件在这里不能执行代码。读出的参数要能复算出训练时记在文件里的指纹，否则不用。
3. **用哪一份包由仓库里的清单决定。** `brainos/duck_kit.py` 的 `SHOWS` 登记了每个节目的包名和 SHA-256。套件里的包不是登记的那一份就不用；解包时再逐个文件核对包内自带的 `SHA256SUMS`。
4. **交付和候选分开标。** 两组（固定组、预先登记的独立组）各 10/10 才标「已交付」；绕场两圈的醉鸭独立组是 8/10，标「候选」；地板舞和充电还没有模型包，标「训练中」，没有运行按钮。
5. **仿真结果不是现场证据。** 小鸭报告自己是仿真体，页面上也写明。
6. **节目是机器人的技能（issue #67 起）。** 原来节目不走运行时的技能通道，因为能力标准里没有「运行一个训练好的模型」这一项。能力标准 1.3 加了 `policy.run`，现在每个有模型包的节目都是 Microduck AD-P102 的一个技能，仿真小鸭自带，见 [TRAINED_SKILLS.md](TRAINED_SKILLS.md)。这一页上的「运行」仍然由应用直接让仿真小鸭表演（应用把命令写进这个机器人自己的状态目录 `sims/<id>/duck/command.json`，小鸭的本体把进展写回 `status.json`），两条路演的是同一个模型，舞台上看到的是同一份进展。停止走两条路都有效：页面上的「停止」，和「我的机器人」里的停止按钮（运行时的 `safety.stop`）。

## 套件

```
.build/duck-kit/                 打包后在应用里是 duck_kit/
  kit.json                       里面有什么
  shows/<节目>.zip               训练项目交付的包，原样
  engine/                        MuJoCo 3.10.0、onnxruntime 1.20.1（鞠躬和醉鸭用到两份第三方步态策略）
  training.json                  构建时的训练进展
  NOTICE.txt                     这些文件是谁的、什么许可
```

```sh
python scripts/duck_kit.py collect --from ~/code/duck-rl    # 从训练项目把登记的包复制到 ~/code/PhysicalOS-private/duck，并留一份训练进展
python scripts/duck_kit.py build                            # 做成 .build/duck-kit（约 70 MB）；build_macos.py 会自动调用
```

训练项目换了新包时：`collect` 会报出新包的 SHA-256 并拒绝复制；确认要换，就改 `SHOWS` 里的包名、SHA-256、出处和成绩，再 `collect`、`build`。没有那个资料目录时套件是空的，应用里小鸭显示为不能添加，并说明原因。

套件里有署名、非商用许可的第三方模型（Pollen Robotics 的九个占位网格，CC BY-NC-SA）和供应商的打印件网格，所以带套件的安装包只用于内部和演示，不能出售。详见套件里的 `NOTICE.txt` 和每个包里的 `vendor/SOURCES.md`。

## 运行时是什么样

```
应用（brainos.duck_kit）
  └─ 仿真机器人进程：neuxmind_runtime serve --adapter brainos.duck_body:body      在线、健康状态、safety.stop
       └─ 物理子进程：brainos.duck_engine --package <解开的包> --engine <套件>/engine
            站在 HOME；收到 show 就从 HOME 按包里的编舞、舵机模型、裁判和权重演一遍；每 0.1 秒画一帧
```

- 仿真小鸭的清单里声明 `policy.run`，`policies` 是它有的节目。经技能通道运行时，运行时调用本体的 `policy.run` 动作；本体用和页面命令同一套准备、开始、停止的步骤。

- 一个节目一个包、一个子进程。换节目时换子进程（约 1–2 秒，第一次更久）。包里是各自冻结的代码，互不影响。
- 一次运行默认用起姿编号 `1700003000`，也就是包里验收录像的那一回合，所以结果可以和录像对照（鞠躬：227 个控制步，4.54 秒）。
- 站着不动 3 秒后物理不再推进，直到下一个命令；画面只在有人看的时候画。
- 画面和 MuJoCo 仿真机器人用同一个地址（`/api/sims/frame`），所以「我的机器人 → 实时状态」里也能看到它。
- 仿真小鸭的配置（`sims/<id>/duck.json`）记的是每个节目的包内容指纹，不记安装位置；应用换了位置或升级后，旧的仿真小鸭照样能启动，它用的是添加时的那几份包。新加的节目要重新添加一个仿真小鸭才有。

## 页面

「训练与改进」页标题下面多了一块「技能模型 · Microduck · AD-P102」（`web/duck.js`）：

- 左边是舞台：实时画面、当前阶段、进度、停止；没有仿真小鸭时是「添加仿真小鸭」。
- 右边是节目：状态（已交付 / 候选 / 训练中）、两组成绩、出自哪一轮哪次更新、「运行」和「验收录像」。
- 下面是训练进展：每个节目的历史最佳、最新评估、评估次数和走势。本机的训练看板（`duck_show.evolution`，默认 `http://127.0.0.1:8767`，可用 `NEUXMIND_DUCK_DASHBOARD` 改，只接受本机地址）在运行时读它，否则用套件里的那份并写明。
- 这一块是一个保留的元素，整页重画后放回原处，所以正在播放的录像和正在进行的节目不会被重画打断。

## 代码在哪里

| 文件 | 做什么 |
|---|---|
| `brainos/duck_kit.py` | 节目清单、套件、解包与核对、添加仿真小鸭、让它表演、训练进展 |
| `brainos/duck_body.py` | 仿真小鸭的本体（运行时加载的适配器），管理物理子进程 |
| `brainos/duck_engine.py` | 物理子进程：按包运行、报告进展、画画面 |
| `brainos/duck_policy.py` | 不用 PyTorch 读权重、算动作 |
| `brainos/duck_paths.py` | 套件在这台电脑的什么位置 |
| `scripts/duck_kit.py` | 收集和构建套件 |
| `web/duck.js`、`web/duck.css` | 页面上的那一块 |
| `brainos/sim_profiles.py`、`web/robot_catalog.js`、`web/robot_images/microduck-adp102.webp` | 档案、品牌型号清单、图片 |

## 在哪里验证过，哪里没有

- 2026-11-27，这台 Mac：五个包都在子进程里演过；鞠躬、点球通过应用的服务层演过；浏览器验收在 Chromium 和 WebKit 上各跑了编造的套件和真实套件。
- 没有验证：真机（没有小鸭的真机接入）；Linux 上的套件（引擎的安装文件按构建电脑的系统下载，Linux 没有试）；应用内发起训练（没有做）。
- 已知的限制：解开的模型包留在工作区的 `duck-kit/<指纹>/` 里，删除仿真小鸭或升级后不会自动清理（每个包几 MB 到十几 MB）；训练进展在没有看板时是构建那一刻的记录；绕场两圈的醉鸭一次约 28 秒，独立组 8/10，演出可能失败，页面会如实显示原因。
