# NeuxMind Robot OS 目标架构

> 版本：2026-11-05（第 1 轮进化）。取代 `ARCHITECTURE.md` 中"以桌面端为中心"的定位；原文件保留作历史。

## 产品定义

一个**跨本体的机器人操作系统与开发平台**：开发者把运行时装到任意机器人上，按标准能力接口编写或直接选用技能与模型，几分钟内让机器人开始工作；平台通过模型市场、token 计费、算力与设备群服务盈利。

## 三层 + 一个契约

```
                 ┌──────────────────────── spec/ 能力接口标准（唯一共同语言）────────────────────────┐
                 │  能力 ID · 字段/单位/坐标系 · manifest v2 · 技能包 v1 · 兼容性判定              │
                 └───────────────▲───────────────────────▲───────────────────────▲──────────────────┘
                                 │                       │                       │
 ┌─────────────── 开发工具层 ─────┴──────┐   ┌──── 云平台层 cloud/ ──┴────┐   ┌──── 端侧运行时 runtime/ ──┴─────┐
 │ sdk/  Python SDK + nx 命令行            │   │ 账户 · 组织 · API Key       │   │ HAL：标准能力 → 厂商适配器         │
 │ brainos/ + desktop/ 桌面控制台（Mac）   │◀─▶│ token 钱包 · 账本 · 支付     │◀─▶│ 技能运行时（可移植技能包）         │
 │ AI 本体适配助手（SSH 调查 → 生成适配器）│   │ 模型市场 · 推理网关 · 计量   │   │ 安全监督：限速/限位/看门狗/急停     │
 │ 仿真（Continuum 接入点）                 │   │ 训练/仿真算力调度 · 设备群   │   │ 模型运行时 · 遥测 · v1/v2 网关      │
 └─────────────────────────────────────────┘   └──────────────────────────────┘   │ 适配器：仿真参考本体 / ROS2 / 厂商   │
                                                                                     └──────────────────────────────────────┘
```

### 为什么这样拆

| 问题（第 0 轮评估） | 解决层 |
|---|---|
| 能力是自由字符串，技能无法跨本体复用 | `spec/` 标准能力 + 兼容性判定 |
| 机器人端只有转发网关 | `runtime/` 真正的端侧 OS |
| 注册与计费在本机 SQLite，商业化不成立 | `cloud/` 多租户云平台 |
| 开发者没有 SDK | `sdk/` + `nx` 命令行 |
| 桌面端承担一切 | 桌面端降为控制台之一，经 v1 兼容层不受影响 |

## 跨本体的工作方式

1. 本体厂商或开发者写一个**适配器**，把本体映射到标准能力（四足：`base.velocity`、`legged.posture`、`sensor.imu`…；机械臂：`arm.joint_position`、`gripper.position`…）。AI 本体适配助手可自动生成初稿。
2. 运行时启动后用 manifest v2 声明能力与参数（最大速度、自由度、关节限位）。
3. 技能包声明 `requires` 与 `constraints`。安装前用 `check_compatibility` 判定；同一个"巡逻"技能可以跑在任何提供 `base.navigate_to` 或 `base.velocity` 的本体上。
4. 模型同理：模型卡声明需要的能力和动作空间（如 VLA 需要 `policy.action_chunk` + `sensor.camera.rgb`），市场据此只给用户展示能用的模型。

## 安全原则（继承第 0 轮的优秀设计）

- 停止路径独立、永不阻塞；硬件急停优先于一切软件。
- 动作类调用必须带现场授权；幂等 `request_id`，结果不明不重放。
- 仿真本体在 manifest 标注 `simulated`，仿真结果永不当作现场证据。
- 余额只来自账本，预留先于调用，结算基于服务端计量证据。
