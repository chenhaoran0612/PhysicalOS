# 暂时隐藏的页面（issue #49 功能简化）

更新：2026-11-26。对应 GitHub issue #49「功能简化」。

## 结论

issue 要求删除「工程助手」「助手工具」「自有服务」。用户在会话里定的做法是：**暂时先只隐藏这些页面，需求文档标注为暂时不做**。所以这一版只是隐藏，没有删除任何功能代码、后端接口或已保存的数据。

关于「自有服务」以及依赖它的两处（模型库的「接入自己的模型」、新建仿真 / 训练 / 测试任务时选自有服务执行），用户的方向是：**这些应该是技能，自有服务也应该是技能**。这一版没有按这个方向改，留给以后的需求。

## 隐藏了什么

| 页面 | 地址 | 说明 |
| --- | --- | --- |
| 工程助手 | `#agents` | 侧栏第三项 |
| 协作流程 | `#workflows` | 工程助手里面的页面，随它一起隐藏 |
| 助手工具 | `#extensions` | 侧栏项，以及账户菜单里的「助手工具设置」 |
| 自有服务 | `#services` | 侧栏项，以及账户菜单里的「服务连接」 |

隐藏之后：

- 侧栏和账户菜单里没有这些项；侧栏从 18 项变成 15 项，分组不变。
- 直接打开这些地址（手输、旧书签、刷新）会回到「任务工作台」，地址栏也改成 `#overview`。
- 其他页面和对话框里只通向这些页面的链接被拿掉：任务页「需要时，再使用这些能力」里的「让助手帮忙开发」卡片、新建任务对话框里的「前往检查连接」、模型配置对话框里的「查看已有服务」、工程任务表单里的「管理扩展」。
- 任务页五个步骤里的「准备能力」原来打开工程助手，现在打开「机器人应用」（这一步是否完成，本来就是看有没有应用）。
- 设备档案里的「交给工程助手开发」被拿掉：它发起的工程任务只在工程助手页面里列出，页面隐藏后就找不回来了。

## 没有动的

- 机器人调研、硬件修复、本体适配、任务页的「让助手准备」：它们和工程助手用同一个引擎，但各有自己的入口和进度界面，照常使用。界面上「工程助手」这个称呼（例如「工程助手调研」）指的是助手本身，没有改。
- 「接入自有服务」「接入自己的模型」这些对话框还在（仿真试运行、模型库、新建任务对话框里的按钮）。登记之后的服务仍可在新建任务时选用，只是没有页面可以再查看或修改它的配置。这是「只隐藏页面」留下的缺口，等「自有服务改成技能」时一并处理。
- 后端接口（`engineering/work`、`engineering/workflows`、`engineering/extensions/*`、`services` 等）和已保存的记录都没有变化。
- 其他页面上提到这些页面的说明文字（例如机器人应用页的「缺少能力时可先交给工程助手开发」）没有改。

## 做法

新增 `web/hidden_pages.js`，`web/index.html` 里加一行（放在哪里都可以，它等所有脚本加载完才动手）；其他脚本没有改。

- `HIDDEN_PAGES` 是隐藏页面的清单。脚本在所有脚本加载完之后（`DOMContentLoaded`）把这些页面从 `views` 里拿掉，`web/app.js` 的 `route()` 找不到页面时本来就回到任务工作台。
- 链接的处理是一个纯函数 `hpDecide()`：保留、拿掉、连同所在卡片一起拿掉、或改指到别的页面（`HIDDEN_STEP_TARGETS`）。侧栏、页面、对话框、账户菜单每次重画后都按它过一遍，所以以后别的功能新加的 `go-agents` 之类的链接也会被拿掉，不用改这里。
- `HIDDEN_ACTIONS` 是页面之外要一起拿掉的按钮（现在只有 `engine-work`）。

**恢复**：把 `web/index.html` 里 `<script src="/hidden_pages.js" defer></script>` 这一行去掉，三个页面和所有入口原样回来。只恢复其中一个页面：从 `HIDDEN_PAGES` 里去掉它。

## 测试

- `tests/hidden_pages_logic.cjs`：清单和 `hpDecide()` 的规则。
- `tests/test_hidden_pages.py`：脚本能取到、在页面里只加载一次、被隐藏页面的脚本仍然在；并运行上面的逻辑检查。
- `tests/hidden_pages_browser.cjs`（夹具 `tests/ux01_browser_fixture.py`）：侧栏和账户菜单、四个地址、任务页的步骤和卡片、其余 11 个页面上没有通向隐藏页面的链接、两个对话框，以及打开测试开关后页面原样回来。

## 对浏览器验收脚本的影响

被隐藏的页面仍然是产品的一部分，检查它们的脚本继续运行。`tests/hidden_pages_helper.cjs` 提供测试开关：创建页面之后加一行

```js
await require('./hidden_pages_helper.cjs').showHiddenPages(page);
```

之后这个页面加载的控制台就带着隐藏的页面（脚本在加载时检查 `window.__showHiddenPages`；这个开关只能由测试在页面加载前设置，界面上没有入口）。已经打开的页面要再 `page.reload()` 一次。

| 脚本 | 改动 |
| --- | --- |
| `engineering_browser` `extensions_browser` `workflows_browser` `cloud03_browser` `ux02_browser` | 加上面这一行（它们检查的就是隐藏的页面） |
| `ux03_browser` | 侧栏项数 18 → 15，并确认没有三个隐藏项；检查自有服务和助手工具表单之前打开开关并刷新 |
| `ssh_edit_browser` | 检查服务的「配置连接」表单之前打开开关并刷新 |
| `journey_browser` | 走到工程助手页面之前打开开关并刷新（之后它逐页检查「这个页面怎么用」，包括四个隐藏的页面） |
| `investigation_browser` | 「从另一个入口发起调研只看到进展」原来经工程助手页面点击，改为直接发起同一个请求 |

以后的脚本如果要打开这四个地址，或点 `go-agents`、`go-workflows`、`go-extensions`、`go-services`、页面之外的 `engine-work`，同样需要这一行。

合并会话的运行器需要加一行映射：`hidden_pages) FIXTURE=ux01_browser_fixture.py; SHOTS=1 ;;`。
