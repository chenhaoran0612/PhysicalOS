NeuxMind Physical OS 0.21.16 — macOS Apple Silicon 开发预览

要求：Apple Silicon（M1 或更新），macOS 13 或更新。
安装：将 NeuxMind Physical OS.app 拖入 Applications，然后打开。
从旧版升级：应用改名了，「应用程序」里原来的 NeuxMind Robot OS.app 不会被覆盖，请先退出并手动删除它。第一次打开新版时，数据文件夹会自动改名为 NeuxMind Physical OS，内容不变；原位置留一个指向新文件夹的链接。
也可以使用同版本 .pkg 安装包。
不需要安装 Python、Node 或其他开发工具。

当前为本地签名的开发预览包，未完成 Apple Developer ID 签名及公证。
若 macOS 阻止首次启动，可在确认来源后通过“系统设置 → 隐私与安全性”允许打开。
此版本尚未验证 Intel Mac；Windows 版后续处理。

首次打开先显示登录 / 注册页：注册要填邮件里的 6 位验证码，登录后可创建项目；以前注册的账号直接登录。
“工作台”（原来叫“任务工作台”）是全部任务的概览：显示任务数量和名称，任务以卡片列出，可以新建和删除；点“进入任务”看这个任务绑定的机器人应用：任务不在任务页里开发应用，而是绑定“机器人应用”里已有的应用（没有合适的就点“去创建应用”），一个任务可以绑定多个应用，一个应用也可以绑定到多个任务，删除任务只解除绑定、不删应用。任务页上的“技能与配置”（绑定了应用后才有）列出每台机器人认识的地点、装了哪些技能、每个技能用的参数，以及直接运行过几次、最近一次的结果。机器人属于账号，不属于某个任务：所有任务都能用同一批机器人，删除任务不会删机器人。新建任务时可以选“用哪台机器人来做”，之后在任务页上可以更换；一个任务只绑定同一品牌型号的应用：选了机器人就是这台机器人的品牌型号，不选时由第一个绑定的应用决定。从旧版本升级后第一次打开时，原来记在各个任务下的机器人和它们的记录会移过来，原来在任务里的应用移到账号里、绑定回原来的任务，只做一次。
登录应用时会同时登录云平台（资料库要用），云平台上没有这个账户时会自动注册；从旧版本升级后第一次打开会退出一次登录，重新登录即可。应用里改密码不会改云平台的密码。
没有配置邮件服务时验证码不会发出，而是写在本机的 mail-outbox.txt 里，注册页会显示它的位置。
要让验证码真的发到邮箱，在 ~/Library/Application Support/NeuxMind Physical OS/state/mail.json 里填发信账号（host、port、user、password、from，说明见代码仓库的 docs/MAIL_SERVICE.md），下一封验证码就按它发出。
没有真机也能马上试用：在“我的机器人”点“添加仿真机器人”，先选类型（机械臂、轮足机器狗、四足机械狗、双足机器人、其他），再选品牌和型号（内置八个型号的模型，在 MuJoCo 里仿真；星玑 CS1 的外形是示意的，厂家没有提供网格文件）；升级后原来的仿真机器人会被删除一次，需要的话重新添加，真机不受影响；
仿真机器人的“其他”类型里有 Microduck AD-P102（小鸭）：它训练出来的技能模型（节目）在应用里按原策略真跑，用安装包自带的 MuJoCo 3.10.0；“训练与改进”页标题下有它的实时画面、技能模型和训练进展（只看，不能在应用里发起训练）。小鸭的套件里有署名、非商用的第三方模型（CC BY-NC-SA）和供应商的打印件网格：这个安装包只用于内部和演示，不能出售，说明见应用包里的 duck_kit/NOTICE.txt。安装包因此大了约 70 MB。
仿真小鸭现在自带技能：在“我的机器人”里打开它的“能力与技能”，每个训练出的动作旁边有“运行”；创建机器人应用时也能选它们。以前添加的仿真小鸭在下次启动时自动装上。
“模型库”“训练与改进”“训练与测试数据”三页改为看板加卡片墙：模型按九个分类管理，每类有自己的指标；训练好的模型文件传到模型库成为版本；有评测库和训练库；小黄鸭的技能模型可以在仿真里按起姿逐个评测；一个模型可以一轮一轮地改进（基线评测、找短板、应用外训练、评测候选、决定是否采纳）。
“仿真试运行”页面按任务来做：页面上只有任务，任务的品牌型号决定仿真哪一种机器人；仿真环境按任务构建一次、保存在任务上，以后直接“进入仿真”；任务的仿真机器人进入时自动装上任务用到的技能，每个技能可以直接运行。仿真里的行走不是物理的。
“验证与测试”“部署与运行”改成数字板加记录列表；点一条记录可以看这次运行的结果、用时、路线和速度、电量曲线；“仿真试运行”页面上多了仿真运行记录。从这个版本起才开始收集运行过程的数据，之前的运行只有结果。
“机器人应用”页面只展示已创建的应用；创建应用时选任务（必选）和品牌型号，这个品牌型号的技能直接可以编排，不用先安装；机器人上还没有的技能，在现场测试时自动装上。从任务点“去创建应用”会直接打开创建表单。
从“安装技能包”里的示例技能安装巡逻或挥手，授权后运行并在“实时状态”里观察；不需要终端。
“安装技能包”只列出这台机器人品牌型号的技能包和通用技能包（比如状态报告）；别的品牌型号的包不显示，也装不上；仿真和真机一样。
装好技能包后直接进入运行表单，按技能的参数填写后就能运行，真机也可以：真机运行前要两项确认（现场有人看着、急停够得着；授权执行），没填安全限值时表单里会先提示。
给没连上的机器人安装技能包时，对话框会写明原因，并带“安装管理层”“接入已有的管理层”“重新连接”。
示例技能里还有去指定地点、巡检和无图自由走，可以在仿真四足上运行（它有三个虚构的地点）。
仿真机器人随应用启动和退出，结果都标注为仿真，不能作为现场证据。添加机器人（真机或仿真）不需要先有任务，也不会顺带建任务；要用它做事时新建任务并选这台机器人。
机器人应用的交付清单里有“仿真环境”：用空场地，或让工程助手按应用的步骤、任务说明和资料写出环境、你确认后，启动一台 MuJoCo 仿真机器人，应用和技能在里面运行，“实时状态”里能看到画面。要先在资料库里为这个品牌型号上传并确认机器人模型（URDF）。底盘和四足直接移动机身，不模拟腿的步态；结果同样不能作为现场证据。应用内置 MuJoCo 引擎，安装包因此大了约 22 MB。
菜单“连接平台服务…”可配置运营方提供的 HTTPS 工作台地址。
平台模型、算力、仿真和计费目录需要配置真实服务；不随安装包虚构资源或模型权重。
本机数据保存于 ~/Library/Application Support/NeuxMind Physical OS/，更新应用不会删除数据。
可先输入 SSH 信息（直连或经跳板机，跳板机可以有多级，最多 5 级，每一级的主机指纹逐个确认；也可以直接粘贴一条 ssh 命令，如 ssh -J a,b,c 用户@机器人），再选本体类型，由工程助手调查本体并保存档案。
粘贴 ssh 命令后认证方式是“本机 SSH Agent”，不会发送密码；平时在终端里输密码登录的设备，请改为“密码”并填写密码。登录被拒时，提示会写明这次用的是哪种认证方式。
“我的机器人”页面：还没有机器人时列出三种添加方式；有机器人后从页头的“添加机器人”添加。卡片上只有机器人的图片、名称、是否在线、品牌和型号，以及下一步、“实时状态”和“更多功能”；地址、本体类型、状态标签、开机自启、管理层安装进度等都在“实时状态”里，有已证实的问题时“实时状态”按钮上有一个红点；验证 SSH 连接、安装管理层、本体设置、配置连接、删除等都在卡片的“更多功能”里；“解除急停”一直在卡片上。这些按钮打开的对话框，标题是功能，机器人名在下面；从卡片打开实时状态、设备档案、硬件初始化、配置连接、管理层时，标题下有一行可以直接切到同一台机器人的其他几个；标题和底部的按钮一直看得见，内容在中间滚动。
本体类型来自本体类型清单（在“我的机器人”页头的“设置”里）：内置五类，和仿真档案一致（机械臂、轮足机器狗、四足机械狗、双足机器人、其他，issue #58），在品牌型号清单里选了型号，类型自动带出；可以添加和删除；还有设备在用的类型不能删除。以前登记的设备保留原来的类型，不在清单里的标为“旧类型”，可以在卡片上改。
添加机器人时要有品牌和型号：设备上报了就用上报的，否则在品牌、型号两个框里选或直接输入（每个框都可以下拉选、也可以打字，issue #61）；经 SSH 添加时必须填。机器人应用和技能属于一个品牌型号：同品牌同型号的机器人都能用，别的品牌型号不能用。从旧版本升级后，没有上报品牌型号的旧真机卡片上写着“未填写品牌型号”，在“更多功能”里填一次即可；不填也能照旧使用，只是为它建的应用不能给别的机器人用。
通过 SSH 接入的机器人，卡片上直接显示在线或离线（后台每分钟检查一次，连续 3 分钟没有应答才算离线，恢复后自动回到在线）；最近一次心跳的时间和离线原因在“实时状态”里。
想确认保存的 SSH 连接现在还通不通，点卡片上的“验证 SSH 连接”：逐级登录一次，显示系统、架构和耗时；登录不上时写明卡在哪一跳。它和“连接检查”不同：“连接检查”检查的是机器人上接入服务的地址和令牌。
通过 SSH 接入的机器人还没有管理层时，点卡片上的“安装管理层”：控制台会自己检查设备、传安装包、安装、启动并接入，不需要登录到机器人上，也不用 sudo；机器人上已经有管理层时会先问你怎么处理。
想让机器人断电重启后管理层自己起来：安装时勾选“装好后设置开机自启”，或之后在“实时状态”里“开机自启”一行点“设置”。控制台会先列出要以管理员身份执行的内容，你确认（需要时输入 sudo 密码，只用这一次）后才会执行。
机器人自己有 ROS 2 时，可以在“更多功能”的“本体设置”里选真实本体：点“从机器人读取”（只读）填好 ROS 2 环境，再填本体配置（话题名、限值、机器人认识的地点和去每个地点要运行的程序），保存后点“安装管理层”；以后只改了本体配置时点“应用到机器人”。装了真实本体后，技能会让机器人真的动起来。这个功能还没有在真机上走过。
真机卡片上的“设备档案”把系统、硬件、ROS 2（发行版、节点、话题、动作、服务）和资源占用合成一份，只读，第一次打开时读取，之后点“重新读取”才会再登录设备。
接入后的“实时状态”每分钟只读读取一次：系统数字之外，“硬件”页签列出全部设备及其驱动和工作状态，“软件”页签列出正在运行的系统服务、ROS 等机器人中间件进程、Docker 容器和占用资源最高的进程。
已接入的 SSH 机器人可在卡片的“配置连接”里直接改连接（地址、登录方式、跳板机）：密码和私钥不回显，留空沿用已保存的；地址变了要重新确认主机指纹；调研、修复或硬件扫描进行中也能改，不会打断正在运行的会话；把机器人改指向另一台机器时，正在运行的会话不会跟过去，要停止后重新开始。
接入了设备端运行时的真机，要先在卡片或详情的“安全限值”里填写最大线速度、最大角速度和运动指令超时；没填之前任何能力都不能让它运动，停止和读取状态不受影响。
“我的机器人”里真机的卡片可以“删除”：连同它的 SSH 连接、保存的登录信息、调研和修复记录、读取到的设备档案一起从这台电脑上删掉（删除前的确认框会逐项列出），不会登录或改动机器人；正在调研、修复、扫描硬件或本体适配流程运行中时不能删。以它为目标的应用和流程记录保留。
调研入口按状态打开：没调研过是开始表单，调研中是进展，调研完是报告。调研不限 Token 和时间，由你决定何时停止。
报告上可以重新调研（先扫描硬件，再完整调研一遍，生成新的档案版本），也可以用对话的方式让助手修复问题。
连接成功后会先做一次只读的硬件扫描，列出硬件清单，并把读到的情况分成故障、待确认和提示：只有直接读到不能用、并且说得出阻塞了什么的才算故障，卡片上只有故障是红色；可以让助手修复：默认勾选“默认允许执行”，命令通过产品检查后直接执行并留下记录，少数看不清的命令仍会先问你，也可以改为逐条批准；助手只做软件层面的修复，软件修不了的问题会标注为“等待现场处理”，现场处理并标注后才能再交给助手；修复同样不限 Token 和时间，由你决定何时停止。
登录云平台账户后，“资料库”页可以把手册、参数表、网页（.html、.htm）、URDF 和驱动安装包上传到云平台（分片上传，中断后可以继续），并标明本体类型、品牌型号和版本。资料按品牌型号归属，同品牌同型号的机器人共用；机器人模型（单个 URDF，或带网格文件的压缩包）单独一栏，每个品牌型号用确认过的最新一份。以前按设备上传的资料，在第一次打开“资料库”或设备的“资料”时归到设备的品牌型号（云平台也要更新到这一版）。没有品牌型号的机器人不能上传资料，也收不到资料库里的驱动安装包。
设备资料、资料库和 Skill 导入的上传按钮会弹出文件选择面板，可以多选。
侧栏的“技能发布”：把技能包发布到云平台（只在自己的组织内可见），看版本、删除版本；“技能加载”：把云端的一个版本装到机器人。机器人页面的“程序和场景数据”可以把机器人上的程序和数据收进云端、再装回去。
机器人页面的“远程调用”：按技能打开“允许远程调用”后，第三方可以经云平台的开放接口调用这个技能，随时可以关闭；要用它，机器人上的管理层要是这一版并连上云平台（只走 HTTPS）。
工程助手的大模型只对接 TokenFans：调用前请在“云平台账户”页连接 TokenFans 并选择默认模型（费用从 TokenFans 账户余额扣除）。真正执行机器人任务仍需对应驱动与实机验收。
界面默认不显示代码和原始数据：数据显示成“名称—值”，命令和原始输出折叠在“展开查看…”里；要你批准的命令会直接显示。
开源工程运行时随包提供，许可证可在菜单“开源许可…”中查看。

“工程助手”（含工程任务和协作流程）、“助手工具”（原来的“工程扩展”：Skills、HTTP MCP）和“自有服务”三个页面暂时隐藏：侧栏和账户菜单里没有它们，直接打开这些地址会回到工作台；以前保存的内容都还在，没有删除。机器人调研、硬件修复和本体适配照常可用。
